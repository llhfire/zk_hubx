# 报价流程双轨分离 PLAN

> 状态：已 grill 并锁定，2026-09-01；本计划只锁定领域边界与实现顺序，未授权立即改代码。
> 事实源：`HubX/CONTEXT.md` 报价单术语、`文档/PRD/PRD-报价流程管理.md`、ADR-0001–0103。

## 一、目标

把报价审批前的两种作业路径彻底分开，同时保留审批、盖章、发送、确认和合同向导的公共后半程：

- **数据流转**：结构化数据是唯一事实源，在线维护功能清单、逐项人天评估和报价配置。
- **文件流转**：业务文件和文件级摘要是事实源；清单解析结果只读，技术评估文件不转换为在线岗位明细，客户正文独立查看/编辑。
- **公共后半程**：两种模式共用阶段键、状态机、审批快照、盖章、发送、确认和合同向导。

## 二、已锁定的领域决策

### 1. 创建与来源

1. 新建主报价必须明确选择“数据流转”或“文件流转”，不设置默认方式；创建后不可切换。
2. 重新报价只用于签约前主报价重开。旧主报价必须先进入“已废止”，才允许从“报价”入口创建新报价单；新单从草稿开始并建立 `previousQuoteId`。
3. 主报价入口统一命名为“报价”，不区分首次/重新；当前线索下已废止主报价数量显示在分隔线右侧，补充报价不计入该数量。
4. 补充报价只用于主合同已签订且仍有效后的新增需求；系统口径为主合同“已归档且未作废”。入口仍在当前线索详情的“报价”页签，主合同归档后激活“补充报价”动作。
5. 补充报价创建时也必须明确选择流转方式，可把主报价方式作为推荐选项但不能静默继承；创建后不可切换。
6. 同一主合同允许多份补充报价并行存在，每份独立审批、盖章并一对一生成补充合同；补充报价使用 `parentQuoteId`，不加入重新报价版本链。

### 2. 数据源边界

| 领域 | 数据流转 | 文件流转 |
|---|---|---|
| 功能清单 | 在线结构化清单，可编辑模块/子功能/端/备注 | 原始清单文件 + 只读解析索引；修正只能重传原文件 |
| 技术评估 | 在线逐项岗位人天与技术备注 | 评估文件 + 评估工期/总人天/备注；不生成在线岗位明细 |
| 报价摘要 | 由清单与逐项评估汇总 | 由文件级评估和销售填写摘要 |
| 客户正文 | 由结构化摘要生成客户件 | 独立编辑上下文中的客户正文；只读查看与编辑分离 |
| 审批/合同数字 | 读取结构化报价摘要 | 读取结构化报价摘要，不读取正文数字 |

7. 文件流转解析索引只读；需要纠错必须重传原始文件并形成新快照。
8. 文件流转正文可编辑客户措辞、说明、自费项目说明和排版；业务数字必须回到报价摘要修改，再重新生成并保存正文。
9. 文件流转工作台默认不展开正文；“在线查看”打开独立只读查看上下文，编辑为独立动作。
10. 新建报价的所有来源都必须保留清单、评估、摘要和正文（如适用）的资料版本。

### 3. 阶段、权限与回退

11. 阶段键共用 1–4，阶段语义、名称、待办标题、按钮和内容按模式独立：
    - 数据流转：在线功能清单 → 在线人天评估 → 在线报价配置 → 系统审批盖章。
    - 文件流转：上传功能清单 → 技术评估文件 → 报价摘要与客户正文 → 系统审批盖章。
12. 新建选择方式后，阶段 1–3 不再显示另一模式的编辑器；审批后统一进入公共审批节点。
13. 文件流转送审前的硬门槛：有效清单文件、评估文件及工期/总人天、报价摘要、已保存且与摘要一致的客户正文；主报价总金额必须大于 0。
14. 付款比例、利润率、工期差异和可选字段继续只提醒、不拦截。
15. 文件流转首次进入审批后，功能清单文件和技术评估文件锁定；驳回只能修改报价摘要或客户正文。
16. 文件流转在首次送审后隐藏/禁用“退回改清单”和“退回技术重评”；必须更换上游资料时先废止旧报价并新建。
17. 数据流转仍可按既有规则在线退回：退回改清单可编辑清单并作废评估，退回技术重评可重做逐项评估。
18. 审批后公共状态为：待盖章 → 已盖章 → 已发出 → 已确认；数据流转生成正式客户件，文件流转使用已保存正文和盖章扫描件（如有）。

### 4. 审批与留痕

19. 审批快照记录：流转方式、功能清单版本、技术评估版本、报价摘要版本、文件流转客户正文版本，以及当时的审批/盖章节点和人员。
20. 快照创建后不随配置或资料变化；驳回后重新提交才创建新快照。
21. 右侧栏两种模式完全共用，只展示当前状态、会签节点、审批意见和盖章节点；文件上传、解析、评估和正文状态留在左侧阶段。
22. 主报价使用“报价审批”，补充报价使用“补充报价审批”；两者都采用当次提交的配置快照。

## 三、实现阶段

### 阶段 A：领域模型与纯函数

- 将 `flowMode` 改为创建时必填，移除“默认在线”的隐式行为。
- 为文件流转建立独立资料集合：清单文件/解析索引、评估文件/摘要、报价摘要、正文版本；文件报价不创建或读取在线 `evalSheet` 作为事实源。
- 收敛 `computeAmountBreakdown`、报价模板行和合同预填，只从当前模式的事实源读取。
- 增加资料版本、送审锁定和“文件已进入审批不可替换”的纯函数规则。
- 保留 `previousQuoteId` 与 `parentQuoteId` 两条独立关系；补充报价不得进入重新报价 Diff。

### 阶段 B：创建入口、列表与主报价页签

- 创建主报价/补充报价均要求显式选择方式；补充报价以主报价方式作为推荐选项。
- 线索详情“报价”页签统一显示“报价”入口；在主合同归档且未作废时激活“补充报价”。
- 将“新建补充报价”从合同详情侧入口收敛到报价页签，保留合同详情只读关联。
- 主报价分隔线右侧统计当前线索的已废止主报价数量；补充报价单独分组和计数。
- 报价中心增加“全部 / 数据流转 / 文件流转”顶层筛选，模式内使用专属阶段名称；状态仍共用。

### 阶段 C：双轨工作台

- 数据流转保留在线清单、在线逐项评估、在线报价配置。
- 文件流转拆成上传清单、技术评估文件、报价摘要与客户正文；不渲染在线清单编辑器和在线人天表。
- 文件清单提供原文件信息、下载/重新上传、解析索引只读预览和错误信息。
- 客户正文默认隐藏；“在线查看”打开只读模态框；“编辑正文”进入独立编辑上下文。
- 正文编辑仅允许文案、说明、自费项目说明和排版；业务数字由摘要注入且只读。
- 送审按钮按硬门槛启用；文件模式首次送审后锁定上游文件，驳回只开放摘要/正文。

### 阶段 D：审批、合同与证据

- 审批快照补齐模式和资料版本；右侧审批栏只保留公共审批状态。
- 两种模式共用盖章、发送、确认和合同向导；合同向导读取报价摘要与客户快照。
- 合同向导改为先选已确认报价，再自动锁定主合同/补充合同类型；主合同写入 `quoteId`，补充合同写入 `parentContractId`、`quoteId` 和 `sourceQuoteId`。
- 线索详情主合同已归档且未作废时，将合同入口切换为「生成补充合同」，只列当前主合同下可用的已确认补充报价；无可用补充报价时置灰并引导先到报价页签处理。
- 全局合同列表、项目详情保留「新建合同」入口，但只能选择已确认主报价；所有入口禁止创建无报价合同。
- 合同类型、报价关联和补充合同父合同创建后不可修改；错误关联只能作废并从正确报价重新生成。
- 同一补充报价同时最多一份未作废补充合同；作废后可再次生成，旧合同历史保留。
- 文件模式盖章时使用已保存正文，支持线下盖章扫描件；不得回到在线报价配置。
- 销售合规档案展示资料版本关系，不复制一套平行手工台账。

### 阶段 E：文档、迁移与回归

- 对齐 `文档/PRD/PRD-报价流程管理.md`、报价流程图、功能看板和技术架构文档。
- 迁移旧 localStorage：缺失审批绑定时补回默认模板，但不覆盖管理员自定义或禁用配置。
- 增加纯函数与组件测试，覆盖两种模式、重传锁定、正文查看/编辑分离、重报价与补充报价分流。
- 增加合同创建测试：主/补充报价强制关联、向导类型锁定、主合同归档后的入口切换、补充报价选择和补充合同作废重生。
- 完成 α 浏览器手走和构建；β 接线保持后置，不改变 `productionOn`。

## 四、验收用例

1. 新建主报价未选择方式时不能进入工作台；选择后标签、阶段和待办始终固定。
2. 数据流转可编辑清单和逐项人天；文件流转看不到在线人天编辑器。
3. 文件清单解析索引只读；重传后形成新快照，未进入审批时可继续评估。
4. 文件评估只显示文件和总人天/工期摘要，不生成逐项岗位明细。
5. 文件正文默认不展开；“在线查看”只读模态框与“编辑正文”入口分离。
6. 正文业务数字不可直接改；摘要变化后正文必须重新保存才能送审。
7. 首次进入审批后，文件清单和评估文件上传控件禁用；驳回后仍禁用。
8. 文件模式缺清单、评估文件、摘要、正文或主报价金额时不能送审；付款比例/利润率等只提醒。
9. 审批快照能还原模式、资料版本、审批人与盖章人；配置变化不影响进行中审批。
10. 报价中心的模式筛选和专属阶段名称不混用；全部列表显示模式标签。
11. 旧主报价未废止时不允许创建重新报价；废止后“报价”入口创建新主报价，旧单只读并计数。
12. 主合同已归档且未作废时，报价页签激活“补充报价”；草稿/审批中/待寄出/待回寄/已作废不激活。
13. 补充报价必须再次明确选择方式，可与主报价不同；同一主合同可并行多份补充报价。
14. 补充报价使用独立审批绑定、`parentQuoteId` 和补充合同向导，不进入主报价重开统计。
15. 两种模式均能从已确认进入盖章、发送、确认和合同向导，且合同数字来自报价摘要。
16. 合同向导没有报价时不能创建；选主报价自动锁定主合同，选补充报价自动锁定补充合同及其当前父主合同。
17. 线索详情存在已归档且未作废主合同时，合同入口显示「生成补充合同」；无可用已确认补充报价时置灰并给出明确引导。
18. 全局合同列表和项目详情仍可新建合同，但必须选择已确认主报价；不能绕过报价直接保存合同。
19. 合同创建后不能改类型、报价或父主合同；错误关联只能作废并用新编号重建。
20. 补充合同作废后，原已确认补充报价可再次生成；同一时间最多一份未作废补充合同，旧记录可追溯。

## 五、明确不做

- 不在同一报价单内切换流转方式。
- 不把文件评估解析成在线逐项岗位人天。
- 不允许审批后替换文件并沿用原审批快照。
- 不把客户正文数字反向写入报价摘要。
- 不把补充报价当重新报价，不复活已废止主报价。
- 不新增独立的审批动态或合规台账。
- 不在本计划内开启 β 报价真实服务端接缝。

## 六、合同创建分叉（本轮新增）

### 已锁定决策

1. 合同域正式实体统一称「补充合同」，内部类型为 `kind: supplement`；不使用「补充协议」作为合同实体名。
2. 主合同、补充合同均必须关联已确认报价；主合同通过 `quoteId` 关联主报价，补充合同通过 `quoteId` + `sourceQuoteId` 关联补充报价，并通过 `parentContractId` 关联当前有效主合同。
3. 合同向导先选报价，自动锁定合同类型和父合同；不能清空、改绑或手动切换类型。合同创建后这些关系不可修改，错误时作废重建。
4. 线索详情入口在当前主合同已归档且未作废时切换为「生成补充合同」；报价详情按报价类型显示生成主/补充合同；全局/项目入口保留「新建合同」但也必须选择已确认主报价。
5. 补充合同入口只展示当前主合同下已确认且没有未作废对应合同的补充报价；无候选时置灰并引导先完成补充报价。补充合同作废后原报价恢复可选并可重生，旧合同保留。

### 实现顺序

- 先补齐 `Contract`/`WizardInput` 的必填约束和 `applyCreateFromWizard` 校验，再改各入口的候选报价读取与按钮文案。
- 统一 LeadDetail、LeadDetail360、报价详情、全局合同列表和项目详情的入口规则，避免各页面自行推断主/补充关系。
- 最后补测试、迁移旧 mock 数据，并在 α 中手走“主报价 → 主合同归档 → 补充报价 → 补充合同 → 作废重生”全链路。
