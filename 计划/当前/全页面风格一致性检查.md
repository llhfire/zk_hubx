# ZK HubX 全页面风格与一致性检查

> 检查日期：2026-08-26  
> 风格基准：`/leads/my`（我的线索）与 `/leads/:id`（线索详情）  
> 覆盖：静态扫描 88 个已注册页面组件；浏览器检查 25 个不同路由，覆盖列表、详情、工作台、看板和系统配置页。

## 总体结论

当前界面已有统一侧栏、顶栏、24px 内容边距和 Arco 组件底座，但页面级规范未形成。各模块更像在同一外壳中独立演进：标题使用 18/20/24/28px 四套尺度，内容宽度、筛选区、卡片密度和详情返回方式不一致。**设计健康度 5.1/10，设计特异性 4/10**，应先统一页面壳层，再逐域整理局部组件。

> 2026-08-28 最终复评：上述为 8 月 26 日基线。α 已完成共享页面壳、二级面包屑、列表摘要、长流程概览和主要窄屏布局迁移；系统配置与消息集成最后八页已收口。12 个桌面路由与 6 个 760px 路由复检无页面级横向溢出，记录见 `HubX/docs/2026-08-28-α六项收口与最终复检日志.md`。

## 基准页规范

| 项目 | 建议统一值 |
|---|---|
| 页面外边距 | 24px；模块纵向间距 16px |
| 列表页 | 单主卡片：一级页签 → 快捷筛选 → 筛选栏 → 表格；正文 14px，辅助信息 12px |
| 详情页 | 面包屑后接顶部控制卡；实体名 18px/600；状态标签；右侧 28px 高小按钮；下接指标卡和 70:30 主辅分栏 |
| 卡片 | 白底、细边框、默认圆角，不使用重阴影和 3–4px 彩色侧边条 |
| 面包屑 | 一级列表不展示；二级配置、详情、编辑页展示“模块 / 列表 / 当前对象”，14px，底部间距 12px |
| 标题层级 | 页面标题 20px/600；详情实体名 18px/600；卡片标题 16px/600；禁止同级页面出现 24/28px 标题 |
| 内容宽度 | 默认随主内容区铺满；长表单/阅读页可限宽 1200px，禁止孤立的 960px 页面宽度 |

线索页提供了合适的密度和卡片节奏，但它本身没有正式面包屑。现已确认：二级及以上页面统一增加面包屑，替代各页自行实现的普通“返回”入口；有未保存状态的表单仍保留“取消/返回”操作。

## 已确认：长流程页面概览模式

适用于持续时间较长、需要多人协作、频繁回访或具有四个及以上关键阶段的业务对象。页面顶部按固定顺序呈现：

1. **面包屑**：`业务域 / 列表或工作台 / 当前对象`。
2. **对象控制卡**：编号、18px/600 对象名称、主状态、必要的上下文标签；高频主操作置右，危险操作收在末位或更多菜单中。
3. **全宽流程步骤**：展示当前阶段、已完成阶段和下一阶段；不使用项目详情现有的 700px 局部宽度。步骤过多时横向滚动，不压缩文字。
4. **关键摘要板**：独立小卡片，采用线索详情的等宽指标单元；标签 12px，值 14–16px，最小宽度 160px。异常项只使用浅色背景和状态文字，不增加粗侧边条。
5. **工作主体**：概览之后再进入 70:30 主辅区、Tab 或具体任务面板，避免用户进入页面后先寻找当前状态。

线索详情作为视觉标准；项目详情保留现有业务字段，但需统一以下样式：步骤条全宽、指标改为等宽纵向结构、卡片内边距与线索一致、操作区允许换行且保持主次顺序一致。

首批适用页面：`LeadDetail360`、`ProjectDetail360`。后续按业务时长和流程复杂度迁移 `ContractDetail`、`QuotationWorkbench`、`DeliveryPlanPage`、`TripDetail`、`CaseDetail`、`SmartMeetingWorkbench`。普通列表、单步配置和纯数据看板不使用该模式。

## 主要问题与优先级

### P0：先解除阻断

1. ~~`/contracts/:id` 稳定触发 `Rendered more hooks than during the previous render`。~~ 已于 2026-08-26 修复：所有 Hook 提升到加载分支之前，并增加合同加载态；合同详情已迁移统一长流程框架。
2. ~~页面切换时会重复堆叠多条合同通知 Toast。~~ 已于 2026-08-28 收口：签约联动桥正常事件静默，只在联动阻断时显示一次警告，并增加回归测试。

### P1：建立统一页面壳层

1. 88 个路由页面中仅 `/finance/contract-cost/:contractId` 使用面包屑；18 个详情/编辑页各自实现“返回”，层级语义不统一。
2. 34 个页面没有可识别的页面标题。客户、合同、项目、日报、审批、系统管理等列表页分别以页签、按钮或卡片内容代替标题。
3. 标题尺度分裂：线索详情 18px，工作台/报价 20px，客户/员工/差旅 24px，回款及精益交付看板 28px。
4. 宽度与留白不一：智能会议固定约 960px 居中；业务单列表和差旅列表存在额外内边距；多数页面则使用全宽画布。
5. 列表结构不一：部分页面缺页头和筛选分组，部分把一级标题做成 Tab，部分将操作按钮游离在卡片外。

### P2：收敛局部表现

1. 35 个路由页面含 20 处以上内联样式，造成字号、颜色、间距难以批量维护。
2. ~~员工详情和线索财务组件仍有装饰性 3–4px 彩色侧边条。~~ 已于 2026-08-28 移除；表格分隔线与树形连接线属于结构边界，文档预览颜色属于输出稿例外。
3. ~~财务、差旅和精益交付看板大量使用独立 KPI 样式；精益交付还显示 `¥NaN`。~~ 已统一为共享四项 KPI，并接入合同与实收上下文消除失真金额。
4. 图标操作、文字操作和危险操作的排序、按钮尺寸、Tooltip 使用不一致；应复用线索列表的“小图标 + Tooltip”模式。

2. 线索详情顶部概览作为长流程页面的视觉基准，项目详情先与其统一；其他长周期、多步骤业务页面复用同一模式。
