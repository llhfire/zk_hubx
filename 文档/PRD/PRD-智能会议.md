## 1. 需求背景

公司的业务会议（需求评审、方案沟通、进度同步、验收确认等）目前通过即时通信、个人笔记或行政会议记录分散沉淀：会议结论缺少结构化留痕，行动项靠口头或群消息传递，责任人、截止日期、业务归属无统一追踪，跨线索/合同/项目/财务交付 Case 的会议上下文无法追溯。

现有「会议管理」模块定位为行政范畴（会议室安排、行政会议记录），不承载业务会议的纪要智能化工作台（见 `HubX/CONTEXT.md` 运营扩展第 10 条）。

## 2. 产品目标

1. 沉淀业务会议的原始转写文本，形成可追溯的一手资料。
2. 通过 AI 辅助生成结构化纪要草稿（核心决议 + 正文 + 行动项），人工确认后成为正式纪要。
3. 行动项作为主数据统一管理，向统一待办中心做只读投影，责任人、截止日期变更幂等同步，不重复创建。
4. 会议纪要可关联线索、合同、项目、财务交付 Case，形成业务视角的会议上下文。
5. 重要变更全程留痕，版本只读可查，不覆盖历史。

## 3. 首期范围（页面）

### 3.1 纪要列表页（独立一级菜单「智能会议」）

- 顶部统计：本月沉淀会议（统计口径见 §8.2，只读智能会议数据，不混入行政会议）。
- 搜索：标题、决议、正文、行动项内容、可见业务引用、参会人。
- 筛选：状态、业务引用、参会人、整理人、确认人、时间范围、有未完成 TODO。
- 列表项：状态展示（草稿/待确认/已确认/已归档）、会议主题、时间、参会摘要、行动项摘要（进行中 · N 项待办 / 已归档 · N 项待办）、关联业务单。
- 操作：进入查看/编辑、新建纪要。
- 数量与摘要实时派生，不做冗余计数字段。

### 3.2 纪要生成与编辑工作台

- 原始文本区：粘贴纯文本或带说话人标签的转写记录；保存原始内容、文件名、上传时间、解析状态。
- AI 草稿生成：点击「AI 智能提取并生成纪要」，生成结构化待确认草稿（见 §6）。
- 元信息：会议主题、会议时间（选择器）、参会人（人员目录多选）、关联业务单（系统目录选择）。
- 核心决议：列表维护，人工增删改。
- 正文：Markdown 编辑，支持 AI 润色（只生成预览，人工采用后形成新版本）。
- 行动项：内容、责任人（人员目录）、优先级、截止日期（可明确选择无截止）、业务单引用（可继承会议级引用）、完成确认。
- 版本：重要变更生成只读版本，可查看/复制，不直接回滚。
- 动作：保存草稿 / 提交确认 / 确认 / 驳回 / 撤回修改 / 归档 / 删除（仅草稿）/ Markdown 复制。

### 3.3 行政会议来源入口

- 行政会议记录提供显式「创建智能纪要」按钮。
- 创建时带入一次性来源快照：标题、时间、组织人、参会人、已有项目引用。
- 之后不双向自动同步；行政会议取消/删除不删除智能纪要，仅在纪要上提示来源状态。
- 一个行政会议最多对应一篇当前智能纪要（已有当前纪要时入口置灰并提示）。
- 智能会议也可无行政来源独立新建。

## 4. 角色与权限

| 角色 | 权限 |
| --- | --- |
| 整理人 | 编辑纪要全文（草稿/待确认状态）、提交确认、删除草稿、撤回已确认 |
| 确认人 | 确认 / 驳回；可见整篇含原始文本 |
| 普通参会人 | 按会议权限只读；原始文本默认不可见 |
| 业务关联人员 | 须具备对应业务单权限才可查看；无权引用脱敏 |
| 管理员 | 可管理：全部权限 + 删除草稿 |
| 责任人（行动项） | 在待办中心看到投影待办；在纪要工作台完成确认 |

权限规则：

1. 会议角色与业务权限**双重过滤**：先判会议角色，再判业务单权限。
2. 整理人、确认人、管理员可看整篇；普通参会人按会议权限查看；业务关联人员须具备对应业务单权限。
3. 无权引用保留但脱敏提示，不扩大业务权限。
4. 原始文本默认仅整理人、确认人、管理员可见。
5. TODO 仅责任人、会议角色及有对应业务权限者可见。
6. 本期不做字段级权限配置界面。

## 5. 状态机

### 5.1 纪要状态

```
草稿 ──提交确认──> 待确认 ──确认──> 已确认 ──归档──> 已归档
                     │ 驳回
                     ▼
                修改后待确认（回到待确认）
已确认 ──撤回修改──> 草稿（生成新版本后编辑）
```

- 驳回回到「修改后待确认」：整理人修改后再次提交，仍是待确认状态。
- 已确认内容修改必须先撤回，撤回生成新版本，不覆盖历史。
- 归档不取消未完成 TODO。
- 删除：仅草稿状态可删（整理人或管理员）；待确认、已确认、已归档不可物理删除。

### 5.2 行动项状态

- `pending`（未完成）/ `completed`（已完成）/ `canceled`（软取消）。
- 已完成项不原地重开，需新建行动项（新 actionItemId）。
- 行动项拥有稳定 `actionItemId`，纪要版本保存其快照。

### 5.3 版本生成时机

AI 重生成、撤回修改、确认、驳回后重新提交等重要变更均生成只读版本。版本可查看/复制，不直接覆盖当前版本回滚。

## 6. AI 能力边界（详见 `计划/当前/smart-meetings-ai-and-beta-design.md`）

1. AI 结果**始终为草稿**，不直接写正式纪要、业务对象或派发待办。
2. α 使用本地 mock/确定性解析，不暴露浏览器密钥；β 预留服务端 AI 接口，密钥仅服务端持有。
3. 解析失败允许部分草稿或空白草稿，继续人工编辑，不伪装解析。
4. 重新解析生成新草稿，不覆盖原文。
5. AI 只提取明确字段：责任人匹配不到人员目录则为「待指派」（该行动项不可确认）；模糊日期不自动推算，截止日期可明确选择无截止；优先级无依据时默认 P1 并标记待确认。
6. AI 润色只生成正文预览，人工采用后形成新版本，不改变核心决议和行动项结构。

## 7. 行动项与统一待办投影

1. 行动项是**主数据**，统一待办是**只读投影**；保存并同步后创建或更新同一待办，不重复创建。
2. 同步条件：纪要**已确认**，且行动项字段完整（内容、人员目录责任人、优先级、截止日期选择、业务单引用——会议级继承亦可）；不合格项可保留但不派发。
3. 同步规则：
   - 新增合格行动项 -> 创建 TODO。
   - 责任人/截止日期/内容变更 -> 更新同一 TODO。
   - 取消行动项 -> TODO 软取消。
   - 已完成行动项 -> TODO 标记完成；不原地重开。
4. 待办中心不直接编辑、完成或删除会议行动项；行动项完成确认在纪要工作台操作。
5. 未确认草稿不产生待办或提醒。
6. 历史版本只读，不反向修改 TODO。
7. 不自动创建项目任务、报价任务或合同任务，不做外部消息推送。

## 8. 数据与统计口径

### 8.1 业务引用

- 支持线索 / 合同 / 项目 / 财务交付 Case，可多选。
- 必须从系统目录选择，不允许手工输入虚构编号；引用选择器只读不写业务对象。
- 保存视角、ID 与展示快照；业务对象变化不删除引用。
- α 用 mock 目录，β 用服务端搜索。

### 8.2 列表与统计口径

- 统计只读智能会议数据，不混入行政会议。
- 本月沉淀统计**待确认/已确认/已归档**，不统计删除的草稿。
- 未完成行动项读行动项主数据（非版本快照）。
- 关联业务单按当前权限去重展示。

### 8.3 数据持久化

- α：独立 mock + localStorage 原型持久化。
- β：服务端/D1 正式持久化。
- 两版共用领域类型、状态机和纯函数，services 隔离数据访问；智能会议数据不混入行政会议结构。

### 8.4 原始资料

- 保存原始粘贴/文本内容、文件名、上传时间和解析状态；本期不保存录音。
- 不支持的文件格式必须明确提示，不得伪装解析。
- 原始文本随纪要版本受同等权限保护；不自动同步知识库、项目文档或第三方训练数据。

## 9. 明确不做（本期）

会议预约、会议室、冲突检测、日历、参会通知、实时协作、录音播放器、知识库同步、PDF/Word 导出、公开分享链接、企业微信/短信/邮件/飞书推送、实时语音转写、AI 自动修改报价/合同/项目、字段级权限配置、行动项直接复制成项目任务。

## 10. 验收标准（业务口径）

1. 草稿 -> 提交 -> 驳回 -> 修改 -> 确认 -> 撤回 -> 归档全链路状态正确，版本在每次重要变更后生成且只读。
2. 只有已确认纪要产生 TODO；同一行动项多次变更只更新同一 TODO，取消软取消。
3. 草稿可删（整理人/管理员），其余状态不可删。
4. 行政会议创建智能纪要带入快照后，行政会议删除不影响智能纪要存在，仅提示来源状态。
5. 无权用户看到的业务引用脱敏；原始文本对普通参会人不可见。
6. 列表统计不混行政会议、不统计已删草稿。
7. AI 草稿永不直接落正式字段；责任人不在目录则行动项待指派且不可确认。
