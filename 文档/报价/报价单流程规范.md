# ZK HubX 报价单流程规范

> 基于业务确认的完整报价流程，覆盖从需求到出单全链路
> 支持文件流转与表单数据流转双模式
> 报价系统参考：https://bj.zkdemo.com/
> 更新时间：2026-08-14

---

## 一、流程总览

```
产品经理用扣子生成功能清单Excel
       ↓
  手动修改 → 形成功能清单版本
       ↓
  罗总评估人天工时
       ↓
  罗总提交 → 返回产品经理核对
       ↓
  产品经理确认 → 转派销售
       ↓
  销售进入报价系统7步（人天只读，增项报价）
       ↓
  报价汇总 → 系统校验 → 提交审批
       ↓
  三人并行会签（黄奕·罗总·闵总）
       ↓
  ┌─ 全部通过 → 待盖章 → 黄海（董助）盖章 → 下载PDF → 客户确认
  │                                    ↓
  │                          客户不满意 → 重新报价（新建版本）
  │
  ├─ 驳回 → 退回销售修改 → 重新提交审批
  │
  └─ 撤回/作废 → 终止报价流程
```

## 二、报价系统7步流程（参考 bj.zkdemo.com）

> 销售拿到产品经理转派的人天评估后，进入报价系统进行增项报价处理。
> 罗总评估的人天在销售工作台中为**只读**，销售不可直接修改技术人天。

### 步骤导航

```
1 基本信息 → 2 前端配置 → 3 后端配置 → 4 其他岗位 → 5 出差驻场 → 6 其他成本 → 7 报价汇总
```

### Step 1：基本信息

| 字段 | 说明 |
|------|------|
| 项目名称 | 文本输入 |
| 项目类型 | 下拉选择：电商购物/社交社区/出行打车/在线教育/医疗健康/金融理财/企业办公/物联网/其他定制/+自定义 |
| 创建人姓名 | 文本输入（产品经理） |
| 技术评估人姓名 | 自动带入（罗总或被指派技术） |
| 项目需求描述 | 多行文本 |

### Step 2：前端配置

**选择前端平台（可多选）：**

| 分类 | 平台选项 |
|------|----------|
| 小程序 | 微信小程序、支付宝小程序、抖音小程序 |
| 移动APP | iOS APP、Android APP、鸿蒙APP |
| Web平台 | H5移动端、PC Web端 |
| 桌面/平板 | 桌面应用、iPad端、Android平板端 |

每个平台可添加多个角色端（如用户端、商户端），并选择开发语言。

### Step 3：后端配置

**选择后端服务（可多选）：**

| 服务选项 | 说明 |
|----------|------|
| API服务 | 后端API服务 |
| 管理后台 | 后台管理系统 |
| 数据库设计 | 数据库架构设计 |
| 即时通讯 | 实时通讯服务 |
| 支付服务 | 支付集成服务 |

可添加自定义开发语言。

### Step 4：其他岗位

> **关键步骤：** 罗总评估的人天在此步骤**只读展示**，销售在此基础上增项补充。

**罗总人天数据（只读区）：**

| 字段 | 来源 | 销售权限 |
|------|------|----------|
| 功能模块 | 罗总评估 | 只读 |
| 各岗位人天 | 罗总评估 | 只读 |
| 技术备注 | 罗总评估 | 只读 |

> 销售如需修改技术人天，必须退回罗总重新评估。

**销售增项区（可编辑）：**

| 岗位 | 说明 |
|------|------|
| UI设计师 | 销售可新增（罗总未配时） |
| 产品经理 | 同上 |
| 测试工程师 | 同上 |
| 项目经理 | 同上 |
| 架构师 | 同上 |
| 运维工程师 | 同上 |
| DBA工程师 | 同上 |
| 安全工程师 | 同上 |
| 技术支持 | 同上 |

**自定义岗位（销售可新增）：**
- 岗位名称
- 人数
- 天数
- 日均成本（元）

### Step 5：出差驻场

| 配置项 | 说明 |
|--------|------|
| 出差配置 | 启用开关，开启后配置出差费用 |
| 驻场配置 | 启用开关，开启后配置驻场费用 |

### Step 6：其他成本

| 成本类别 | 包含项 | 销售权限 |
|----------|--------|----------|
| 商务成本 | 商务接待费、商务宴请费、礼品费 | 可编辑 |
| 销售成本 | 销售提成比例(%)、其他销售费用 | 可编辑 |
| 项目运营成本 | 客户培训费、文档制作费、版本更新费 | 可编辑 |
| 第三方服务成本 | 云服务器年费、域名费、SSL证书费等 | 可编辑（需附件依据） |
| 硬件设备成本 | 服务器采购费、办公设备费 | 可编辑（需附件依据） |
| 自定义成本 | 成本名称 + 金额（可动态添加） | 可编辑 |

### Step 7：报价汇总

**汇总信息：**

| 展示项 | 说明 |
|--------|------|
| 项目名称 | 基本信息中填写 |
| 创建人 | 基本信息中填写 |
| 技术评估人 | 自动带入 |
| 报价时间 | 系统自动生成 |
| 总人天 | 系统自动汇总 |
| 总人数 | 系统自动汇总 |
| 预估工期 | 系统自动计算 |
| 项目总报价 | 人力成本 + 出差成本 + 其他成本 |

**成本明细：**
- 人力成本明细（各岗位人天×单价）
- 出差/驻场成本明细
- 其他成本明细（商务/销售/运营/第三方/硬件/自定义）

**占比展示：**
- 人力占比 %
- 差旅占比 %
- 其他占比 %

**系统校验（提交前自动执行）：**
- 总人天 × 人天单价 = 人力成本小计
- 各模块小计之和 = 总报价
- 校验不通过 → 禁止提交，提示具体问题

**汇总后操作：**
- 确认无误 → 点击"提交审批" → 进入三人并行会签
- 审批通过前 → 可导出图片（带"草稿/未生效"水印）供内部查看
- 审批通过后 → 可下载正式PDF报价单（盖章版）→ 发给客户

## 三、交付模式：文件流转 vs 表单数据流转

### 3.1 两种模式对比

| 环节 | 文件流转（当前） | 表单数据流转（目标） | 兼容策略 |
|------|-----------------|---------------------|----------|
| **功能清单** | 扣子生成Excel→人工修改 | 系统内建表单 | Excel可导入，表单可导出 |
| **人天评估** | 技术发Excel/口头报数 | 系统工作台填表 | Excel可导入 |
| **综合报价** | 手动算Excel | 报价系统7步自动算 | 文件可导入系统 |
| **审批** | 线下/微信/邮件 | 系统内审批流 | **统一走系统** |
| **最终交付** | 手动盖章→扫描PDF | 系统生成PDF | **统一PDF** |

### 3.2 兼容原则

```
原则1：文件可以导入系统，表单可以导出文件
原则2：审批环节统一走系统，不接受线下审批
原则3：最终交付物（给客户的报价单）统一为PDF格式文档
原则4：过渡期内两种模式并存，逐步迁移
原则5：系统表单数据是审批、盖章和正式报价的唯一依据
```

### 3.3 文件导入规则

- 导入时校验：模板版本、报价编号、重复记录、字段冲突
- 导入后生成数据快照并保留原文件
- 文件仅作为导入/导出/线下协作载体，不作为审批依据

## 四、工作台设计

### 4.1 技术评估工作台（罗总/被指派技术）

> 罗总或被指派技术在此工作台完成人天评估

**工作台功能：**

| 功能模块 | 说明 |
|----------|------|
| 待评估任务列表 | 显示待评估的报价单，含项目名称、产品经理、截止时间 |
| 功能清单查看 | 查看产品经理发来的功能清单（Excel或在线表单） |
| 人天评估表单 | 按模块填写各岗位人天（产品/UI/前端/后端/测试） |
| 技术疑义退回 | 可标记功能描述不清、提出技术疑问、退回产品经理补充 |
| 评估提交 | 填写完成后提交给产品经理 |
| 历史评估 | 查看历史评估记录 |

**评估表单字段：**

| 字段 | 说明 |
|------|------|
| 功能模块 | 自动从功能清单带入 |
| 子功能 | 自动从功能清单带入 |
| 产品/人天 | 技术填写 |
| UI/人天 | 技术填写 |
| 前端/人天 | 技术填写 |
| 后端/人天 | 技术填写 |
| 测试/人天 | 技术填写 |
| 小计 | 系统自动汇总 |
| 备注 | 技术填写风险说明等 |

**技术疑义退回机制：**
- 罗总评估时可标记"功能描述不清"
- 提出技术疑问 → 退回产品经理补充
- 产品经理补充后重新提交 → 罗总继续评估
- 疑义未解决前，人天评估不可提交

**文件模式兼容：**
- 可上传Excel评估表，系统自动解析填入
- 可导出Excel供线下评估后上传

### 4.2 报价工作台（销售）

> 销售拿到产品经理转派的人天评估后，在此工作台进行最终报价处理

**工作台功能：**

| 功能模块 | 说明 |
|----------|------|
| 待报价任务列表 | 显示待报价的报价单，含项目名称、技术评估状态、产品经理转派时间 |
| 人天评估查看 | **只读**查看罗总评估的人天工时数据 |
| 报价系统入口 | 进入7步报价流程（增项报价处理） |
| 报价历史 | 查看历史报价记录 |
| 报价对比 | 多版本报价对比（重新报价时） |

**报价系统7步入口：**

| 步骤 | 入口 | 说明 |
|------|------|------|
| 1 基本信息 | 表单 | 项目名称/类型/创建人/技术评估人/需求描述 |
| 2 前端配置 | 选择卡片 | 前端平台多选 + 角色端配置 |
| 3 后端配置 | 选择卡片 | 后端服务多选 + 自定义语言 |
| 4 其他岗位 | 只读区+编辑区 | 罗总人天只读 + 销售增项可编辑 |
| 5 出差驻场 | 开关+表单 | 出差/驻场配置 |
| 6 其他成本 | 表单 | 商务/销售/运营/第三方/硬件/自定义 |
| 7 报价汇总 | 汇总页 | 总报价 + 明细 + 占比 + 校验 + 提交审批 |

**汇总后操作：**
- 确认无误 → 点击"提交审批" → 进入三人并行会签
- 审批通过前 → 可导出图片（带水印）供内部查看
- 审批通过后 → 可下载正式PDF报价单（盖章版）→ 发给客户

**文件模式兼容：**
- 可导入Excel报价单，系统自动解析
- 可导出Excel/PDF报价单

## 六、正常流程（6步）

### 第1步：产品经理出功能清单

- 产品经理用**扣子（Coze）**生成初始功能清单Excel
- **手动审核修改**，形成功能清单版本（v1.0）
- **不需要黄奕审核**，**需抄送销售**
- 指定报价完成的截止时间

### 第2步：罗总评估人天

- 罗总收到功能清单后，评估各模块人天工时
- 可指派技术人员协助评估
- 评估结果录入技术评估工作台
- 可标记功能疑义、退回产品经理补充
- **评估完成后返回产品经理核对**

### 第3步：产品经理核对并转派销售

- 产品经理收到罗总的人天评估后核对
- 确认无误后**转派给销售**
- 销售在报价工作台收到待报价任务

### 第4步：销售进入报价系统

- 销售进入报价系统7步流程
- **Step 4 其他岗位**：罗总人天**只读**展示，销售在此基础上增项
- 其余步骤：配置前端/后端/出差/其他成本等
- 系统自动校验报价合理性
- 报价汇总页点击"提交审批"→ 进入三人并行会签

### 第5步：三人并行会签 + 盖章

**并行会签（三人同时审批）：**

| 审批人 | 角色 | 审批重点 |
|--------|------|----------|
| 黄奕（销售部负责人） | 审批 | 报价合理性、利润、付款条件 |
| 罗总 | 审批 | 人天准确性、技术可行性、工期 |
| 闵总 | 审批 | 商务条款、客户信用、战略匹配 |

**审批规则：**
- 三人**并行会签**，全部通过才进入"待盖章"
- 任一人**驳回**，流程立即退回销售
- 修改后重新提交，三人**全部重新审批**

**盖章：**
- 三人全部通过 → 进入**[待盖章]**状态
- **黄海（董助）**执行盖章（建议1个工作日内完成）
- 盖章后系统状态变为**[已盖章]**
- **此时可下载PDF报价单（盖章版）**

### 第6步：客户收到报价

- 销售将PDF报价单发送客户
- 客户收到的是 **PDF格式文档**，包含：
  - 报价信息（项目总价、付款方式、工期等）
  - 功能清单（模块、子功能、功能描述）
- 报价单抄送给所有参与人
- 系统记录发送时间，作为报价有效期起算日

### 第7步：客户确认

- 客户确认报价 → 进入合同签约
- 客户不满意报价 → 进入**重新报价流程**（见第八节）
- 客户放弃 → 进入**作废流程**（见第九节）

## 七、驳回流程

### 7.1 驳回场景

| 审批人 | 可能驳回原因 |
|--------|-------------|
| 黄奕（销售部负责人） | 报价偏低/利润不足、付款条件不合理、客户资质存疑 |
| 罗总 | 人天评估不合理、技术方案有风险、工期不可控 |
| 闵总 | 商务条款不妥、客户信用风险、战略优先级不匹配 |

### 7.2 驳回后处理

```
任一审批人驳回
    ↓
系统记录驳回意见（必填，说明驳回原因）
    ↓
退回销售（不是产品经理）
    ↓
销售根据驳回意见修改
    ↓
  ┌─ 修改报价金额 → 重新汇总报价 → 重新提交审批
  ├─ 功能范围变更 → 退回产品经理 → 产品经理修改功能清单 → 罗总重新评估 → 重新提交
  └─ 修改商务条款（付款方式、工期等）→ 重新提交审批
    ↓
重新提交后，黄奕·罗总·闵总三人全部重新审批
```

### 7.3 驳回规则

- **驳回意见必填**：审批人必须填写驳回原因，不能空白驳回
- **驳回次数不限**：但每次驳回必须修改后才能重新提交
- **不能原样重提**：销售修改后必须变更内容，系统校验有差异才能重新提交
- **审批链重置**：驳回后重新提交，三人需全部重新审批

### 7.4 驳回后的通知

| 通知对象 | 通知内容 |
|----------|----------|
| 销售 | 报价单被驳回 + 驳回意见 + 驳回人 |
| 产品经理 | 报价单被驳回（知会） |
| 其他审批人 | 报价单已驳回，待修改后重新提交 |

## 八、重新报价流程

### 8.1 触发条件

客户收到报价后不满意，要求重新报价：
- 减功能（砍掉部分模块）
- 减服务项（去掉某些非核心服务）
- 调整价格（压价）
- 调整工期（要求缩短）

### 8.2 流程（按变更范围区分）

```
客户反馈不满意
    ↓
销售/产品经理与客户沟通调整内容
    ↓
  ┌─ 功能/服务/工期/人天变更 → 产品经理修改功能清单 → 罗总重新评估人天 → 产品经理核对转派 → 销售重新报价 → 三人审批 → 盖章
  │
  └─ 仅价格调整（功能/人天不变）→ 销售调整报价金额 → 三人审批 → 盖章
    ↓
  两种情况均需：创建新报价版本（v2.0）→ 不覆盖旧版本
```

### 8.3 关键规则

- **不允许覆盖旧版本**，必须新建报价版本
- 变更记录需保留：新旧功能清单对比、新旧报价对比
- 报价单版本号递增（v1.0 → v2.0 → v3.0...）
- 每个版本的审批记录、盖章记录独立保存
- 即使仅调整价格（人天不变），也必须重新三人审批+重新盖章

## 九、作废流程

### 9.1 作废场景

| 场景 | 说明 |
|------|------|
| 客户明确放弃 | 客户口头或书面通知不再推进 |
| 项目取消 | 内部决定不再跟进该客户/项目 |
| 报价超有效期 | 报价单超过约定有效期（如30天），客户未确认 |
| 需求重大变更 | 客户需求发生重大变化，原报价完全不适用 |
| 内部策略调整 | 公司战略调整，决定不接此类项目 |

### 9.2 作废权限

| 报价单状态 | 谁可以发起 | 谁审批同意 |
|------------|-----------|-----------|
| 草稿 | 产品经理 | 无需审批，直接作废 |
| 审批中 | 销售或产品经理 | 通知所有审批人知会 |
| 已审批/待盖章 | 罗总或闵总发起 | 罗总或闵总审批同意 |
| 已盖章 | 黄海（董助）发起 | 黄海（董助）审批同意 |
| 已发给客户 | 黄海（董助）发起 | 黄海（董助）同意 + 销售通知客户 |

### 9.3 作废流程

```
发起作废申请
    ↓
填写作废原因（必填）
    ↓
  ┌─ 草稿状态 → 产品经理直接作废 → 通知销售
  ├─ 审批中 → 通知审批人 → 流程终止
  ├─ 已审批/待盖章 → 罗总或闵总审批同意 → 作废 → 通知所有人
  ├─ 已盖章 → 黄海（董助）同意 → 作废 → 通知所有人
  └─ 已发给客户 → 黄海（董助）同意 → 作废 → 销售通知客户
    ↓
系统标记为 [已作废]，保留历史记录
    ↓
后续如需重新报价 → 新建报价单（不恢复旧单）
```

### 9.4 作废后处理

- **不可恢复**：作废的报价单不能重新激活，只能新建
- **保留记录**：作废原因、作废人、作废时间永久保留
- **通知销售**：销售需跟进客户，确认客户已知悉报价作废
- **合同关联**：若已有关联合同，作废报价单需在合同中标注

## 十、主动撤回流程

> 销售提交审批后发现错误，可主动撤回，无需等待审批人驳回。

### 10.1 撤回规则

- 审批完成前，销售可以主动撤回
- 撤回后回到报价草稿状态
- 必须填写撤回原因
- 撤回记录保留

### 10.2 撤回流程

```
销售发现错误 → 点击"撤回"
    ↓
填写撤回原因（必填）
    ↓
系统通知所有审批人：报价单已撤回
    ↓
回到 [草稿] → 销售修改后重新提交
```

## 十一、超时异常流程

### 11.1 技术评估超时

```
产品经理指定截止时间（如3日内完成）
    ↓
罗总/被指派人未在截止时间内完成评估
    ↓
系统自动提醒 → 第一次提醒（截止前1天）
    ↓
仍超时 → 第二次提醒（超时后）→ 通知产品经理
    ↓
产品经理决定：
  ├── 催促技术继续评估
  ├── 自行估算人天（标注为产品估算，非技术确认）
  └── 与销售沟通延长时限
```

### 11.2 审批超时

```
报价单发起三人并行会签
    ↓
某审批人超过2个工作日未审批
    ↓
系统自动催办提醒
    ↓
超过5个工作日仍未审批
    ↓
系统通知销售 → 销售可：
  ├── 线下催促
  └── 超时自动升级（通知闵总/更高层级）
```

### 11.3 盖章超时

```
三人审批通过 → 进入[待盖章]
    ↓
黄海（董助）超过1个工作日未盖章
    ↓
系统提醒黄海
    ↓
超过2个工作日仍未盖章
    ↓
通知销售 + 升级至闵总
```

## 十二、需求变更异常流程

### 12.1 审批过程中需求变更

```
报价单已发起审批，客户提出需求变更
    ↓
销售判断变更影响：
  ├── 变更不影响功能范围和人天 → 继续审批
  ├── 变更影响功能范围 → 撤回审批 → 退回产品经理 → 修改功能清单 → 罗总重新评估 → 重新提交
  └── 变更重大 → 作废当前报价 → 重新走全流程
```

### 12.2 已盖章后需求变更

```
报价单已盖章发给客户，客户提出需求变更
    ↓
销售判断变更影响：
  ├── 增功能/增服务 → 新建报价单（增量部分）→ 走完整审批流程
  ├── 减功能/减服务 → 重新报价（见第八节）
  └── 项目取消 → 作废流程（见第九节）
```

## 十四、版本管理

### 14.1 报价版本链路

每个报价版本包含完整快照，不可覆盖：

```
报价V1
├─ 功能清单快照V1
├─ 罗总人天评估快照V1
├─ 销售增项报价快照V1
├─ 审批记录V1
│   ├─ 黄奕（销售部负责人）：通过/驳回 + 意见 + 时间
│   ├─ 罗总：通过/驳回 + 意见 + 时间
│   └─ 闵总：通过/驳回 + 意见 + 时间
├─ 盖章记录：黄海（董助）盖章时间
├─ 发送记录：销售发送客户时间
└─ 盖章PDF V1
```

### 14.2 版本规则

- 任何关键数据变化必须新建报价版本
- 旧版本永久保留，不可覆盖
- 重新报价时自动创建新版本（v1.0 → v2.0 → v3.0...）
- 作废后不可恢复，如需重新报价必须新建版本

## 十五、审批流状态机（系统实现参考）

```
[草稿]
  ↓ 产品经理提交
[功能清单已确认]
  ↓ 罗总评估人天
[人天评估完成] ←→ 可退回（技术疑义）
  ↓ 产品经理核对并转派
[已转派销售]
  ↓ 销售进入报价系统7步
[报价已汇总]
  ↓ 提交审批（系统校验通过）
[审批中] ←→ 黄奕审批 / 罗总审批 / 闵总审批（并行）
  │
  ├── 全部通过 → [审批通过/待盖章]
  │                  ↓ 黄海（董助）盖章（1工作日内）
  │               [已盖章]
  │                  ↓ 销售下载PDF报价单
  │               [已发出]
  │                  ├── 客户确认 → [成交] → 进入合同
  │                  ├── 客户不满意 → [重新报价] → 新建版本
  │                  └── 超期未确认 → [待跟进]
  │
  ├── 驳回 → [退回修改] → 销售修改 → 重新提交 → [审批中]
  │
  ├── 销售主动撤回 → [草稿] → 修改后重新提交
  │
  └── 作废 → [已作废] → 不可恢复，新建报价单
```

## 十七、报价文件格式说明

最终给客户的报价文件为 **PDF格式文档**，包含两部分：

### Part 1：报价信息
- 项目名称
- 项目总价（含税）
- 付款方式（如50%-40%-10%）
- 项目工期
- 报价有效期
- 报价编号 + 版本号
- 备注说明

### Part 2：功能清单
- 功能模块
- 子功能
- 功能描述
- 备注

### PDF安全特性
- 带唯一报价编号和版本号
- 带二维码（可查询报价状态）
- 作废后二维码查询显示"已作废"
