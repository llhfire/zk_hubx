## 一、模块概述

精益交付（`/financial-delivery`）是**财务交付视角**下的一笔业务全景：从工时评估、报价、合同、回款到成本与利润的全链路。本次收口解决移植稿的核心缺陷——**所有汇总数字都是与明细无关的硬编码**，五类数据（工时评估、报价单、合同、回款、成本项）互相对不上、且与真实域（报价域、合同域、运营费用）零关联。

**核心原则：mock 只造原子事实，一切汇总派生。**

## 二、数据来源契约（五条数据链）

### 2.1 工时评估
- 事实源：**报价域** Stage1/Stage2（功能清单 + 岗位人天评估）。精益交付不自建第二套评估。
- 评估口径：**按岗位拆分天数**（产品/设计/前端/后端/测试/其他）。总人天、评估成本 = 加总派生。
- 报价功能项直接引用同一份岗位天数，不再出现「评估 8 天、报价 13 天」。

### 2.2 报价单
- 事实源：**报价域**（pages/quotation，α 走 mock 接缝、β 走 HTTP）。精益交付删除内部 mockQuotations。
- 金额公式（全部派生）：
  - `功能报价 = Σ(岗位人天 × 对外报价单价)`
  - `totalAmount = 功能报价 × (1 + 利润加成率) + 服务项合计`
- **第三方代收代付**（云服务器/域名/SSL/短信，客户承担）单列展示，**不计入** totalAmount 与利润计算。
- 参数两套、不得混用：
  - 对外报价单价 `rolePrices`：默认 1000/800/1200/1200/600/800；
  - 成本日薪：400/350/500/450/450/350，独立常量维护。

### 2.3 合同数据
- 事实源：**合同域**（pages/contracts）。合同域 mock 补建 3 份带分期回款计划的合同，case.contractId 指向真实合同 ID。
- case 的合同金额 = 主合同金额 + Σ已归档未作废补充合同变更额（与主术语表「有效标的额」同口径）。

### 2.4 回款数据
- 事实源：**合同域** paymentPlans（应收基线）+ collectionRecords（实际回款）。
- **收入确认口径 = 回款（收付实现制）**：actualRevenue = 回款记录累计。完工百分比法（权责发生）标注为未来演进，本轮不实现（ADR-0087）。
- 趋势图双线：应收基线（期次计划累计）vs 实际回款（到账累计）。

### 2.5 成本项
- 事实源：`CaseCostItem` 流水（唯一成本事实）。totalCost = Σactual；EAC = Σactual + Σforecast；成本结构/趋势/穿透全部派生。
- 口径对齐运营费用 PRD（ADR-0076–0085）：
  - **出差补贴归差旅**（商务成本），不归 labor；
  - 运营分摊 = **项目工天 × 时薪公摊率**，公摊率常量与运营费用模块共用（该模块落地前 mock 同值常量）。
- 成本日薪独立成套，见 2.2。

## 三、派生指标定义（双口径）

**全周期口径**（衡量这笔生意本身好不好，用于健康灯/气泡图纵轴/预警）：

| 指标 | 定义 |
|------|------|
| 全周期利润率 | (有效标的额 − EAC) / 有效标的额 |
| 健康状态 | 全周期利润率 vs targetMargin + EAC 超预算帽（budgetCap）红灯 + WIP 天数超限黄灯 |

**回款口径**（衡量现金压力，只用于 WIP 与现金流展示，**不做健康判定**——回款节奏会导致交付前期利润率必然失真）：

| 指标 | 定义 |
|------|------|
| totalRevenue | 累计回款（合同域 collectionRecords，按到账日落月） |
| 已发生利润率 | (累计回款 − Σactual 成本) / 累计回款（仅趋势图展示） |
| WIP 占用 | max(0, Σactual 成本 − 累计回款) |
| WIP 天数 | 距最近一次回款的天数 |
| 应收基线 | paymentPlans 期次按预计回款日落月累计 |

## 四、仪表盘

- 概览统计：从 case 列表派生（删除 mockDashboardData.overview 的平行口径）。
- 气泡图：contractAmount/EAC/margin 全部取派生值。
- 穿透看板：按行业分组，从 cases + 成本明细派生（成本拆分 development/rework、entertainment/travel 按 costType 归集）。
- **模拟器 = 敏感性 + 底线价**（参数语义本次定死）：
  - 输入：合同额（可拖动）、功能范围%（保留的已评估功能项，按金额加权）、商务预算（= case.commercialCap，与成本链同源）、目标利润率（参考线）；
  - 输出：利润率 = (合同额 − EAC(范围%)) / 合同额；盈亏平衡合同额（利润率=0）；底线价 = EAC / (1 − 目标利润率)。
- 相似项目：按行业 + 项目类型从已完结 case 派生，不再引用 proj-sim-xxx。

## 五、事后总结（PostMortem）

- predictedPnl：结项时点的**四类完整预测快照**--人力 = 最终报价评估人天 × 成本日薪；商务/运营/第三方 = 结项时点 Σforecast 成本项（当时 EAC 的分项）。不可变。
- actualPnl：从成本明细 + 回款派生，四类对应。
- 接口修正：毛利存金额、净利率存百分比的混用字段改为**金额 + 百分比双字段**。

## 六、Case 定位（ADR-0088，经复审修正）

- 保留 **CASE- 独立编号**（`CASE-YYYY-MM-DD-序号`）。
- 主术语表业务单概念修订：线索/项目/合同三视角之外，精益交付 Case 是**财务交付视角**（第四视角）。
- **Case 是轻实体**（ADR-0086/0088 修正案）：不持有业务明细事实（报价/合同/回款/成本全部派生），但持有：
  - **管理参数**：targetMargin（目标利润率）、budgetCap（预算帽）、commercialCap（商务上限）——建 Case 时填写，无第二个候选主人；
  - **自有状态机**：草拟/报价/协商/已签/交付/挂起/验收/催款/完结/终止 10 态。其中「协商中」「催款中」在报价/合同/项目域均无对应状态可派生，由人推进（系统可基于回款逾期等给半自动建议），不假装派生。
- Case ↔ 报价 1:N：关联主报价 + 全部补充报价，报价 Tab 列表展示。

## 六A、成本流水写入口（三通道 + 兜底）

| 通道 | 生成规则 |
|------|----------|
| 日报通道 | 日报提交后按「项目工时 × 岗位成本日薪」自动生成人力成本流水 |
| 报销通道 | 报销通过后自动归集差旅/商务/运营成本 |
| 公摊通道 | 运营费用模块月结后按项目工天 × 时薪公摊率自动生成分摊流水 |
| manual | 仅兜底（以上三通道覆盖不了的一次性成本） |

mock 阶段：sourceId 能接真实日报域 mock 就接，接不上的降级 manual，**删除假 dr-xxx/reimb-xxx 引用**。

## 六B、模拟器缩放规则

- **只有 forecast 人力成本随功能范围% 线性缩放**；已发生成本、商务、运营分摊、第三方一律不缩（租金照付、已出差照算、云服务照扣）——保守估计，不把不可省的钱算成可省。
- 底线价 = EAC(范围%) / (1 − 目标利润率)。

## 六C、权限

精益交付仅财务 + 管理层可见；管理参数与成本项仅财务可改，其他角色只读（与运营费用 ADR-0084 同风格，具体矩阵编码时按角色表落）。

## 七、不做（本轮）

- 不做完工百分比收入确认；不接真实后端（合同域仍是内存 mock）；不动运营费用模块与日报/工时模块；不做预算管理、多币种。
