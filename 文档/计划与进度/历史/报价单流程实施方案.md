# 报价单流程实施方案（本轮）

## 核心架构决策

**一个工作台贯穿报价全流程。** 功能清单、人天评估、7 步报价、审批盖章不再是四个独立页面，而是同一个工作台的四个阶段（Stage）。不同角色在不同阶段打开同一 URL，看到的是当前阶段的内容。

```
/quotation              报价中心（列表 + 状态看板 + 角色切换器）
/quotation/:quoteId     统一工作台（内部按 stage 渲染，取代原三条路由）
```

原 `/quotation/eval|quote|approval/:quoteId` 三条路由改为重定向到 `/quotation/:quoteId`，保证线索页等已有跳转不断。

## 状态机缺口（本轮补齐）

已确认规则：**三人并行会签保持不变**（黄奕+罗总+闵总，全通过才待盖章，任一驳回全员重审）。

现有 `decideAudit` 的 bug：驳回时未清空其他人已 APPROVED 的记录，与"全员重审重置"规则冲突。

需要新增的流转动作：

| 动作 | 角色 | 状态迁移 |
|---|---|---|
| `submitFeatureList` | PM | draft → feature_confirmed |
| `raiseTechIssue` | 罗总 | feature_confirmed → draft（挂 PENDING 疑义，阻断评估提交） |
| `resolveTechIssue` | PM | 疑义转 RESOLVED，回 feature_confirmed |
| `submitEval` | 罗总 | feature_confirmed → eval_completed（校验无 PENDING 疑义） |
| `assignToSales` | PM | eval_completed → assigned_sales |
| `returnToTech` | 销售 | assigned_sales → feature_confirmed（附退回理由） |
| `submitForAudit` | 销售 | assigned_sales/rejected → auditing（重置全部审批节点） |
| `withdrawAudit` | 销售 | auditing → assigned_sales（主动撤回，记原因） |
| `decideAudit` | 三审批人 | 驳回→rejected 且**重置全部节点**；全通→pending_stamp |
| `stampQuote` | 黄海 | pending_stamp → stamped |
| `markSent` | 销售 | stamped → sent（登记发送时间，有效期从此起算） |
| `markDeal` / `markVoided` | 销售 | sent → deal / voided |
| `createNewVersion` | 销售 | 基于当前单 v1.0 → v2.0，旧版不可覆盖 |

每个动作追加一条 `QuoteTimelineEvent`（新增类型），供工作台顶部流转轨迹展示。

## 阶段与角色可见性矩阵

Stage 由 `status` 推导，不额外存字段：

```
Stage 1 功能清单   draft / feature_confirmed
Stage 2 人天评估   feature_confirmed / eval_completed
Stage 3 报价配置   assigned_sales / rejected / auditing(只读)
Stage 4 审批盖章   auditing / pending_stamp / stamped / sent / deal / voided
```

阶段导航行为：**当前阶段可编辑，已过阶段只读回看，未到阶段锁定**。可编辑还需角色匹配（PM 只能编 Stage 1，罗总只能编 Stage 2，销售只能编 Stage 3，审批人/董助只能操作 Stage 4）。

## 实施步骤

### 1. `quotation/types.ts` 扩展
- `QuoteTimelineEvent`（时间、操作人、角色、动作、说明）
- `QuoteStage` 类型 + `deriveStage(status)` 推导函数
- `Quote` 增 `timeline`、`deadline`（技术评估截止）、`ccSalesNames`、`sentAt`
- Stage 3 补型：`FrontendConfig`（平台/角色端/框架）、`BackendConfig`（服务项/语言）

### 2. `quotation/quoteFlow.ts`（新建，纯函数 + 单测）
状态机核心：`canEditStage(status, role, stage)`、`nextStatus(action, quote)`、金额汇总 `computeQuoteSummary(quote)`（技术人天成本 + 增项 + 差旅驻场 + 其他成本），以及一致性校验（∑分项 = 总价）。放纯函数便于 Vitest 覆盖。

### 3. `QuotationContext.tsx` 补全
接入上表全部动作，统一走 `quoteFlow` 的迁移函数并写 timeline。

### 4. `QuotationWorkbench.tsx`（新建，统一外壳）
- 顶部项目状态条：报价编号 / 版本 / 状态 Tag / 客户 / 截止倒计时
- 阶段 Steps 导航（可点击回看，锁定态 disabled）
- 角色切换器（原型演示用，接 Context 的 `currentRole`）
- 主体按 stage 渲染 Stage1~4 面板
- 底部流转操作栏：按 (status, role) 动态出按钮
- 右侧折叠面板：流转轨迹 timeline + 技术疑义

### 5. `Stage1FeatureList.tsx`（新建，工作台一）
左侧模块树 + 主表格（一级模块/二级子功能/功能描述/备注），支持增删模块与子功能、行内编辑；技术疑义高亮行与答复；提交前校验（至少 1 模块 1 子功能、无未答复疑义）。Excel 导入导出本轮只留按钮占位（`Message.info`），不实现解析。

### 6. Stage2/3/4 改造
- **Stage2**：迁入外壳；补动态岗位列增删、人天手动录入（行小计/列汇总自动算）、技术疑义退回按钮、工期与技术方案备注可编。切片重组（打包/合并/拆分）本轮保留现有三种粒度的展示，不做交互式重切。
- **Stage3**：补齐 7 步真实内容 — Step1 基本信息补录、Step2 前端配置（平台多选卡片+角色端+框架）、Step3 后端配置、Step4 罗总人天只读 + 增项 CRUD + 退回罗总、Step5 出差驻场开关与金额、Step6 其他成本 CRUD、Step7 汇总校验并提交审批 / 主动撤回。
- **Stage4**：迁入外壳；修驳回重置逻辑；补穿透式明细（汇总 → 人天/增项 → 功能清单 → 外部成本四层折叠）；盖章后"下载 PDF"沿用占位。

### 7. `QuotationCenter.tsx`（新建）替换旧列表
接 `QuotationContext.quotes`，列：报价编号 / 项目 / 客户 / 版本 / 状态 / 当前待办人 / 总价 / 更新时间 / 操作（进入工作台）。顶部按状态分组统计 + 角色切换器。删除 `pages/QuotationList.tsx`。

### 8. 路由与菜单
- `routes.tsx`：加 `quotation` → `QuotationCenter`、`quotation/:quoteId` → `QuotationWorkbench`；三条旧路由改重定向；移除 `QuotationList` import
- `MainLayout.tsx`：`/quotation` 菜单项从"财务管理"下移到更贴合业务的位置由你定；本轮先保留原位，只确保高亮逻辑覆盖 `/quotation/*`

### 9. 验证
- `npx vitest run src/app/pages/quotation/__tests__/quoteFlow.test.ts`（新建单测：状态迁移合法性、驳回重置、金额一致性、权限矩阵）
- `npm run build` 全量构建

## 本轮不做（留后续）

Excel 双向导入导出解析、版本 Diff 对比器、真实 PDF 生成与电子签章、代理/转交机制、超时催办与提醒接入、成本敏感数据的销售视图脱敏、交互式切片重组。均以按钮占位或注释标明。
