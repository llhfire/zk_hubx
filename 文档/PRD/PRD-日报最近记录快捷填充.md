| 项目 | 内容 |

## 2. 需求背景

员工填写日报时，经常重复选择相同的工作归属、项目和工作性质。现有表单需要逐项选择，重复操作较多，影响日报填写效率。

本需求在工作项中增加“最近记录”快捷标签，展示当前员工最近提交过的常用组合。员工点击标签后，系统自动填充对应的工作归属、项目和工作性质，减少重复选择。

## 3. 产品目标

1. 降低重复填写日报时的选择成本。
2. 帮助员工快速复用本人最近提交过的工作组合。
3. 保证快捷填充不覆盖工作内容、工时等本次日报特有信息。
4. 保证历史项目停用或退出当前可选范围后，仍能正确显示历史项目名称。

## 4. 适用范围

本期适用于“填写日报”弹窗中的销售日报工作项。

最近记录包含以下三个字段：

- 工作归属。
- 项目，即工作归属下的关联项目、线索或日报项目。
- 工作性质。

本期不包含：

- 手动新增、编辑或删除最近记录。
- 收藏、置顶或拖动排序。
- 跨员工共享最近记录。
- 根据点击次数计算常用记录。
- 自动填充工作内容、用时、风险反馈或明日计划。

## 5. 用户故事

作为需要每天填写日报的员工，我希望系统展示本人最近提交过的“工作归属/项目/工作性质”组合，以便点击后快速填充当前工作项。

## 6. 页面设计

### 6.1 展示位置

- 在每条工作项的“工作归属”字段上方增加一行快捷标签。
- 行标题固定为“最近记录：”。
- 首条工作项和通过“新增今日工作详情”创建的工作项均展示最近记录。
- 每条工作项展示同一组当前员工最近记录。
- 当前员工没有符合条件的历史记录时，不显示“最近记录”行。

### 6.2 标签格式

每个标签按照以下格式展示：

`工作归属/项目/工作性质`

示例：

- `软件售前/A公司CRM系统开发需求/线索跟进`
- `开发/B公司数据中台项目/需求对接`
- `运营/HubX内部优化项目/内部协同`
- `移民售前/加拿大移民咨询项目/方案撰写`
- `推广/品牌推广活动/报价沟通`

### 6.3 展示数量

- 去重后最多展示 5 个标签。
- 不足 5 个时，按实际有效记录数量展示。
- 标签超过当前行宽时自动换行，不横向撑开弹窗。

## 7. 数据规则

### 7.1 数据范围

系统仅读取满足以下条件的日报记录：

1. 日报撰写人为当前登录用户。
2. 日报模板为销售日报。
3. 日报已经提交。
4. 工作项同时存在工作归属、项目名称和工作性质。

不得读取其他员工的记录。

### 7.2 排序规则

1. 日报按照提交时间从新到旧排序。
2. 同一份日报包含多条工作项时，按照日报中原有工作项顺序处理。
3. 最新记录显示在最前。

### 7.3 去重规则

以“工作归属 + 项目 + 工作性质”三项完整组合作为唯一键。

- 三项完全相同时视为重复记录，只保留时间最新的一条。
- 任意一项不同均视为不同记录。
- 先按时间倒序处理，再去重，最后截取前 5 条。

处理顺序如下：

```text
筛选当前员工已提交日报
→ 按提交时间倒序
→ 提取工作归属、项目、工作性质
→ 过滤字段不完整的记录
→ 按三项组合去重
→ 取前 5 条
```

## 8. 交互规则

### 8.1 点击标签

用户点击某个最近记录标签后，系统自动填充当前标签所在工作项的以下字段：

| 字段 | 填充内容 |
|---|---|
| 工作归属 | 历史记录中的工作归属 |
| 项目 | 历史记录中的项目 ID 和项目名称 |
| 工作性质 | 历史记录中的工作性质 |

点击标签不得修改当前工作项的以下字段：

- 工作内容/成果。
- 用时。
- 风险/异常反馈。
- 其他未包含在标签中的字段。

### 8.2 多工作项

- 每条工作项的最近记录标签只作用于当前工作项。
- 点击第一条工作项中的标签，不得修改其他工作项。
- 新增工作项后，其最近记录标签应立即可用，无需关闭并重新打开弹窗。

### 8.3 键盘操作

- 标签可通过键盘获得焦点。
- 按 Enter 或空格键时，行为与鼠标点击一致。

## 9. 历史项目兼容

当历史记录对应的项目已停用、已完成或不在当前项目下拉选项中时：

1. 点击标签后仍需填充历史项目 ID 和项目名称。
2. 项目下拉框必须正确显示历史项目名称，不得显示为空。
3. 该历史项目仅作为当前选中项补充展示，不得因此重新加入正常可选项目列表。
4. 用户主动切换工作归属或重新选择项目后，继续执行现有项目联动规则。

## 10. 状态更新

- 用户成功提交一份新日报后，该日报中的有效工作项进入最近记录数据范围。
- 再次打开填写日报时，系统按照最新提交时间重新计算最近记录。
- 若新提交的组合与已有组合重复，仅更新其排序位置，不增加重复标签。

## 11. 异常与边界场景

| 场景 | 处理规则 |
|---|---|
| 没有历史日报 | 不显示最近记录行 |
| 历史工作项缺少任一组成字段 | 不生成标签 |
| 历史记录超过 5 个 | 去重后仅显示最新 5 个 |
| 多条历史记录组合相同 | 仅显示最新一条 |
| 历史项目不在当前选项中 | 保留并显示历史项目名称 |
| 点击标签前已填写工作内容或工时 | 保留原内容和工时 |
| 新增多条工作项 | 每条工作项均显示最近记录 |

## 12. 数据字段

最近记录复用日报工作项已有数据，不新增独立持久化表。

| 业务字段 | 数据字段 |
|---|---|
| 当前用户 | `DailyReport.userId` |
| 日报模板 | `DailyReport.templateType` |
| 提交时间 | `DailyReport.createdAt` |
| 工作归属 | `SalesWorkItem.workAttributionCategory` |
| 归属类型 | `SalesWorkItem.workAttributionType` |
| 项目 ID | `relationId`，兼容 `leadId`、`projectId` |
| 项目名称 | `relationName`，兼容 `leadName`、`projectName` |
| 工作性质 | `SalesWorkItem.workNature` |

## 13. 验收标准

### AC-01 展示位置

打开销售日报填写弹窗时，“最近记录”显示在每条工作项的“工作归属”上方。

### AC-02 数据归属

最近记录仅来源于当前登录用户的已提交销售日报，不得出现其他员工记录。

### AC-03 标签内容

标签严格按照“工作归属/项目/工作性质”格式展示。

### AC-04 排序

最近提交的有效组合显示在最前。

### AC-05 去重与数量

三项组合完全相同的记录只显示一次，去重后最多显示 5 个不同标签。

### AC-06 快捷填充

点击标签后，当前工作项的工作归属、项目和工作性质正确填充。

### AC-07 字段保护

点击标签不得清空或修改当前工作项已填写的工作内容、用时和风险反馈。

### AC-08 多工作项

点击“新增今日工作详情”后，新增工作项同样展示最近记录；点击标签只修改该工作项。

### AC-09 历史项目

历史项目不在当前项目选项中时，点击标签后项目下拉框仍正确显示历史项目名称。

### AC-10 空数据

当前用户没有有效历史记录时，不显示空标签或无效占位。

## 14. 测试建议

1. 单元测试：排序、字段完整性过滤、组合去重和最多 5 条。
2. 组件测试：首条与新增工作项均展示最近记录。
3. 交互测试：点击不同标签后，仅当前工作项三项字段发生变化。
4. 回归测试：工作归属切换、项目下拉选择、工作性质选择及日报提交不受影响。
5. 兼容测试：历史项目不在当前可选列表时仍能显示名称。
