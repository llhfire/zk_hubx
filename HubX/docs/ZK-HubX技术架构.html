1b. Cloudflare 托管技术栈（β 版）

层级Cloudflare 服务技术栈地址 / 标识说明
前端托管 Cloudflare Pages React 18 + Vite 7.3 + React Router 7.18 + Arco Design + Tailwind v4 beta.zkhubx.com（自定义域）
zkhubx-web.pages.dev（默认域）		 静态 SPA，构建产物直接部署。α 前端共用同一 Pages 项目（alpha.zkhubx.com）。VITE_API_BASE_URL 构建时内联，指向 Workers。
后端 API Cloudflare Workers Hono（轻量 Web 框架）+ TypeScript，esbuild 扖包 zkhubx-api.llhfire.workers.dev 无服务器边缘运行时。入口 apps/api/src/index.ts，纯函数从 packages/ui/src/services/*Mutations.ts 单源导入（esbuild resolve alias）。文档式 REST API，乐观锁 + 服务端时钟。
数据库 Cloudflare D1 SQLite（serverless 关系型） zkhubx-db（id ac02e216-…53339） 文档式存储（ADR-0094）：一域一表，data 列存整段 JSON，id + version 做乐观锁。无外键、无列拆分。β 期不做关系建模。迁移用 wrangler d1 execute --file。
部署工具 wrangler CLI Wrangler 4.127（Node.js CLI） — Workers：wrangler deploy。Pages：wrangler pages deploy。D1 迁移：wrangler d1 execute zkhubx-db --file=schema.sql。本地开发：wrangler dev → :8787（本地 D1 需手动初始化）。
域名与 DNS Cloudflare DNS — zkhubx.com 两个自定义域：alpha.zkhubx.com（α 前端）、beta.zkhubx.com（β 前端）。Workers 暂用默认 *.workers.dev，未绑自定义域。HTTPS 由 Cloudflare 自动签发。

零运维：全栈跑在 Cloudflare 边缘网络，无独立服务器、无容器、无 Nginx。免费额度足够内部使用（Workers 10 万请求/天、D1 500 万行读/天、Pages 无限请求）。 部署流程：本地 git push → Cloudflare Pages 自动构建部署前端；Workers 需手动 wrangler deploy；D1 迁移需手动执行 SQL。 α / β 区别：α 前端不注入 service，纯 mock；β 前端注入 http service 调 Workers API。两者共用同一份 packages/ui 代码。

3. 一次写入怎么走

1 页面动作向导保存、跟进、登记实收
2 Context调用 service.put / create
3 http servicefetch + 头 X-Actor + body.version
4 Workers PUT比 version，不匹配 409
5 D1INSERT OR REPLACE 整段 JSON，version+1
6 写时联动仅合同：created / approved / voided → 项目/商机

没有登录会话、没有接口鉴权、没有操作日志表。actor 信任请求头。 β 签约桥不再执行 α 的前端联动，但合同变化后会调用项目 refresh()，使 Workers 创建的项目在同一会话可见。

4. 平台基座（ADR-0094）

已落地的可信度修补 工作区已编码

  • 文档式 D1：一域一张表，data 存整对象。β 期不做关系建模。
  • 乐观锁：PUT 带 version，冲突 409 + 当前 version。
  • 服务端时钟：updatedAt 由 Workers 生成，回写前端。
  • X-Actor：过渡身份；登录落地后换会话。

刻意没做

  • JWT / 登录页 / 路由守卫 / 接口级权限
  • 按状态/客户的列查询、引用完整性
  • WebSocket、合并冲突 UI
  • D1 migrations_dir 自动迁；现流程是 d1 execute --file
  • 迁移文件已按 0001 至 0005 排序；生产执行前仍需先核对远端迁移状态
