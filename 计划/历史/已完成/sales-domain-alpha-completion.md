# 销售域 α 完成计划

> 日期：2026-08-31  
> 状态：已完成（2026-08-31）  
> 范围：仅 `HubX/apps/prototype` α 版及其共享 UI 包；不进入 β、D1、Workers 或真实外部供应商接入

## 1. 完成口径

销售域 α 完成，不等于新增一套销售系统，而是补齐现有“线索 → 客户 → 报价 → 合同 → 回款”链路中仍为静态、分叉或伪交互的部分。完成后：

1. 客户、联系人、开票资料和客户业务链有统一可变的 α 事实源；列表、详情、线索转客户、报价和合同读取同一份数据。
2. 合同模板可以起草、发布不可变版本、停用和按主体/产品分类选择；合同保留模板版本及正文快照。
3. 销售明确承诺进入统一待办，生日、合同到期与维护期到期进入统一提醒；不另建“销售助手”一级页面。
4. 报价支持重新报价差异、补充报价影响、责任人转交、限时代理、电子签署演示和合规档案；每个动作有可回看的记录。
5. 线索治理改为真实异常工作台，删除随机评分和自动处罚假规则。
6. 历史合同版本可查看、比较并基于选中版本创建新版本，不出现“按钮可点但仍复制最新版”的伪交互。

## 2. 锁定的业务决定

### 2.1 客户主档

- 企业和个人均是一条独立客户；不同签约公司不得合并成集团客户。
- 企业按统一社会信用代码强判重，个人按手机号强判重；名称相似只预警。
- 一个客户可有多个联系人且仅一位主联系人；被业务记录引用后只能停用。
- 一位客户只有一套当前开票资料，修改保留变更记录，只影响未来业务单。
- 客户状态由合同、项目、回款和维护事实派生；停用是独立档案开关。
- 客户业务链按线索分组，展示报价、主/补充合同、项目和回款；无线索合同归“直接签约”。
- 重复客户合并保留旧 ID、来源和历史引用，不覆盖式删除。

### 2.2 合同模板与历史

- 模板字段为名称、签约主体、产品分类、富文本正文和白名单变量。
- 草稿可编辑；发布后不可变；停用不影响历史合同。
- 每个主体与产品分类最多一个默认模板。
- 合同保存模板版本与渲染正文快照。
- 历史合同版本只读；从指定版本继续编辑时创建新版本并记录基线版本。

### 2.3 跟进与提醒

- 明确的下次跟进承诺写入现有 Todo；调整时间或负责人更新同一条待办。
- 完成一次跟进即完成当期待办；新约定产生下一条待办。
- 联系人生日、合同到期和免费维护期到期写入 Reminder，可人工转为 Todo。
- α 默认提前量：生日 7 天/当天；合同 30/7/1 天；维护期 30/7 天，并由系统配置统一维护。
- 不实现“阶段推进智能建议”或基于历史成交率的预测。

### 2.4 报价增强

- `previousQuoteId` 只表示重新报价的前一版本；补充报价改用 `parentQuoteId` 指向主报价。
- 重新报价差异覆盖功能清单、人天、增值项、总价、工期、付款、质保和客户文件。
- 补充报价显示相对当前有效合同的变更影响，不混入重新报价版本链。
- 转交永久更换销售或技术评估人；代理只在有效期内代办销售/评估，不替代审批、会签、盖章或合同审批。
- 电子签署仅为明确标识的 α 演示状态机，不生成个人签名，不声称法律效力；允许上传真实线下签署证据。
- 合规档案是现有证据的只读投影，支持 HTML 摘要和 JSON 元数据导出；源文件逐个下载，不伪造压缩包。

### 2.5 线索治理

- 工作台分为线索异常、重复线索、退回质检、规则概览。
- 所有处置都由管理员显式确认并写入事件流水。
- 规则概览读取系统配置和既有派发规则，不维护页面私有规则。
- α 不做合规评分、随机指标、自动回收、自动处罚或自动进垃圾池。

## 3. 实施阶段

### A. 销售共享数据底座

新增客户领域类型、纯函数、种子数据、Context 与 localStorage 适配，建立客户、联系人、开票资料、变更记录和合并映射。先补判重、主联系人唯一、状态派生、快照与业务链聚合的单元测试，再接页面。

主要目标：

- `packages/ui/src/app/pages/customers/`：领域类型、规则、Context、mock 与测试。
- 应用 Provider：让客户列表、详情、线索、报价、合同读取同一上下文。
- 保留 `customerId`，报价与合同另存 customer/contact/invoice snapshot。

### B. 客户列表与 360 详情

沿用现有列表页和长流程详情框架，不改全站布局：

- 列表完成搜索、筛选、新建、编辑、停用/恢复、强判重、相似名称提醒和合并入口。
- 详情完成基础资料、联系人、当前开票资料及变更记录、按线索分组的客户业务链、活动聚合。
- 所有按钮产生真实 Context/localStorage 状态变化；合同、项目、报价和线索均可下钻。
- 全局搜索改读客户共享事实源，避免继续引用静态数组。

### C. 合同模板与合同版本

- 新增合同模板管理页与路由，复用系统列表、编辑抽屉和富文本能力。
- 完成草稿、发布、复制新版本、停用、默认模板和适用范围校验。
- 合同 Wizard/Editor 根据主体与产品分类带入模板，并保存模板版本与正文快照。
- 修复 VersionTimeline：选中历史版本后创建的新版本必须以该版本为基线，并提供相邻/指定版本差异。

### D. 跟进待办与销售提醒

- 在 LeadFollowUp 保存链路中以稳定业务键创建、更新或完成 Todo。
- 客户详情展示相关跟进待办和机会提醒，但写入仍归 TodoContext/ReminderContext。
- 新增客户生日、合同到期和维护期提醒适配器；支持稍后提醒与转待办。
- SystemConfig 增加统一提前量配置并复用现有持久化/备份恢复。

### E. 报价版本与责任协作

- 拆分 `previousQuoteId` / `parentQuoteId`，迁移 α 种子和创建逻辑。
- 新增重新报价差异与补充报价影响的纯函数、测试和只读视图。
- 新增转交/代理记录及校验，接入报价工作台的责任区与时间线；待办随转交人更新，历史操作人不变。

### F. 签署演示与合规档案

- 新增共享签署演示模型，报价和合同在内部用印后可创建演示包并推进状态。
- 页面始终展示“α 签署演示，不具有电子签名法律效力”。
- 完成线下签署证据上传、预览和下载，不生成伪签名。
- 建立合规档案投影与完整/缺失/异常判断，支持 HTML/JSON 导出和源文件逐项下载。

### G. 线索治理收口

- 用实际 Lead Context、事件和配置重写 `LeadGovernance.tsx`。
- 异常：派发/首联超时、跟进承诺逾期等只读识别与显式催办。
- 重复：强标识命中与名称相似分开，合并保留主记录及别名历史。
- 退回质检：遵守不同销售去重三人三轮，管理员最终确认才进垃圾池。
- 规则概览：只读显示系统配置并跳转到唯一配置入口。

### H. 对齐、验证与交付

- 更新功能看板中客户管理、线索治理、合同模板、跟进助手和报价增强的状态与说明。
- 新增销售域 α 收口日志，记录数据源、演示路径、限制和验证结果。
- 运行相关单测后执行 `npm test`、`npm run build`。
- 启动 prototype，实页验收客户列表/详情、线索详情/治理、报价中心/工作台、合同模板/编辑/详情、提醒与待办。
- 对本轮 UI 文件运行 impeccable 检测，修复明显模板化、伪交互、可访问性和信息密度问题。

## 4. 明确不做

- β 版 API、D1/Workers 持久化、刷新幂等和生产数据迁移。
- 真实电子签名、CA、短信、企微、邮件或供应商回调。
- 生产级登录、RBAC、字段权限与审计后端。
- AI 阶段推进建议、成交预测、自动回收、自动处罚。
- Word 合同模板解析、脚本变量、自定义公式、批量压缩包下载。
- 新建独立“销售助手”一级菜单或第二套待办/提醒中心。

## 5. 验收场景

1. 线索绑定已有客户或转为新客户时执行强判重，并生成首位主联系人；重复档案不能静默创建。
2. 修改客户联系人或开票资料后，新合同读取新值，历史合同仍展示旧快照。
3. 客户详情按业务机会展示主报价、重新报价、补充报价、主/补充合同、项目和回款，不把不同机会混成一条链。
4. 已发布模板不可原地编辑；新版本发布后，旧合同正文不变。
5. 从指定合同历史版本创建新版本时，内容确实来自该历史版本。
6. 调整同一次下次跟进时间只更新一条 Todo；完成后再约时间才新增下一条。
7. 相同生日/到期对象在同一触发日不产生重复 Reminder，停用对象不触发。
8. 重新报价 Diff 与补充报价影响视图不串链；旧 α 数据迁移后关联完整。
9. 报价转交更新当前责任人与未完成待办，历史记录不改；代理过期、重叠或越权时阻止操作。
10. 电子签署演示全程有非法律效力提示，上传的线下证据可真实预览/下载。
11. 合规档案只投影已有证据；缺失项明确显示，导出文件内容真实可打开。
12. 线索治理不再出现随机分数或自动处罚；管理员处置进入同一事件流水。
