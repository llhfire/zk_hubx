# 设计系统组件清单

> 配套：`设计系统规范.md`（结构规则）、`docs/design/页面标记与全站检查标准.md`（行为规则 M-001~M-049）
> 目标：每个页面都按本清单的组件组织；清单里没有的 UI 语汇，先补组件再改页面。

## 三、迁移顺序

1. **基础**：建 `design-system/` 骨架、`tokens.css`、迁入 ✅ 组件、改写全部 import。
2. **原子与展示层**：先建 `MoneyText` / `StatusTag` / `EmptyState` / `DataTable` / `MetricGrid` / `DescriptionsCard`——这六个覆盖 80% 的重复。
3. **按业务域迁移**，每域一提交，迁移前后跑 `typecheck` + `test` + 浏览器截图对比：
   线索 → 客户 → 合同 → 报价 → 交付 → 财务 → 差旅 → 支持 → 资源 → 其它。
4. **收尾**：删除 `components/ui/`，接 `npm run check:ds` 门禁。

## 四、验收标准

- [ ] 全仓 0 处引用 `app/components/ui`；
- [ ] 页面里没有视觉类内联样式（`color`/`background`/`fontSize`/`borderRadius`/`boxShadow`）；
- [ ] 同一语义只有一个组件实现（状态标签、指标卡、空态、表格、金额）；
- [ ] `npm run typecheck` / `npm test` / `npm run build` 全绿；
- [ ] 45 条路由浏览器冒烟 0 pageerror，且关键页面截图与迁移前一致。
