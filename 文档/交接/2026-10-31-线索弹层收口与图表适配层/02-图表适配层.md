# 02 · 图表适配层

新建目录：`packages/ui/src/design-system/charts/`（`tokens.ts` 72 行、`index.tsx` 166 行）

## 为什么要一层

上一场遗留的第 2 项是「6 处 Recharts 直引 + 7 处硬编码图表色」。它们不是同一个问题：

- **6 处直引**：`recharts` 从页面 import，等于绕过设计系统出口，严格门禁记为 `directUiImport`。
- **7 处硬编码**：`fill="#8884d8"`、`stroke="#165dff"`、`stroke="#00b42a"`、`fill="#fff"`；
  另外还有一批没被门禁抓到的存量：`fill="var(--primary)"`、`var(--success-500)`（theme.css 的 Tailwind 系）
  与 `rgb(var(--success-6))`（Arco 系）在同一批图表里混着用。
- 每个页面各写一遍刻度字号、网格虚线、Tooltip 卡片；`tick={{ fontSize: 'var(--text-xs)' }}`
  这种写法本身也被 `visualInlineStyle` 计一次。

所以这一层同时解决三件事：**出口单一、色板单一、默认值单一**。

## 出口只有一个：`Chart`

`design-system/index.ts` 只加两行：

```ts
export { Chart } from './charts';
export type { ChartTone, PieLabelRenderProps } from './charts';
```

类型导出不计入「每个导出必须有实样」，所以 ui-library 只需要为 `Chart` 补一处实样。`Chart` 内部：

| 分组 | 成员 |
|---|---|
| 画布与坐标系 | `Canvas`（`ResponsiveContainer`，宽度恒 100%，高度默认 280 或 `"100%"`）、`Grid`、`XAxis`、`YAxis`、`Tooltip`、`Legend` |
| 图形 | `BarChart` `Bar` `LineChart` `Line` `PieChart` `Pie` `Cell` `RadarChart` `Radar` `PolarGrid` `PolarAngleAxis` `PolarRadiusAxis` |
| 色板 | `SERIES`、`series(i)`、`tone`、`SURFACE`、`ON_SERIES` |

`Chart.series(i)` 用**固定类别顺序的索引**取色：索引不能来自「当前数据里第几条」，
否则某个类别缺数据时，后面所有类别会集体串色。

## 两套色板，分工写死在注释里

| 色板 | 来源 | 用在 | 规则 |
|---|---|---|---|
| `Chart.SERIES` / `Chart.series(i)` | theme.css 的 `--chart-1..5`（HSL，深色主题有对应档） | 并列类别：饼图扇区、成本构成、多平台雷达、渠道来源 | 位置即语义；索引来自固定顺序 |
| `Chart.tone.*` | 复用 `STATUS_TONE_VARS[tone].fg`（Arco 的 `--ds-tone-*`） | 状态/好坏：应收 vs 实收 vs 成本、现金流确定性分层 | 与旁边 StatusTag 完全同源，不另开状态色 |

`Chart.tone` 内部映射：`primary` = `rgb(var(--primary-6))`，其余 success/warning/danger/info/neutral/purple/cyan/gold
直接取 `STATUS_TONE_VARS`。

## 默认值清单（只写一次）

| 位置 | 默认值 |
|---|---|
| `Grid` | `strokeDasharray="3 3"` + `stroke="var(--color-border-2)"` |
| `XAxis` / `YAxis` | `stroke="var(--color-text-3)"`、`tick={ fontSize: 'var(--text-xs)', fill: 'var(--color-text-3)' }`（调用点传 `tick` 则整体覆盖） |
| `Tooltip` | 卡片 `background: --color-bg-2`、`border: 1px solid --color-border-2`、`--radius-sm`、`--ds-shadow-subtle`、`--text-xs` |
| `Legend` | `wrapperStyle.fontSize = --text-xs`、`iconSize = 8` |
| `Pie` | `stroke="var(--color-bg-2)"`（扇区缝隙用底色，不是白）、`fill = --chart-1` |
| `Radar` | `fillOpacity = 0.15` |
| `Line` | `type="monotone"`；**不**改 `dot` / `strokeWidth`（各页视觉不同，强加会改外观） |

`SURFACE` / `ON_SERIES` 作为 `Chart.SURFACE` / `Chart.ON_SERIES` 暴露，给自绘 SVG 用
（饼图内百分比文字、扇区描边）。

## 踩到的坑

1. **`tone.info` 和 `tone.primary` 是同一个蓝**。Arco 里 `--ds-tone-info-fg` 就是
   `rgb(var(--primary-6))`。第一版把「商务成本」映射成 `tone.info`，结果饼图上「人工成本」和
   「商务成本」同色（浏览器截图才看出来）。改成 `tone.cyan`，并在 `tokens.ts` 的 `CHART_TONE`
   注释里写明这条，避免下一个人再踩。
2. **`var()` 写进 SVG 属性是可行的**（此前 `PersonalWorkbench` 已有先例，本场在浏览器确认
   `stroke="var(--primary)"` 计算值正常）。所以色板可以直接输出 `var(--chart-3)` 字符串，
   不需要为了取真实值去 `getComputedStyle`。
3. **recharts 在 SSR 不渲染图形**：`renderToStaticMarkup(<BarChart width height>)` 只吐一个空
   `.recharts-wrapper`，拿默认值做断言会全部落空。改为**直接调用包装组件**读它产出的元素 props
   （`propsOf(Chart.XAxis({ dataKey: 'month' })).tick`），这样才能验「默认值合并 / 调用点覆盖」。
   这条写进了测试注释，别再用 SSR 测图形。
