# 派发制取代未派发线索的公海自领；退回公海的线索仍可自领

获客域线索派发工作台（`文档/PRD/PRD-线索派发管理.md`，2026-08-24 grill 收束）引入推广中台定向派发：录入 -> 待派发 -> 按业务线/等级指派销售。现有公海模型是销售自领（领取 -> assigned），两者对「未派发线索」的出口语义冲突。

决定：**待派发（录入后未派发）的线索锁定领取，派发是唯一出口**。理由：

1. 公司是分配制不是抢池制——派发交互本身就是「选部门 -> 选销售 -> 通知」的人工定向动作；
2. 30min 派发 SLA 的追责链要求「谁欠着没派」可指认；销售随手自领会把 SLA 洗掉；
3. 定向指派要按业务线、等级路由，自领无法表达这个意图。

但保留两个自领通道，避免把销售侧公海模型整个推翻：

- **派发到公海**：派发动作者可以不指名，把线索投进公海转可领取——推广主动释放，不是销售放弃，不算退回质检的一次放弃；销售领取时才起算首联 SLA。
- **退回公海的线索**：已派发过、被销售退回的线索回公海后照旧可自领（现有「退回公海」动作不变，计数规则见 CONTEXT §退回质检：按不同销售去重，满 3 人转管理员确认）。

实现约束：这是在公海池上加「待派发」标记 + 领取按钮禁用，不是第五个池；销售侧五池页签结构不动，只加时效监控字段。若未来改成完全分配制（废自领），本 ADR 的两个保留通道是切入点。
