## Platform

web

## Users

HubX 面向软件外包与自运营投放团队的内部业务人员。核心用户包括推广/录入人员、销售、产品经理、技术评估人、合同与财务管理人员以及业务管理者。

## Product Purpose

HubX 用一条可追溯的业务链管理从广告投放、线索、客户、报价、合同到项目交付、回款和利润的内部协作。成功意味着同一业务事实只有一个写入方，其他视角以引用或投影方式使用，并能穿透回原始记录。

## Positioning

HubX 不把线索、合同和项目视为互不相关的清单，而是将它们作为同一笔业务的销售、法务与交付视角，以报价、合同、回款和交付状态机保持跨域一致。

## Operating Context

- 业务主线为“广告投放 → 线索 → 客户 → 报价 → 合同 → 项目 → 交付 → 利润”。
- 内部经常处理 Excel 功能清单、客户报价 PDF、Word/扫描合同、付款凭证、项目交付物和会议纪要。
- 详情页需要支持长周期、多人协作和历史回看；列表页需要支持快速筛选、异常识别和对象下钻。

## Capabilities and Constraints

- 现有技术栈为 React + TypeScript + Vite，基础组件使用 Arco Design。
- α 版是可完整演示和验证的原型，允许使用 mock、Context、浏览器会话态或 localStorage，但不得伪造上传、下载、审批或状态流转成功。
- 本轮销售域收口只覆盖 α 版；不实施 D1/Workers 持久化、真实电子签章供应商、企微/短信外部推送或生产级身份权限。
- 成熟页面的现有布局和 `HubX/DESIGN.md` 是界面一致性依据；新能力优先复用已有列表、长流程详情和表单框架。

- 未提供真实客户证言、外部宣传指标或真实签章供应商资产，后续不得自行伪造。

## Product Principles

- 同一业务事实只有一个写入方。
- 状态、金额、责任人与历史记录必须可解释、可回看。
- 页面存在不等于流程完成，每个主动作都要产生可见的状态变化或可下钻的记录。
- α 可以是模拟数据，但不能是模拟交互。
- 先继承现有领域词表和页面模式，只在明确冲突时引入新概念。
