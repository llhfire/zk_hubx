# 线索详情页（LeadDetail360）信息架构与交互优化方案

> **文档版本**：v1.0  
> **核心目标**：盘活顶部步进条黄金视域、重构左右分栏职责模型、解决右侧模块“空间过小而功能过重”的倒挂问题。

---

## 一、 现状诊断与核心痛点

当前 [LeadDetail360.tsx](file:///Users/pc/Documents/AI%20work/01-PROJECTS/ZK%20HubX/ZK_HubX/ZK_HubX/HubX/packages/ui/src/app/pages/LeadDetail360.tsx) 在功能完整度上已经具备了销售全生命周期（线索 -> 报价 -> 合同 -> 回款 -> 项目交付）的能力，但在**空间布局分配**与**用户心智操作流**上存在显著的结构性失衡：

```
+-----------------------------------------------------------------------------------+
| 顶部：面包屑 + ProcessOverview (线索标题/标签/操作按钮)                            |
| 步进条：[接入录入 -> 初步建联 -> 需求调研 -> 主合同签署 -> 项目交付中 -> 终验结项]   | <- 痛点1: 纯静态只读，占满通栏无生产力
| 6项微指标：负责人 / 对接人 / 总标的 / 客资成本 / 跟进次数 / 下次跟进                 |
+--------------------------------------------------+--------------------------------+
| 左侧主工作区 (70% 宽幅)                           | 右侧边栏 (30% 窄栏，约340px)    |
| 1. 关键信息档案卡 (联系人/电话/微信/主体/需求)     | 1. 售前群分析 (独立卡片)         |
| 2. 附件面板                                      | 2. 挤压了整整 7 个厚重 Tab!     |
| 3. Tab (基础信息 / 合同信息 / 回款与发票)         |    - 跟进 (Timeline + 弹窗写跟进) | <- 痛点2: 挤压严重
| 4. 项目交付执行独立板块 (里程碑/任务/缺陷)        |    - 报价 (QuoteCard 卡片堆叠)   | <- 痛点2: 业务实体过重
|                                                  |    - 合同记录 (ProcessRecordCard)|
|                                                  |    - 演示环境 (链接管理)        |
|                                                  |    - 方案资料 (附件管理)        |
|                                                  |    - 出差申请 (差旅列表)        | <- 痛点2: 不适合窄栏
|                                                  |    - 费用报销 (报销明细)        | <- 痛点2: 不适合窄栏
+--------------------------------------------------+--------------------------------+
```

### 痛点 1：步进条区域（Steps）空占黄金视域，缺乏生产力
1. **静态指示器，无法交互**：当前的 6 步生命周期只是根据 `lead.status` 计算出的一个只读索引，点击任何步骤均无响应；
2. **缺乏阶段上下文（Context Blindness）**：销售人员无法一眼获知当前阶段该干什么（前置准入、核心任务、必备附件）、在该阶段已停留了几天、是否已经超出公司规定的 SLA 时效；
3. **阶段流转断层**：销售无法在步进条上直接触发「推进到下一阶段」或「完成当前阶段目标」，必须去点「编辑线索」或在写跟进弹窗里修改下拉框，动线过长。

### 痛点 2：右侧区域（30%）空间极小，但功能极度繁重
1. **7 个厚重 Tab 严重拥挤**：
   - 包含跟进、报价、合同、演示、资料、出差、报销；
   - 报价、出差、报销等均是包含金额、审批流、明细清单的**重量级业务实体**，强塞在 340px 左右的侧边栏内，造成字段强行折行、卡片挤压变形；
2. **高频跟进体验被压缩**：
   - 最频繁的「跟进记录时间线」在窄栏里阅读体验差，长文本交流纪要被纵向拉长；
   - 记录跟进需要唤起遮罩弹窗（Modal），无法做到边看客户全貌边就地记录；
3. **左右职责主次倒挂**：
   - 左侧 70% 宽阔区域大部分时间处于静态查阅状态（基本信息 Descriptions）；
   - 右侧 30% 狭窄区域却承担了日常销售工作 80% 的业务录入与切换（报价、出差、报销、写跟进）。

## 二、 架构重构方案：两大核心改造

### 改造一：将步进条升级为「阶段驾驶舱（Sales Path & Guidance）」

借鉴现代化 B2B CRM（如 Salesforce Lightning Sales Path 与飞书销售管线）的标杆模式，把步进条从**被动指示器**变为**主动推进器**：

#### 1. 阶段指引面板（Stage Guidance & Tasks）
- 步进条上的每个步骤节点支持点击查看该阶段的指引，并与当前激活阶段智能联动：
  - **接入录入**：核心目标（完善客户主体与联系方式），SLA 倒计时；
  - **初步建联**：核心目标（24h 内电话/微信首联，摸清核心诉求），快捷动作「立即记录初联」；
  - **需求调研**：核心目标（输出技术需求清单或原型），快捷动作「上传/更新方案」；
  - **方案报价**：核心目标（完成成本测算并提交报价审批），快捷动作「一键发起报价」；
  - **合同签署**：核心目标（合同盖章归档与首期回款），快捷动作「发起主合同」；
  - **项目交付 & 结项**：联动项目执行健康度与交付验收。

#### 2. 阶段时效与健康度徽标（Stage SLA Badge）
- 在当前进行中的步骤节点下方展示停留时间（如 `进行中 · 已停留 2 天`）；
- 若停留超时（如初联 >24h，或调研 >7天），自动呈现暖橙或绯红告警徽标，驱动销售快速响应。

#### 3. 就地「推进至下一阶段」快捷操作（Stage Progression Button）
- 在步进条右侧设立固定的推进控制器：
  - 例如当前在线索调研阶段，按钮高亮提示 `推进至「方案报价」>`；
  - 点击弹出阶段流转快捷确认（支持录入阶段流转要点与意向变更），一键完成推进，无需进入复杂的全量编辑表单。

---

### 改造二：重塑左右分栏职责 ——「左主业务实体，右纯互动动态流」

明确两栏的专属心智模型：
- **左侧 68%（全景实体工作台）**：负责“重型、宽幅、表格化、方案化”的核心业务实体；
- **右侧 32%（互动与活动流）**：负责“轻量、即时、时间序、沟通协同”的客户互动往来。

```
+---------------------------------------------------------------------------------------------------+
| 顶部：【阶段驾驶舱 Sales Path】                                                                    |
| [接入录入] -> [初步建联] -> [● 需求调研(停留3天)] -> [方案报价] -> [合同签署] -> [交付结项]   [推进阶段 >]|
| 阶段指引微条：本阶段核心任务：确认客户功能范围与预算；建议动作：【上传需求清单】【关联原型】       |
+-----------------------------------------------------------------+---------------------------------+
| 左侧主工作区 (68% 宽幅 - 全景业务实体)                           | 右侧工作区 (32% - 纯净互动流)   |
| 1. 客户核心档案与 360 概览 (电话/微信/主体/售前群/初始需求)      | 1. 售前群 AI 摘要与意向提取     |
| 2. 宽幅 Tab 矩阵 (业务大件在此舒展承载)：                       | 2. 【常驻快捷写跟进输入框】     |
|    - [客户档案]：企业工商/开票抬头、对接人名片、派发时效        |    (就地录入，免弹窗，即写即存) |
|    - [方案与报价]：报价版本卡片、工期/金额模型、作废对比        | 3. 【互动时间线 Activity Stream】|
|    - [合同与回款]：主合同、补充合同、款项期次、开票台账        |    - 全部 / 电话 / 微信 / 阶段  |
|    - [差旅与费用]：出差申请记录、差旅报销明细、借款核销        |    - 时间轴展示沟通细节与附件   |
|    - [交付看板]：交付里程碑、任务看板、缺陷跟踪                 |    - 下次跟进待办自动提醒       |
|    - [资料与环境]：方案附件库、演示环境管理、原型交互           |                                 |
+-----------------------------------------------------------------+---------------------------------+
```

#### 详细拆解：
1. **右侧栏瘦身方案**：
   - 移出报价、合同、出差、报销等 4 个沉重模块，不再有多层卡片嵌套；
   - **常驻快捷写跟进（Quick Logger）**：销售边在左侧看报价/需求，边在右侧直接打字记录沟通要点、选择跟进方式（电话/微信/拜访）、选择下次跟进时间，点击「保存」立即插入时间线；
   - **呼吸感极佳的互动时间线**：长段纪要、录音转文字、售前群关键信息沉淀拥有足够的纵向和横向空间展示，告别折行挤压。

2. **左侧主区域扩容承接**：
   - **方案与报价**：享受 68% 的大屏宽幅，`QuoteCard` 可以清晰展开两级功能清单、工期估算、利润测算和多版本对比，不用再缩进弹窗或窄栏；
   - **合同与财务台账**：合同信息、回款进度条、期次核销和发票明细可以平铺为标准表格与状态条，符合财务与法务的严谨阅读习惯；
   - **差旅与费用**：出差申请与报销明细形成完整链路展示，与差旅模块体验统一。

## 三、 演进路线图与实施建议

为了稳妥推进、保证线上业务不受冲击，建议分两阶段实施：

### 阶段 1：右侧减重与左侧业务实体归位（收益最高、改动最清晰）
1. **调整右侧 Aside Tab**：
   - 将 `quotation`、`contract-records`、`travel`、`reimbursement`、`demo`、`documents` 迁移至左侧主区域的 Tab 中；
   - 右侧保留 `follow` 与 `售前聊天群分析`；
2. **升级右侧跟进区**：
   - 在右侧顶部加入常驻的简易跟进输入框（Quick Log），同时保留大弹窗入口满足复杂多附件需求；
3. **左侧主区域 Tab 结构对齐**：
   - 设立【档案概览】、【方案与报价】、【合同与财务】、【差旅与费用】、【交付执行】、【资料与环境】。

### 阶段 3：方案与报价精细化工作台与客户反馈博弈闭环（消灭横向过宽）
1. **解决方案卡片横向过宽、信息稀疏问题**：
   - 弃用长条形单行横跨 800+ px 的 `ProcessRecordCard` 占满通栏做法；

       * 方案头部与快捷操作（进入工作台、基于反馈生成 v+1 重新报价）；

       * 交付物范围穿透面板。
2. **客户商务反馈与博弈跟踪看板（Customer Feedback & Negotiation Tracker）**：
   - 覆盖 8 维商业诉求分类：价格偏高（超出预算）、工期偏长（交付紧迫）、范围调整（功能增删）、付款争议（条款/账期）、技术疑虑（架构/选型）、竞对冲击、基本认可、其他反馈；
   - **量化差距智能对比（Gap Analysis）**：自动对比当前方案总价 vs 客户期望预算，当前工期 vs 客户期望交付周期，实时计算超出金额（及百分比）与超出天数；
   - 沉淀客户原话与关切，记录销售内部应对策略与改版思路；
   - **闭环行动入口**：一键基于反馈创建下一版本报价（v1.0 -> v1.1），并支持联动写入线索跟进流（双向沉淀到右侧 30% 沟通时间线）。

## 四、 预期效果评估

1. **消除横向过宽与视觉空旷**：方案与报价由单条拉伸变为左右双栏精细化结构，比例匀称自然；
2. **信息阅读负荷降低 40%**：左右职责界限清晰，找业务数据（报价、合同、差旅）一律看左边宽屏，看跟进和聊天纪要一律看右边时间轴；
3. **商务谈判博弈全程可追溯**：方案改版不再盲目，为什么出 v1.1、为什么砍掉某些模块、客户当时嫌贵还是嫌慢，在反馈看板上一清二楚；
4. **跟进记录效率提升 50%**：告别每次必须点开 Modal 的繁琐流程，支持就地即写即存，且方案反馈一键同步沉淀至跟进记录；
5. **销售推进 SOP 标准化落地**：通过步进条的阶段指引与阶段时效预警，帮助主管和销售掌控线索周转周期，杜绝线索在阶段中沉睡超时；
6. **视觉层级高度统一**：主档案卡内聚关键属性、初始需求与线索附件，下接宽幅实体工作台，整体视觉节奏舒展紧凑。
