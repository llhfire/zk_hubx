# 销售域全功能与流程测试用例（α）

> 版本：v1.0 · 日期：2026-08-31  
> 被测范围：`apps/prototype` α 版及 `packages/ui` 共享 UI。销售域按功能看板覆盖：线索全流程、报价工作台、客户与报价基础、合同签约、跟进助手、报价与合规增强。  
> 本文是执行用例，不代表 β/API/D1 或真实外部供应商已接通。

## 1. 测试约定

### 1.1 环境与角色

| 项目 | 约定 |
|---|---|
| 环境 | `cd HubX && npm run dev`，访问 `http://localhost:5173`；每轮执行前清理或备份相关 `localStorage` |
| 角色 | 管理员、销售张三、销售部负责人黄奕、技术评估人罗总、决策层闵总、董助黄海；涉及回款/发票时使用财务视角 |
| 线索样本 | L-PUBLIC（公海）、L-MY（张三名下）、L-HIGH（高科技）、L-TRASH（垃圾）、L-CLOSED（已签单） |
| 客户样本 | C-ENT（企业，有统一社会信用代码）、C-IND（个人，有手机号）、C-DUP（与 C-ENT 强判重）、C-SIM（名称相似） |
| 报价样本 | Q-DRAFT、Q-EVAL、Q-QUOTE、Q-AUDIT、Q-REJECTED、Q-STAMPED、Q-SENT、Q-CONFIRMED、Q-VOIDED |
| 合同样本 | CT-MAIN（主合同）、CT-SUP（补充合同）、CT-DRAFT、CT-APPROVED、CT-VOIDED |
| 缺陷等级 | P0：主链路阻断/数据错账；P1：重要功能错误或跨域不一致；P2：一般交互、提示、样式或兼容性问题 |

### 1.2 通用验收规则

1. 页面首次加载、切换路由、刷新后不出现 React/Vite 运行时错误；异步操作有明确成功或失败反馈。
2. 新建、编辑、删除、状态流转后，列表、详情、关联 Tab、待办/提醒和时间线读取同一份最新数据；刷新后 α 数据仍保持（localStorage 语义）。
3. 只读角色不能通过隐藏按钮、直接输入 URL 或浏览器回退绕过前置条件；未到达的报价阶段显示锁定而不是伪可编辑。
4. 所有金额、百分比、人天、期次合计按同一精度计算；跨视角展示不得重复计入补充报价、回款或发票。
5. 每个需要留痕的动作均写入对应时间线/操作记录，操作人、时间、原因/意见不丢失。

## 2. P0 端到端冒烟用例

| ID | 场景与前置 | 操作步骤 | 预期结果 |
|---|---|---|---|
| E2E-001 | L-PUBLIC 可领取 | 公海打开线索 → 认领 → 添加跟进并选“方案报价” → 保存 | 线索进入我的线索，状态/等级/跟进次数更新，时间线有认领与跟进记录 |
| E2E-002 | 有效线索、无客户档案 | 线索详情选择“转为客户” | 创建唯一客户并回写 `customerId`，联系人自动成为主联系人，线索标记已转客户 |
| E2E-003 | C-ENT 已存在 | 新建/转客户，输入相同统一社会信用代码（含空格/大小写差异） | 强判重阻止静默创建，展示已有客户；用户可取消或进入已有档案 |
| E2E-004 | Q-DRAFT | 报价中心 → 新建报价 → 功能清单 → 人天评估 → 报价配置 → 提交审批 | 状态依次为草稿→待评估→待报价→待审核，审批节点读取提交时快照 |
| E2E-005 | Q-AUDIT | 黄奕、罗总、闵总依次会签通过 → 黄海盖章 → 销售发送客户 → 客户确认 | 状态为待盖章→已盖章→已发出→已确认；可见生成主合同入口 |
| E2E-006 | Q-CONFIRMED | 点击“生成主合同” → 校对预填 → 保存并提交 | 合同金额、付款期次、工期、质保、发票、主体正确带入；报价回写 `contractId` |
| E2E-007 | CT-APPROVED | 合同详情新增实收，选择两期并分配金额；再新增有效发票 | 合同、线索详情和项目视角的实收/待收/开票状态同步，金额只计一次 |
| E2E-008 | CT-MAIN 已批准 | 合同详情发起补充报价 → 完成报价、审批、确认 → 生成补充合同 | 补充报价用 `parentQuoteId`，补充合同指向主合同；主报价版本链不被污染 |
| E2E-009 | Q-SENT 到期 | 将系统日期置于有效截止日或提前量触发日 | 报价仍为已发出但显示过期标记；合同/维护期提醒按配置出现，不重复生成 |
| E2E-010 | 线索已终止 | 尝试在报价工作台继续前进；再执行撤回/退回 | 前进动作被冻结，回退动作仍可执行；提示清楚且不产生非法状态 |

## 3. 线索全流程

| ID | 前置 | 操作 | 预期 |

| L-001 | 有五类样本 | 依次打开公海、我的、全部、已成交、垃圾 | 每个池只展示对应 `clueType`/成交条件；Tab 计数与实际行数一致 |
| L-002 | 多状态线索 | 使用状态、意向等级 S/A/B/C、来源、负责人组合筛选 | 条件按 AND 组合生效；清空后恢复全量；分页/总数正确 |

### 3.3 领取、分配、转移、公海与垃圾

| ID | 前置 | 操作 | 预期 |
|---|---|---|---|
| L-014 | L-PUBLIC | 销售张三点击认领 | `clueType` 变为 assigned、负责人为张三；重复点击不重复生成事件 |
| L-015 | L-PUBLIC，多选 | 管理员批量分配给销售，填写原因 | 所有选中线索成功分配，未选中不变；每条记录保留原因与操作人 |
| L-016 | 已分配线索 | 负责人转移给另一销售 | 新负责人立即生效；历史跟进/创建人不被改写；相关待办转移到新负责人 |
| L-017 | L-MY | 退回公海并填写原因 | 进入公海、保留退回次数和原因；原负责人不再出现在“我的线索” |
| L-018 | 退回次数为 2 | 第 3 次退回公海 | 线索自动进入垃圾池；垃圾原因/退回链路完整，不能仍停在公海 |
| L-019 | 任意有效线索 | 标记垃圾，未填写原因 | 阻止操作并提示必填；填写原因后进入垃圾池并写事件 |
| L-020 | L-TRASH | 管理员恢复 | 恢复到规则指定池/状态，垃圾原因和历史保留；非管理员不能恢复 |
| L-021 | L-MY | 软删除 | 列表隐藏、详情不可从正常入口进入；操作日志保留；相关历史报价/合同引用不被物理删除 |
| L-022 | L-CLOSED | 已成交池打开详情 | 只读展示成交链路；不出现可把已成交线索回退为普通状态的伪按钮 |

## 4. 客户与报价基础

| C-002 | 有新建权限 | 新建企业客户，填写统一社会信用代码和主联系人 | 保存成功；企业强判重键为统一社会信用代码；主联系人唯一 |

| C-005 | 同企业不同主体 | 用不同签约公司新建同名客户 | 保持两条独立客户，不按名称合并成集团客户 |

| C-007 | 多联系人 | 新增第二联系人，切换主联系人 | 任一时刻仅一位 active 主联系人；停用联系人自动取消主联系人标记 |
| C-008 | 联系人已被业务引用 | 尝试删除/停用 | 只能停用，禁止破坏式删除；历史报价/合同快照仍可查看 |
| C-009 | 客户有联系人 | 编辑联系人电话、职务、生日、负责人、启停 | 客户详情和提醒适配器读取最新值；非当前联系人不生成生日提醒 |
| C-010 | 有开票资料 | 新建/修改抬头、税号、银行、地址、电话 | 当前资料覆盖成功，变更历史追加一条且记录时间/操作人 |
| C-011 | 已产生报价/合同 | 修改开票资料 | 新建业务读取新资料；历史业务的 invoice/customer snapshot 保持旧值 |
| C-012 | 有合同、项目、回款 | 查看客户业务链 | 按线索机会分组展示报价、重新报价、补充报价、主/补充合同、项目、回款；无关联线索归“直接签约” |
| C-013 | 客户存在主合同/项目/未收款/维护期 | 查看客户状态 | 状态由事实派生为待合作/合作中/已合作，不能由单独手工布尔值与事实冲突 |
| C-014 | 客户 active | 停用客户，再尝试新建业务/恢复 | 停用是档案开关；不能产生新的业务关联或机会提醒；恢复后按规则重新可用 |
| C-015 | 两个重复客户 | 管理员合并 target/source | target 保留，source 有 `mergedIntoId`、别名和历史映射；合同、报价、线索引用可追溯 |
| C-016 | 全局搜索 | 搜索客户、联系人、合同/报价关联客户 | 搜索使用 CustomerContext 事实源，不回退到静态数组；结果可进入客户详情 |

## 5. 报价工作台

### 5.1 报价中心、权限与阶段访问

| ID | 前置 | 操作 | 预期 |
|---|---|---|---|
| Q-001 | 多状态报价 | 打开 `/quotation`，按新状态、阶段、待我处理筛选 | 过滤正确；已发出且过期显示过期标记；不出现“已完成桶”伪分类 |
| Q-002 | 无报价权限角色 | 访问报价中心 | 不能看到新建入口；直接访问工作台仍按查看权限判定 |
| Q-003 | 创建人/销售/评估人/审批人/盖章人/admin | 分别打开同一报价 | 允许访问的角色可查看；无关人员不可查看；管理员可查看全部 |
| Q-004 | 不同状态 | 打开工作台并点击 1–4 阶段 | 已到达阶段可只读回看；未到达阶段锁定；当前阶段定位与待处理人一致 |
