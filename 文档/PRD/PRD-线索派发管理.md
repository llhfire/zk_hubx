## 1. 需求背景

公司自运营投放（小红书主推、百度、抖音等）产生线索后，由推广人员/录入员录入系统，再指派给销售跟进。现状缺三样东西：录入侧没有统一工作台；派发时效（30 分钟内）与销售首联时效（1-2 小时）无法监控追责；线索等级调整无审核、无效线索被单人武断丢弃。

原型 `ZKHubX-线索派后管理.html` 给出了推广域工作台的交互草案；本 PRD 是 grill 收束后的业务规则定稿。**不建第二套线索数据**：工作台是现有 Lead 实体在获客侧的视图与动作面（ADR-0096）。

## 2. 产品目标

1. 推广人员/录入员有统一录入与派发操作台，管理者有全量监控视角。
2. 派发 30min SLA、首联 2h SLA（1h 临期）全程可见、可催办、可追责。
3. 等级调整有审核约束（降级审核、升级免审带弱提示）。
4. 无效线索要历经 3 个不同销售退回 + 管理员确认才能进垃圾。
5. 录入周期成交率（Cohort）一屏可见。
6. 线索全生命周期事件只增不删、可穿透。

## 3. 范围与角色

| 角色 | 数据范围 | 主操作 |
| --- | --- | --- |
| 管理者 | 全量线索 | 录入、派发（到人/到公海）、催办、降级审核、垃圾确认、直改等级（留痕） |
| 推广人员 | 本人负责渠道 ∪ 本人录入（含非本人渠道） | 录入、催办、对未派发线索直改等级 |
| 录入员 | 仅本人当日录入 | 录入 |

- 三视角沿用 RoleSwitcher 切换模拟（α 无登录）；数据过滤为纯函数，β 接真权限复用。
- 「负责渠道」是用户档案上的多选字段，不硬编码。
- 承接销售不进本工作台：其时效视图在销售域列表与详情（§9）。

## 4. 录入表单

必填：业务线（软件外包/移民业务/代运营业务）、本公司主体（读系统公司主体配置）、推广渠道（读数据字典）、客户姓名、联系手机号、初始客户分级（S/A/B/C）。
选填：客户企业/单位名称、微信号（供 1-2h 内加微）、广告计划/投放笔记说明（channelPlan 自由文本）、需求与留资备注。
初始分配：存入待派发池（启动 30min 派发监控）或立即指派销售（部门 -> 销售人员，派发一次做完，不进待派发池）。
意向评分 0-100 **不落库**（原型字段删除）。无 D 级；无效线索由后续质检链路处理。

## 5. 派发与 SLA

- 待派发线索锁定销售领取，派发是唯一出口（ADR-0096）。
- 派发目标二选一：**指派销售**（dispatchedAt 锁定，启动首联 SLA）或**派发到公海**（线索转可领取，不算退回放弃；销售领取时启动首联 SLA）。
- 派发 SLA：录入确认时刻起算 30min（系统配置）；超期列表标红 + 管理者告警卡 + 催办，**不自动派发、不自动退回**。
- 首联 SLA：dispatchedAt（或公海领取时刻）起算 2h 超时标红、1h 临期提醒（数字系统配置）；首联 = 第一条跟进记录，任意方式含未接通，留痕停表。
- 已派发后退回公海的线索为普通公海线索，可自领，不重跑派发 SLA。

## 6. 催办

催办 = 给欠时效的人（派发超时催推广、首联超时催销售）发站内提醒 + 线索事件流水留痕（谁何时催了谁）。α 不接企微；β 经服务接缝接企微推送。按钮文案「催办」。

## 7. 等级调整与质检

- 未派发线索：推广初评等级，推广/管理员可直接改。
- 已派发线索：升级免审即时生效 + 「新晋升」弱提示；降级走审批中心业务类型「线索等级调整」，审核人按业务线在审批配置里定（人名不写死），审核期间维持旧等级；管理员直改只留痕。
- 退回质检（3人3轮）：退回计数按**不同销售去重**；凑满 3 个不同销售退回转「待管理员确认」，管理员确认才进垃圾池，不自动；派发到公海不算放弃。
- 「双向监督与质检」卡片 = 等级调整待审数 + 质检分桶（已 1 人放弃 / 已 2 人放弃），点入看名单与退回原因。

## 8. 统计与穿透

- 录入周期成交率卡片：按线索录入月归因，成交 = 线索进入「已签单」（与已成交池同口径）；只读纯函数派生，报表化归全链路 ROI。
- 穿透抽屉（列表行点开）：三节点进展（录入/跟进/成交）、流转属性（归因周期/主体/渠道/销售/录入人/时间）、只读事件时光轴；写动作一律不进抽屉，「进线索详情」跳 LeadDetail360。
- 线索事件流水（leadEvents）只增不删：录入、派发到人、派发到公海、催办、等级调整及审核结果、退回、管理员垃圾确认。

## 9. 销售域联动（本期同步做）

- 五池列表新增「时效」列：首联状态（超时红标+倒计时 / 临期 / 已首联 / 正常），与获客侧同一纯函数、同一口径。
- LeadDetail360：头部加派发时间与首联状态；动态/时光轴读取同一份 leadEvents（派发、催办、退回、等级调整事件在销售详情可见）。

## 10. 词表与配置迁移

- 渠道来源词表迁数据字典：5 值英文 key（xiaohongshu/baidu/douyin/wechat/website，grill 终版决策，取代早期「8 值平移+微信/官网」草案）；录入表单与筛选动态读字典；`LeadSource` 硬编码 union 退位，存量中文值就近平移。
- SLA 数字（30min / 2h / 1h）、质检人数（3）、审核人（按业务线）均入配置，不写死。
