# 在线报价配置页（Stage 3）商务与履约模块 UI/UX 深度优化方案

> 适用模块：报价工作台数据流转模式 · 在线报价配置页（Stage 3 / `Stage3WebAutomation.tsx`）  
> 责任范围：销售商务增项、交付履约服务、现场驻场技术服务、外部自费与代采项目、商务结算与付款计划（含自定义付款方案存储与跨报价单复用）  
> 目标：将基础表单式输入重塑为具备清晰财务透明度、高信息密度、智能预设赋能与方案持久沉淀能力的现代化 B2B CPQ（Configure, Price, Quote）商业配置引擎。

---

## 一、优化背景与现存痛点剖析

在线报价配置页是销售成单与内部审批前最核心的「商业精算台」。经过 Stage 3 的第一阶段重构，页面已具备 72:28 双栏结构与常驻商业决策驾驶舱。但在日常销售高频使用场景下，仍存在以下 5 大模块的交互与视觉瓶颈：

| 模块 | 当前实现现状 | 用户体验（UX）痛点 | 视觉层级（UI）痛点 |
|---|---|---|---|
| **1. 销售商务增项** | 紧凑 7 列行内输入，仅 4 个通用预设 | 缺乏增项类型划分（人力咨询 vs 固费服务包）；点击预设无去重或选中状态；空状态无指引 | 7 列字段易挤压折行；金额主次对比不强；无一键复制或批量清空 |
| **2. 交付履约服务** | 出差与驻场纵向堆叠，多层 Switch 与嵌套块 | 缺乏城市差旅标准基准（销售需手动算交通/住宿/补贴）；无单城市小计展示，只能看到总计 | 两个大块展开后页面垂直过长，需大量上下滚动 |
| **3. 现场驻场技术服务** | 纯天数/单价计算，字段扁平 | 缺乏驻场阶段/服务职责定义（机房割接/上线陪产/技术攻坚）；与销售增项界限易混淆 | 缺少独立卡片视觉辨识度与人天单价明细标签 |
| **4. 外部自费与代采项目** | 纯手工输入名称与金额，仅标明自费 | 缺少「客户直付直购」与「我方垫资代采」权责划分；无高频代采预设库（ECS、域名、SSL、短信等） | 空列表只留一个按钮，显得单薄冷清 |
| **5. 商务结算与付款计划** | 纯百分比数字列表，质保期为固定写死标签；预设方案写死 | 必须手动心算凑 100%，无一键平账/补齐尾款功能；质保年限不可调；**无法将精心调校的付款方案存储为模版供其他报价单引用** | 缺乏直观的阶段里程碑彩色进度条；发票与税率说明不够细致 |

## 二、5 大模块专项 UI/UX 深度重塑方案

### 模块 1：销售商务增项（商业价值提升与分类预设库）

#### 1. 业务逻辑升级
- **增项类型区隔（Type Segregation）**：
  - **按天计费型人力增项（Daily-based）**：如 PMO 专项管理、架构性能压测、安全等保整改配合。
  - **定额交付服务包（Fixed Package）**：如定制化专场培训、UI 原型与设计切图原件包、知识产权源码交付审计包、生产割接加急保驾。
- **高频增项分类快捷库**：
  - `[项目管理]` + PMO 专属项目管理 (¥1,000/天)
  - `[安全合规]` + 等保三级合规配合 (¥1,200/天)
  - `[技术护航]` + 生产上线割接保驾 (¥1,000/天)
  - `[交付赋能]` + 客户专场技术培训 (¥800/天)
  - `[资产交付]` + 源码交付与知识产权移交 (¥6,000/包)

#### 2. UI/UX 交互升级
- **卡片式条目与高密度对齐**：
  - 左侧：岗位/服务名称 + 类别徽标 + 事由说明（输入框带常用提示）；
  - 中间：量化调节器（人数微型步进器 × 天数微型步进器 × 日单价）；
  - 右侧：增项小计（粗体高亮展示） + 快捷操作（复制行、删除）；
- **智能化空状态**：
  - 未添加任何增项时，呈现清爽的「无商务增项 · 纯研发工时报价」占位说明，并展示一键点击预设标签，消除冷清感。

---

### 模块 2：交付履约服务（异地出差服务透明化与标准套用）

#### 1. 业务逻辑升级
- **出差标准基准一键套用（Travel Standard Presets）**：
  - **一线城市标准（北上广深）**：交通 ¥1,200/人，住宿 ¥450/天/人，补贴 ¥120/天/人；
  - **省会/二线城市标准**：交通 ¥800/人，住宿 ¥320/天/人，补贴 ¥100/天/人；
  - **省内周边/同城标准**：交通 ¥300/人，住宿 ¥240/天/人，补贴 ¥80/天/人；
- **单目的地实时小计（Per-destination Subtotal）**：
  - 实时拆分并展示每个出差地点的：`往返交通小计` + `住宿小计` + `出差补贴小计` = `单地总成本`。

#### 2. UI/UX 交互升级
- **折叠与分段控制器（Segmented Switch）**：
  - 顶部可采用分段选择器或平滑切换：【异地出差配置 (N地 · ¥XX)】 与 【现场驻场配置 (N地 · ¥XX)】，收窄纵向高度；
  - 支持单地一键套用标准、一键克隆目的地。

---

### 模块 3：现场驻场技术服务（现场交付保驾护航精算）

#### 1. 业务逻辑升级
- **驻场服务场景分类**：
  - `系统部署与环境割接`
  - `生产上线初期现场保驾`
  - `大促/重大活动现场技术值守`
  - `驻点封闭联合研发与培训`
- **权责与交付物明确**：
  - 每条驻场服务增加「交付产出 / 验收凭据」说明（如：《现场割接验收单》、《上线保障值班记录》）。

#### 2. UI/UX 交互升级
- **透明公式展示**：
  - 清晰呈现：`人数 × 驻场天数 × 技术服务单价 (¥/天/人) = 驻场小计`；
  - 单项小计右侧醒目展示，支持快捷选择常用服务单价（如 ¥800/天、¥1,000/天、¥1,500/天）。

---

### 模块 4：外部自费与代采项目（权责清晰与常用代采库）

#### 1. 业务逻辑升级
- **权责模式划分（Billing Mode）**：
  - **客户直付自购**：客户直接与第三方签署并付款，我方仅出具选型配置清单，不占用我方资金池；
  - **我方垫资代采**：我方先行垫付采购，按实报实销走代收代付通道并开具对应结算票据；
- **高频自费与代采预设库（1-Click Add）**：
  - `+ 阿里云 ECS / RDS 服务器 (首年预估 ¥6,000)`
  - `+ 域名购买与 SSL 国密证书 (¥1,500/年)`
  - `+ 腾讯云短信通知包 5 万条 (¥2,000)`
  - `+ 微信小程序/开放平台认证费 (¥300/年)`
  - `+ 苹果开发者企业账号年费 (¥688/年)`
  - `+ 大模型 AI Token 算力资源包 (¥5,000)`

#### 2. UI/UX 交互升级
- **双标签分组汇总**：
  - 卡片顶部显示：`客户自购清单合计: ¥XX` ｜ `我方代采垫资合计: ¥XX`；
  - 每行支持快速切换「自购 / 代采」标签，避免合同谈判与财务开票权责不清。

---

### 模块 5：商务结算与付款计划（可视化进度条、智能平账与模版方案存储）

#### 1. 业务逻辑升级
- **付款方案存储与跨报价单复用引擎（Payment Preset Storage Engine）**：
  - **当前方案另存为模版**：支持销售在调整完任意付款期（如首付 40%、中期 30%、上线 20%、尾款 10%）后，点击「保存当前方案为模版」；
  - **方案元数据**：必须指定「模版名称」（如：`政企分期 4:4:2`、`老客户信贷 6:4`、`免质保 5:5 极速结款`），支持补充「适用场景备注」；
  - **持久化存储**：保存在本地持久存储池（`hubx-quotation-custom-payment-presets-v1`），生命周期跨所有报价单共享；
  - **快捷引用与方案管理**：已保存的自定义模版以独特紫色高亮徽标展示在模版预设区，支持一键引用，并提供删除/重命名管理能力。
- **质保期限全量可调**：
  - 下拉支持：`无质保`、`6 个月`、`1 年 (标准)`、`2 年 (+5% 维保)`、`3 年 (+10% 维保)`；
- **发票与税率说明**：
  - 增值税技术服务专票（6%）、增值税普票（3% / 6%）、离岸跨境免税（0%）；
- **一键平账 / 补齐尾款（Auto-Balance to 100%）**：
  - 当销售配置前两期为 40%、30% 时，系统动态检测剩余 30%，末尾提供「一键补齐差额 (+30%)」按钮，秒级消除红灯校验；
- **节点触发条件预设（Trigger Milestones）**：
  - 预付款：合同签署生效后 3 个工作日内；
  - 阶段款：原型设计与关键架构评审通过后 5 个工作日内；
  - 上线款：系统初验并部署至生产可用后 5 个工作日内；
  - 质保金：系统平稳运行满 12 个月且无遗留严重缺陷后 7 个工作日内。

#### 2. UI/UX 交互升级
- **付款计划 5 大规范化字段矩阵（严格契合商务合同与资金流管控）**：
  1. **期数与阶段**：显式展示 `第 X 期` 徽标标签与阶段名称输入框；
  2. **预计回款日期**：内置日期选择器（`DatePicker`），支持明确约定款项到账日；
  3. **回款条件（自然日 / 工作日）**：由触发事件描述输入框（如“合同签订生效后”）、约定天数输入框（如“5”）和自然日/工作日选择器紧凑编组，满足法务合规条文需求；
  4. **回款比例**：带百分比后缀的数字步进器（0~100%），支持一键补齐尾款智能平账；
  5. **回款金额**：依据总报价动态等比折算的加粗高亮金额展示（`¥XX,XXX`）。
- **外部自费与代采项目垂直对齐与统一表头**：
  - 将每行内重复的列标题提升为顶部统一表头行（费用名称、金额、备注说明/采购属性、操作）；
  - 每行各输入控件与删除按钮高度统一为 28px，容器通过 `grid` + `alignItems: 'center'` 实现 100% 垂直基线精准对齐。
- **可视化资金流动积木条（Visual Milestone Flow Bar）**：
  - 在期数输入上方展示等比例彩虹分段条，鼠标悬浮显示每阶段金额与时间节点；
  - 达到 100% 呈现高质感渐变绿标，未达 100% 呈现黄色预警差额段。
- **自定义方案模版卡片与弹窗**：
  - 弹窗轻量紧凑（宽度 480px），可预览各期节点、回款条件与占比，确认后立即加入跨报价单全局预设标签栏。

## 三、整体 UI/UX 视觉系统对齐（符合 ui-refactor 规范）

1. **色彩语义系统**：
   - 研发人力：`rgb(var(--arcoblue-6))`（深邃科技蓝）
   - 商务增项：`rgb(var(--orange-6))`（商业溢价橙）
   - 交付履约：`rgb(var(--green-6))`（履约落地绿）
   - 自费代采：`rgb(var(--gray-7))`（第三方中性灰）
   - 自定义模版：`rgb(var(--purple-6))`（专属典雅紫）
   - 警示与校验：`var(--color-danger-6)` / `var(--color-warning-6)`
2. **排版与对齐规范**：
   - 所有金额、人天、比例均采用等宽无衬线字体 `'Inter Variable', Arial, sans-serif`；
   - 左右对齐遵循栅格化基准线，消除输入框高低不齐；
   - 紧凑视图：表头高度 36px，行内间距 8px~10px，避免过量空白。
3. **商业驾驶舱联动**：
   - 右侧 280px Sticky 驾驶舱即时联动：增项、差旅、代采与付款比例的调整均在 0 毫秒内同步反映到总报价、毛利率晴雨表与体检清单。

## 四、实施与验证路径

1. **第一阶段：模版持久化存储模块开发**（`paymentPresetStore.ts`，支持内置预设、自定义方案存储、读取、删除与单测）；
2. **第二阶段：页面交互重构与功能接入**（`Stage3WebAutomation.tsx`，接入增项分类、差旅单地拆分、自费/代采模式、付款彩虹条与保存模版弹窗）；
3. **第三阶段：样式增强与视觉润色**（`Stage3WebAutomation.css`，完善卡片阴影、空状态、彩虹条、预设标签样式）；
4. **第四阶段：单测套件扩充与全量回归**（验证 `Stage3WebAutomation.test.tsx` 现有 7 个用例 100% 兼容，并追加自定义方案存储与新交互测试）；
5. **第五阶段：生产构建验证**（`npm run build` 打包验证）。
