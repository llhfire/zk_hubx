

### 一、工作台定位与核心设计原则

1. **角色定位**：销售人员专属作业工作台。
    
      
    
2. **核心业务目标**：
    
      
    - 承接产品经理核对确认后转派的项目评估单。
        
          
        
    - **只读继承**罗总评估的技术人天、切片结构与建议工期，销售端无权篡改技术人天。
        
          
        
    - 按照标准的 **7 步报价向导**（基本信息 $\rightarrow$ 前端 $\rightarrow$ 后端 $\rightarrow$ 其他岗位增项 $\rightarrow$ 出差驻场 $\rightarrow$ 其他成本 $\rightarrow$ 报价汇总）进行增项成本录入与商业报价制定。
        
          
        
    - 执行严格的**系统一致性校验**，确认无误后提交三人并行审批会签。
        
          
        
    - 具备**版本比对**（重新报价时）、**草稿暂存**与**审批前主动撤回**能力。

### 三、报价系统 7 步流程详细交互规范

#### Step 1：基本信息（继承与补录）

- **字段继承（只读）**：项目名称（如“微官网系统”）、项目需求描述、创建人（产品经理）、技术评估人（罗总）。
    
      
    
- **销售补录项**：
    
      
    - 客户全称（如“和昇塑料制品有限公司”）。
        
          
        
    - 客户联系人、联系电话。
        
          
        
    - 行业分类（下拉选择：企业办公/电商购物/物联网/制造工业等）。
        
          
        
    - 报价有效期（默认 30 天）。
        
          
        

#### Step 2：前端配置（平台与终端矩阵）

- **选择平台端（多选卡片）**：
    
      
    - 小程序端（微信小程序、支付宝小程序、抖音小程序等）。
        
          
        
    - 移动 APP（iOS、Android、鸿蒙 HarmonyOS）。
        
          
        
    - Web 平台（PC Web 端、H5 移动端）。
        
          
        
- **角色端与语言配置**：
    
      
    - 为每个选中平台添加角色端（如“用户端”、“商户端”）。
        
          
        
    - 选择前端开发语言/框架（Uni-App、Vue3、React 等）。
        
          
        

#### Step 3：后端配置（服务与架构选型）

- **选择后端服务项（多选）**：
    
      
    - `API 服务`、`后台管理系统 (CMS)`、`数据库设计`、`即时通讯 (IM)`、`第三方支付集成` 等。
        
          
        
- **开发语言与组件**：选择 Java / Go / Python / Node.js 等后端语言。
    
      
    

#### Step 4：其他岗位与销售增项（核心控制步骤）

- **罗总人天明细区（全局只读）**：
    
      
    - 完整展示罗总在工作台二切片评估的模块、切片组、子功能点及各岗位人天（产品、UI、前端、后端、测试等）。
        
          
        
    - 销售人员**严禁直接修改、覆盖或剔除**罗总的技术人天数据。
        
          
        
    - 若销售认为技术工时过高/过低，只允许点击【↩️ 退回罗总重新评估】并附言说明，流程退回工作台二。
        
          
        
- **销售增项区（可编辑）**：
    
      
    - 针对罗总未涵盖或客户特殊商务要求的岗位，销售可自主点击【➕ 添加增项岗位】。
        
          
        
    - 增项岗位录入字段：`岗位名称`、`人数`、`天数`、`日均单价/成本`、`小计金额`、`增项事由说明`。
        
          
        
    - 增项小计自动独立归集，不污染罗总原始技术人天。
        
          
        

#### Step 5：出差与驻场配置

- **出差配置（开关）**：
    
      
    - 开启后配置：出差地点、出差人数、预计出差天数、交通费（往返机票/高铁）、住宿费（元/天/人）、差旅补贴（元/天/人），系统自动计算差旅小计。
        
          
        
- **驻场服务配置（开关）**：
    
      
    - 开启后配置：驻场地点、驻场人数、驻场天数、现场技术支持服务费，系统自动累加驻场小计。
        
          
        

#### Step 6：其他成本与第三方费用配置

销售根据项目实际发生情况配置非人力硬性成本：

  

- **第三方云资源与账号费用（需填报预估或上传依据）**：
    
      
    - 云服务器（ECS）、数据库（RDS）、对象存储（OSS）、短信包、域名/SSL 证书、微信认证费（300元/年）等。
        
          
        
- **商务与运营成本**：
    
      
    - 商务接待/公关成本、销售佣金/提成比例、客户培训费、发票税费等。
        
          
        
- **自定义成本项**：支持销售动态添加 `成本名称 + 金额 + 费用说明`。
    
      
    

#### Step 7：报价汇总、自动校验与提交审批

- **多维数据汇总看板**：
    
      
    - **工期与人天**：总人天（技术 30 天 + 增项 7 天 = 37 天）、总人数、建议工期（20 工作日）。
        
          
        
    - **报价结构总览**：
        
          
        
        $$\text{项目最终总报价} = \text{人力成本小计} + \text{差旅驻场费用} + \text{第三方/其他成本} + \text{税费}$$
        
    - **比例分布图**：直观展示人力占比（如 85%）、差旅占比（5%）、其他/硬件占比（10%）。
        
          
        
- **商务条款配置**：
    
      
    - **付款方式配置**：下拉选择标准模式（如：`50% 首付款 - 40% 交付款 - 10% 验收尾款`）或自定义阶段比例。
        
          
        
    - **售后服务期**：默认提供 1 年免费基础运维保障。
        
          
        
- **系统自动一致性校验（提交前硬校验）**：
    
      
    - 校验 1：$\sum \text{各分项人天} = \text{总人天}$；
        
          
        
    - 校验 2：$\text{各成本小计之和} = \text{项目总报价}$；
        
          
        
    - 校验 3：付款阶段比例之和必须精确等于 $100\%$；
        
          
        
    - 校验 4：若开启差旅/第三方成本，金额必须大于 0。
        
          
        
- **操作流转**：
    
      
    - 校验通过后，激活【🚀 提交审批】按钮，点击后系统生成报价快照并流转进入三人并行会签审批。
        
          
        
    - 审批通过前，支持导出带“草稿 / 内部预览”水印的图片或 PDF。
        
          
        

### 四、退回、撤回与版本变更机制

1. **销售主动撤回机制**：
    
      
    - 销售提交审批后、审批人尚未全部签署前，销售若发现填报有误，可在工作台随时点击【撤回报价】。
        
          
        
    - 必须填写“撤回原因”，单据即刻恢复为销售草稿状态，审批流自动中断并通知审批人。
        
          
        
2. **退回修改响应机制**：
    
      
    - 若审批被黄奕、罗总或闵总任一人驳回，工作台状态变更为 `[审批驳回待修改]`，高亮显示驳回人及驳回意见。
        
          
        
    - 销售修改后重新提交，系统校验变更点并重置审批链，发起全员重审。
        
          
        
3. **多版本对比与重新报价（v2.0）**：
    
      
    - 若客户对报价不满意要求调整，销售在工作台点击【新建报价版本】（版本号自增至 v2.0）。
        
          
        
    - 新版本自动复制上一版本数据，支持两版本一键 Diff 对比（高亮显示减项、价格调整与人天变动），旧版本归档保留。
