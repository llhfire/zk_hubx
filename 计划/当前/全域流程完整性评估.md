# ZK HubX 全域流程完整性评估

> 评估日期：2026-08-26  
> 范围：当前仓库的 α 场景、β 数据接缝、跨域联动及异常流程。  
> 事实源优先级：`HubX/CONTEXT.md` / ADR → 当前代码与 API → `featureBoard.config.json` → 活跃计划。8 月 13 日进度表与旧四域清单仅作历史参考。

## 2026-08-28 α 复评

α 核心漏斗已新增自动化冒烟并通过：`线索 → 派发 → 首联 → 报价 → 主合同 → 项目指派 → 合同批准 → 开工 → 实收`。未确认项目已统一为 `ap-lead-{leadId}`，线索洽谈触发和后续合同创建幂等合并为同一项目。合同兼容回款与独立台账已统一流水 ID，主合同、回款、项目 360、项目成本及精益交付主页面均改由独立 `collections` 生成只读投影；浏览器已验证各下游金额一致。

因此“α 核心漏斗缺少整链验证”“项目成本/精益交付实收双读”及 `ClosedLeads`、`PaymentInvoiceList` 两处独立 mock 已关闭。后续又补齐 α 的“交付计划→任务→项目日报→交付物归档→验收”及“回款期次→逾期→开票/红冲→售后移交”操作接缝。α 可评为主流程基本完整；β 刷新持久化、权限、成本利润和服务端售后移交仍待完成。验证记录见 `HubX/docs/2026-08-28-α核心漏斗冒烟日志.md` 与 `HubX/docs/2026-08-28-α六项收口与最终复检日志.md`。

## 评估口径

- **A 完整闭环**：入口、主流程、异常回退、唯一数据源、下游消费和验证全部具备。
- **B 主流程基本完整**：主要场景可走通，但少量异常或生产接缝未收口。
- **C 可演示但未闭环**：页面和纯函数较完整，仍有 mock、双账或跨域断点。
- **D 局部页面或规划**：尚未形成端到端业务流程。

页面存在不等于流程完整；α 能演示不等于 β 能持久化。功能看板共有 20 个非规划模块，目前仅“日报工时、运营费用”三个 α 检查项全勾，β 尚无模块达到“测试通过”。

## 总体判断

整体处于 **α：B-，β：C-**。α 销售、交付和财务主线现可连续演示并具备关键状态门槛；β 仍缺服务端持久化、真实身份权限和部分跨域写时联动；资源域仍未形成完整领域流程。

核心链路当前不能判定完整：

`渠道投放 → 线索录入/派发 → 销售跟进 → 报价 → 合同 → 未确认项目 → 交付 → 实收/开票 → 成本/利润 → 售后`

主要断点是 β 页面仍读静态数据、签约立项的 β 接缝未完成、交付计划无服务端存储、开票与验收未持久化、公摊费率口径分叉。

## 下一阶段验收门

- 同一业务事实只有一个写入方，其他页面只能引用或投影。
- α 与 β 共用状态机和 mutation，β 刷新后数据与状态不丢失。
- 每个关键状态至少覆盖正常推进、驳回/撤回、作废/退回和幂等重试。
- 核心漏斗冒烟通过前，不把模块标记为 β“测试通过”。
- 暂缓新增 AI、管理驾驶舱和更多独立页面，直到 P0 双账和主链断点清零。
