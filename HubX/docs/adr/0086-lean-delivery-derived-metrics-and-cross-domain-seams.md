# 0086 精益交付汇总指标全部派生，报价/合同/回款跨域引用，不自建平行数据

移植稿 `pages/financial-delivery/` 的所有汇总数（totalCost、totalFeatureCost、totalAmount、EAC、利润率、趋势、穿透看板）都是与明细无关的硬编码，五类数据互相对不上；且自建了第二套报价单/工时评估，contractId 指向不存在的合同。手工对齐数字只救得了演示，救不了「每个数据有来源」。选择：mock 只造原子事实（成本流水、回款流水、评估人天），一切汇总由 `calc.ts` 纯函数派生；报价/评估读报价域（α mock 接缝 / β HTTP），合同/回款读合同域。**Case 是轻实体（复审修正案）**：不持有业务明细事实，但持有管理参数（targetMargin/budgetCap/commercialCap，无第二个候选主人）与自有 10 态状态机（协商中/催款中在报价/合同/项目域均无可派生的对应状态）。成本流水写入口定三通道：日报（工时×岗位成本日薪）、报销（通过后归集）、公摊（运营费用月结按工天生成分摊），manual 仅兜底；mock 不造假 dr-xxx/reimb-xxx 引用。指标双口径：全周期利润率（标的额 vs EAC）管健康判定，回款口径只管 WIP/现金流--回款口径下交付前期利润率必然失真，不能做健康灯。代价是跨域接缝与派生函数维护；换来的是数字永久自洽、单一事实源。仪表盘同样处理：穿透看板、模拟器（敏感性+底线价，只缩 forecast 人力成本）、相似项目全部派生化，不留无来源部件。
