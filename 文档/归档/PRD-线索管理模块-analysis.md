# 内容分析：PRD-线索管理模块

## 核心内容

- 覆盖线索从公海、认领、跟进、报价、合同、回款开票到转项目的完整业务链路。
- 明确了线索详情的左右布局、主 Tab 与业务过程 Tab 的职责划分。
- 对报价版本、合同版本、审批、附件归集和回款拆分给出了完整规则。

## 结构评估

- 当前主线为：模块范围 → 列表与详情 → 业务过程 Tab → 状态流程 → 跳转规则 → 验收与开发建议。
- 报价章节内容较完整，但原有小节编号与全局编号层级不一致。
- 合同、演示、资料、出差报销等章节可在“业务过程 Tab”下保持同级展示。

## 格式问题

- 多数标题缺少 Markdown 标题符号后的空格，部分章节层级使用了不一致的 `#` 数量。
- 表格表头、分隔行和数据行之间存在空行，影响 Markdown 渲染。
- 报价章节的“模块范围、核心业务规则、报价记录、新增报价”使用了独立编号，阅读时不易定位。
- 连续列表项之间存在较多无意义空行，页面纵向间距偏大。

## 本次处理范围

- 统一标题层级和编号格式。
- 补充文档目录，便于快速定位。
- 修复表格和列表的 Markdown 排版。
- 不修改或删减任何业务规则、字段、状态及验收要求。
