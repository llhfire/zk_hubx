# 设计系统组件清单

> 配套：`设计系统规范.md`（结构规则）、`docs/design/页面标记与全站检查标准.md`（行为规则 M-001~M-049）
> **铁律：每个页面都必须按本清单的组件组织；清单里没有的 UI 语汇，先补组件或组件变体，再改页面。组件不恰当时不得在页面里绕开组件库。**
> **实样入口**：`/ui-library` 四层——「基础 UI」（原子与录入控件）、「模块组件」（组合块，按六类分页签）、
> 「页面框架」（可运行骨架）、「业务样板」（真实页面切片 + 复制边界）。
> 58 个导出全部有真实渲染；新增组件必须同时补一份实样并落到对应层 —— 目录里只有一行文字等于没交付。

## 三、新增 UI 语汇时的做法

1. 页面先停在组件边界，不得先用页面级 JSX/CSS 临时替代；
2. 判断属于哪一类（primitives / layout / data-display / forms / feedback / business），**不按业务域分类**；
3. 检查是否已有同语义组件——同语义就加受限的 `variant` / `tone` / `size`，语义不同才新建；
4. 样式只写进 `design-system/components.css`，颜色/字号/圆角/阴影只引用 `tokens.css` 变量；
5. 从 `design-system/index.ts` 导出（含 props 类型）；
6. 在 `__tests__/designSystem.test.tsx` 补一条渲染断言；
7. 在 `app/pages/ui-library/` 下补一份实样：原子/录入控件进「基础 UI」的 `panels/FoundationPanel.tsx`，
   组合块进「模块组件」的 `panels/ModulesPanel.tsx`（按六类分组），并同步 `data.ts` 的目录行；
8. 跑 `npm run typecheck` + `npm test` + `npm run check:ds`，全部通过后才能回到页面使用。
