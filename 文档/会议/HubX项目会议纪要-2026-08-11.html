HubX 会议纪要（2026-08-11）

一、会议基本信息

  • • 会议主题：HubX 业务流程、报价审批、合同回款、财务开票、成本核算及人资模块评审
  • • 会议日期：2026-08-11
  • • 参会人员：陈孟春、杨培豪、何江奇、黄奕、闵总、王总
  • • 整理依据：会议录音识别文本

二、会议目标

  1. 1. 明确从客户需求到报价、合同、项目执行、回款开票的完整线上流程。
  2. 2. 评审当前原型中的报价、审批、合同、财务、成本、人资和会议管理功能。
  3. 3. 减少线下表格、私聊传递和重复录入，提升流程效率与管理可追溯性。
  4. 4. 明确下一阶段产品优化与技术评估事项。

三、核心结论

1. 业务流程必须形成完整线上闭环

目标流程统一为：

客户沟通留痕 → 需求梳理 → 功能清单 → 工作量评估 → 成本核算 → 对外报价 → 报价审批 → 合同 → 项目执行 → 回款/开票 → 资料归档

  • • 已迁移到系统的工作应尽量全程在线完成，不应再形成“线上录一次、线下再做一次”的双轨流程。
  • • 每个节点需要明确操作人、操作时间、输入输出、审批记录和版本变化。
  • • 线索、合同、项目和财务不是相互割裂的业务，而是同一业务对象在销售、项目、法务/财务等不同角色下的视图。
  • • 优先从 PC 端落地完整流程，移动端作为后续阶段规划。

2. AI 用于提效，但必须控制需求扩张

  • • AI 可以辅助生成、整理和缩减功能清单，但不能无边界补充客户未提出的功能。
  • • 功能清单必须基于客户沟通记录，可追溯到群聊、录音、跟进记录等原始依据。
  • • AI 输出应保持适当粒度，避免清单过细导致报价虚高、客户范围预期扩大及后续验收争议。
  • • 后续可使用 AI 自动完成沟通总结、每日项目动态总结、流程监控和重复性录入工作。

3. 产品设计先满足业务效率，再评估技术方案

  • • 产品阶段应优先明确最顺畅、最高效的业务方案，不能因为技术实现存在难度就直接降低业务目标。
  • • 技术团队应先评估在线表单、在线表格、固定模板上传解析等方案，再决定首期落地方式。
  • • 对暂时无法一次实现的能力，可采用分阶段方案，但最终目标仍是结构化在线协同和全链路留痕。

四、模块需求与会议决议

4.1 需求、功能清单与工作量评估

  • • 功能清单应由客户需求和沟通记录产生，并在确认后冻结范围和边界。
  • • 工作量评估应尽量迁移至系统内，由技术评估人员填写人天、难度等数据。
  • • 需要技术评估以下实现路径：
    1. 1. 系统内结构化在线表单；
    2. 2. 在线表格协同填写；
    3. 3. 固定 Excel/Word 模板上传并解析；
    4. 4. 首期通过模板粘贴/导入，后续再升级自动解析。
  • • 不接受长期依赖销售手工复制大量人天和功能数据的方案。
  • • 工作量评估完成后，系统应直接形成内部成本报价基础数据。

4.2 报价配置与报价单

  • • 原始成本/原始报价保持不变，价格调整只影响最终报价。
  • • 支持两种调整方式：按比例上浮、按固定金额上浮。
  • • 上浮金额应合理分摊到功能或人天数据中，允许出现小数人天，以保证计算准确。
  • • 内部成本明细不直接给客户；客户看到的是最终生成的正式报价单。
  • • 报价完成后生成 Word 等正式文档，报价单中应包含功能清单和最终报价。
  • • 报价资料应包括功能清单、工作量评估、技术评估文件、原始报价依据等，形成完整上下文。
  • • 报价提交后进入系统内审批，不再重复走企业微信审批。

4.3 报价审批与审批中心

  • • 报价页面顶部展示审批记录和当前状态。
  • • 审批人可以查看报价上下文、附件及历史记录后执行同意或拒绝。
  • • 拒绝必须填写原因；修改后发起新一轮审批，历史轮次必须保留。
  • • 系统需建设统一审批中心，区分待审批、已审批等状态。
  • • 从审批中心查看业务详情时，优先使用弹窗/抽屉承载完整上下文，避免审批多条数据时频繁跳转页面。
  • • 首页待办应能进入审批中心处理任务。
  • • 报价操作指引需改成准确的业务步骤，例如：需求沟通 → 功能清单确认 → 工作量评估 → 成本核算 → 报价审批。

4.4 合同付款比例与回款计划模板

  • • 付款比例不宜使用不断增加的平铺按钮，应采用下拉选择。
  • • 预置常用比例，例如 3:3:3:1、4:5:1 等；具体预置清单待业务确认。
  • • 每个模板需包含：模板名称、付款比例、简要说明、各期回款条件。
  • • 相同付款比例可以存在多个模板，因为回款条件可能不同。
  • • 选择模板后自动生成回款计划和回款条件。
  • • 预计回款日期不进入模板，由具体项目单独填写。
  • • 日期类型可以默认继承第一期选择，但后续各期仍应允许调整，不应完全锁死。
  • • “存为模板”必须弹窗填写模板名称和说明，不能只提示保存成功。
  • • 需要单独的后台入口维护付款模板。

4.5 回款、开票与财务工作台

  • • 业务人员在回款/发票页面提交开票申请，系统自动带出客户、合同、主体和当期款项信息。
  • • 签约主体可能在沟通过程中变化，因此开票主体必须可切换，不能完全固定。
  • • 财务端需要独立开票审批/工作台，区分待处理和已处理。
  • • 财务查看开票申请时必须看到完整上下文：项目、合同、当期款项、回款状态、历史开票和后续回款情况。
  • • 支持先回款后开票，也支持先开票后回款；系统只做状态提示，不做绝对阻断。
  • • 开票信息字段旁增加复制图标，便于财务快速复制到税务系统。
  • • 财务完成开票后上传发票文件并确认，业务页面同步更新为已开票，可查看和下载附件。
  • • 对先开票后回款的记录建立逾期提醒，便于财务联系负责人跟进。

4.6 发票冲红与重开

  • • 增加发票冲红、重开流程。
  • • 冲红由业务/销售发起申请，必须填写原因，并支持上传客户沟通截图、备注或其他附件。
  • • 冲红属于谨慎操作，需要确认和审批流程。
  • • 原开票记录保留并标记为已冲红；重开生成新的开票记录。
  • • 系统需完整记录申请人、审批人、财务操作人、原因、附件和操作时间。
  • • 所有冲红及重开资料自动归档，不再依赖人工二次归档。

4.7 项目资料与模块联动

  • • 验收单、用户确认书、需求变更确认书等资料主要在项目管理环节产生。
  • • 文件只上传一次，但应在项目、合同、回款条件和统一资料页中按权限关联展示。
  • • 统一资料页按时间线记录所有新增资料，并支持查看、下载和追溯来源。
  • • 回款或开票前，如果所需验收资料尚未上传，系统可以弹窗提醒，但原则上不做强制阻断。
  • • 客户提供的合同模板允许上传；后续版本可采用下载修改后重新上传的方式管理，但附件合同的结构化识别能力需另行评估。

4.8 成本核算

  • • 成本页面重点展示金额和成本构成，图表应直观反映金额、比例和差异。
  • • 人工成本支持新增员工、工时和工作性质/工作内容。
  • • 日报数据应直接关联到成本核算，可按日期范围筛选，不限于按月。
  • • 在成本页面可直接查看日报详情，无需跳回日报模块。
  • • 人工成本至少提供两个分析维度：
    1. 1. 按人员统计；
    2. 2. 按工作性质/工作内容统计。
  • • 日报填报时必须选择工作性质，才能支持后续成本统计。
  • • 每个统计表需要合计行，展示筛选周期内总工时和总成本。
  • • 高频操作放在显著位置，例如回款、开票；附件、拆分等低频操作放入详情或更多操作。

4.9 员工列表与薪资展示

  • • 转正工资有调整时，列表只需在原金额下方用灰色小字显示调整后金额。
  • • 生效时间不直接铺开显示，鼠标悬停时查看即可。
  • • 员工资料继续保留社保、公积金和每月工天。
  • • 每月工天用于适配双休、大小周等不同用工方式，是成本计算基础数据之一。

4.10 人资费用管理

  • • 费用以卡片形式展示，支持新增和修改，并显示金额及生效时间。
  • • 页面需要展示费用金额汇总。
  • • 费用类型不建议开放任意自由输入，避免同义名称和重复类型。
  • • 在费用类型下拉框中提供“编辑/维护类型”的快捷入口，进入受控的类型维护流程。

4.11 企业微信集成

  • • 企业微信集成主要用于待办和消息推送。
  • • 业务审批本身在 HubX 内完成，不重复发起企业微信审批。
  • • 企业微信的具体消息类型、接收人和失败重试机制需要在后续实施方案中明确。

4.12 会议管理

  • • 会议管理需在正式环境验证登录和完整流程。
  • • 会议类型应支持新增和编辑，建议纳入字典配置。
  • • 项目人员/参会人员应支持快捷选择。
  • • 常规会议可建立参会人模板，例如周例会、部门例会；选择会议类型后自动带出默认参与人员，并允许调整。

五、待确认事项

  1. 1. 功能清单与工作量评估首期采用在线表单、在线表格还是固定模板上传解析。
  2. 2. AI 生成需求清单的粒度、约束规则和人工确认责任人。
  3. 3. 先开票后回款的预警时限、提醒对象和升级规则。
  4. 4. 项目资料、合同资料和统一资料页之间的权限、分类及同步规则。

六、主要风险

  • • 需求膨胀风险：AI 自动生成过细功能清单，可能造成报价虚高和交付边界扩大。
  • • 双轨流程风险：线上系统与线下 Excel/私聊并存，会继续造成重复录入和信息断点。
  • • 跨模块一致性风险：线索、合同、项目、财务分别维护同一资料，容易产生状态不一致。
  • • 财务合规风险：冲红、重开、主体切换若缺少审批和审计记录，后续难以追责。
  • • 提醒失效风险：先开票后回款如果没有明确时限和责任人，可能产生逾期和税务成本。
  • • 统计口径风险：日报未强制选择工作性质，人工成本按工作内容统计将失真。
  • • 技术复杂度风险：在线表格、文档解析、AI 上下文和跨模块联动均需要专项技术验证。

八、建议验收标准

  1. 1. 任一报价可追溯到客户沟通、功能清单、工作量评估、成本和审批记录。
  2. 2. 报价审批、开票、冲红、重开均保留完整操作日志和历史版本。
  3. 3. 财务无需跨多个页面查找，即可查看开票所需的完整项目和回款上下文。
  4. 4. 同一资料只上传一次，并在相关模块按权限一致展示。
  5. 5. 成本核算能按日期、人员和工作内容统计，且结果与日报数据一致。
  6. 6. 常规业务人员可在系统内完成流程，不依赖私聊传文件和线下二次登记。
