3. 一次写入怎么走

1 页面动作向导保存、跟进、登记实收
2 Context调用 service.put / create
3 http servicefetch + 头 X-Actor + body.version
4 Workers PUT比 version，不匹配 409
5 D1INSERT OR REPLACE 整段 JSON，version+1
6 写时联动仅合同：created / approved / voided → 项目/商机

没有登录会话、没有接口鉴权、没有操作日志表。actor 信任请求头。 没有导航级 refetch：β 签约桥在 isBeta() 为 true 时直接 return，也不调 refresh()（洞 A）。

4. 平台基座（ADR-0094）

已落地的可信度修补 工作区已编码

  • 文档式 D1：一域一张表，data 存整对象。β 期不做关系建模。
  • 乐观锁：PUT 带 version，冲突 409 + 当前 version。
  • 服务端时钟：updatedAt 由 Workers 生成，回写前端。
  • X-Actor：过渡身份；登录落地后换会话。

刻意没做

  • JWT / 登录页 / 路由守卫 / 接口级权限
  • 按状态/客户的列查询、引用完整性
  • WebSocket、合并冲突 UI
  • D1 migrations_dir 自动迁；现流程是 d1 execute --file
  • 两个文件都叫 0002_*.sql，B5 P1 才改名

6. 三个会挡冒烟的洞（B5 P0，均必做）

洞 C · Workers

首次创建合同不 spawn

PUT /api/contracts/:id 仅 if (old) 才 handleSigningLinkage。向导第一次是 INSERT，old 空，整段跳过。之后 prevSnapshot 含本 id，events.created 永假。批准路径无项目则 continue，从不补 spawn。结果：β 从未 INSERT ap-{合同id}。

洞 A · 前端桥

β 不刷新项目 Context

ApprovalDeliveryBridge 注释写「合同列表变化时刷新项目」。isBeta() 为 true 时直接 return，且未取出 refresh。只修 A 不修 C，refresh 仍是空列表。同会话新建合同后项目列表不会自己出现。

洞 B · 双写

登记实收进错账

合同详情 addCollection → 嵌套 collectionRecords + receivedAmount。360 / 台账读 collections 表。用户只能在合同详情登记，360 看不到这笔钱。B5 要求与看板共用 registerMainPaymentDualWrite。

签约联动（设计意图 vs 现网）

设计（ADR-0093 / 0095）： 主合同草稿 PUT ──created──► INSERT projects id=ap-{合同id} 未确认 已指派 + 批准 ──approved─► startDelivery 进行中 主合同作废 ──voided───► shelveProject 搁置 批准时无项目 不 spawn（不是立项点） 现网：created 因洞 C 永不命中 → spawnUnconfirmedProject 是死代码 α：SigningOpenBridge 仍 diff；跟进另有内存 spawn lead-spawn-{线索id} β 洽谈无合同：应走 U1 / ap-lead-{线索id}，B5 不做
