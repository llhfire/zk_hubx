## 三、文档结构设计

### 1. 文档说明
为什么写、覆盖时间范围、如何使用、信息源与可信度说明。

### 2. 阶段总览表
表格：阶段｜日期｜主题｜一句话。共 7 行，作为全篇导航。

### 3. 分阶段详述
每个阶段一节，统一五块模板：

- **背景与触发**：为什么这个阶段发生（会议/决策/复盘触发点）
- **做了什么**：里程碑要点列表
- **关键决策**：为什么这么做（含放弃的选项，若有）
- **结构/数据变化**：文件结构、数据模型、状态机怎么变
- **遗留与风险**：没做完的、踩过的坑

### 4. 当前状态快照（演进终点）
- 架构现状（monorepo 结构）
- 已通 http 的域 / 仍 mock 的域
- 4 个 P0 待办现状（引 08-16 核实结论）
- 遗留事项汇总

### 5. 附录：git 提交清单
16 个提交表格（hash｜日期｜类型｜内容）。

## 四、内容还原策略（关键约定）

1. **有据可查**（git 提交 / 跨会话记忆 / 现有文档）→ 直接写，标注来源。
2. **git 缺失阶段的细节**（08-14~08-15）→ 用 `SYSTEM-OVERVIEW.md` + 代码现状逆向还原，并标注「据代码现状还原」。
3. **还原不了或不确定** → 明确标注「待补充确认」，**绝不编造**。
