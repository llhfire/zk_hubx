# HubX 知识库模块 PRD

## 0. 文档说明

本文档用于指导 HubX 知识库模块的产品评审、前端开发、PHP 后端开发、数据库设计和测试验收。

1. `MUST` 表示必须实现，`SHOULD` 表示建议实现，`MAY` 表示可选实现。
2. 当前页面为 React 前端虚拟功能，文档数据和附件未接入真实后端。
3. 正式版本必须由 PHP 服务端完成权限校验、文件存储、预览转换、下载鉴权和数据持久化。
4. 前端传入的组织、上传人和管理员身份均不可信，服务端必须根据登录态重新校验。
5. 知识库组织数据必须复用 HubX 员工与组织体系，不得维护第二套独立组织架构。
6. 企业微信是员工及组织资料主数据源时，知识库只保存组织 ID 关联和必要名称快照，不得反向修改企业微信组织资料。

## 1. 产品目标

知识库用于按组织沉淀、查找和管理企业内部文档，解决以下问题：

- 文档散落在个人电脑、聊天工具和不同业务页面中，难以统一查找。
- 文档缺少明确的归属组织和查看权限。
- 用户无法快速定位某个部门的知识资产。
- 图片、PDF、Office 等常用文件不能直接在线查看。
- 压缩包、安装包等不适合在线预览的文件缺少统一下载入口。
- 文档附件更新时缺少安全、清晰的替换流程。

## 2. 需求范围

### 2.1 本期包含

- 左侧组织架构导航。
- 组织节点文档数量展示。
- 按组织查看知识库文档。
- 文档分类筛选。
- 文档名称和文件名搜索。
- 上传文档并自动归属当前选中的组织。
- “内部公开”和“所有人可查看”两种查看权限。
- 文件在线预览或直接下载。
- 文档信息编辑。
- 删除原附件后重新上传新附件。
- 文档删除。
- 上传者和管理员的管理权限控制。
- 阅读次数记录。

### 2.2 本期不包含

- 标签体系。
- 在上传弹窗中切换其他部门。
- 一个文档上传多个附件。
- 文档版本管理和历史版本恢复。
- 文档在线协同编辑。
- 评论、收藏、点赞和分享链接。
- 文档审批发布流程。
- 批量上传、批量移动和批量删除。
- 外部匿名访问。
- 全文内容检索和 OCR。

## 3. 角色与权限

### 3.1 角色定义

| 角色 | 定义 |
|---|---|
| 普通员工 | 已登录 HubX 且具备知识库访问权限的员工 |
| 文档上传者 | 创建该知识库文档记录的员工 |
| 系统管理员 | 具备知识库全局管理权限的管理员 |

### 3.2 权限矩阵

| 操作 | 普通员工 | 文档上传者 | 系统管理员 |
|---|---:|---:|---:|
| 查看“所有人可查看”文档 | 是 | 是 | 是 |
| 查看有权访问的“内部公开”文档 | 是 | 是 | 是 |
| 在线预览或下载有权查看的文档 | 是 | 是 | 是 |
| 上传文档 | 按组织数据权限 | 按组织数据权限 | 是 |
| 编辑文档信息 | 否 | 是 | 是 |
| 删除、替换附件 | 否 | 是 | 是 |
| 删除文档 | 否 | 是 | 是 |
| 管理任意组织文档 | 否 | 否 | 是 |

`MUST`：编辑、替换附件和删除操作必须同时在前端控制显示，并在服务端接口中再次鉴权。

`MUST`：普通员工即使构造接口请求，也不能修改或删除其他员工上传的文档。

## 4. 信息架构与页面布局

### 4.1 页面入口

- 一级菜单：`知识库`
- 路由：`/knowledge`

### 4.2 页面结构

页面采用左右两栏布局：

1. 左侧：组织架构树。
2. 右侧：当前组织知识库文档列表。

页面不展示“当前组织、组织文档、所有人可查看”等额外统计卡片，文档数量统一展示在组织树节点右侧。

### 4.3 左侧组织架构

`MUST`：

- 组织树复用员工管理中的组织结构和稳定组织 ID。
- 默认展开组织树。
- 默认选中公司根组织。
- 每个组织节点右侧显示该节点对应的文档数量。
- 点击组织节点后刷新右侧文档列表及上传入口文案。
- 叶子组织显示本组织文档数量。
- 父级组织显示本级及全部下级组织文档数量。
- 文档数量统计必须应用当前用户的查看权限，不能通过数量泄露无权访问的文档。

示例：

```text
总公司        8
├─ 技术部     5
│  ├─ 前端组  1
│  └─ 后端组  1
├─ 销售部     1
└─ 财务部     1
```

### 4.4 右侧文档列表

列表标题格式：`{当前组织名称}知识库`。

列表字段：

| 字段 | 说明 |
|---|---|
| 文档名称 | 主标题；点击后按文件格式执行预览或下载 |
| 文件名称与大小 | 显示在文档名称下方；点击行为与文档名称一致 |
| 分类 | 技术方案、SOP 流程、模板、项目复盘、其他 |
| 归属组织 | 文档所属组织名称 |
| 查看权限 | 内部公开、所有人可查看 |
| 上传人 | 创建文档的员工名称快照 |
| 更新时间 | 最近一次编辑或附件替换时间 |
| 操作 | 仅保留编辑、删除 |

`MUST`：操作列不得重复展示预览和下载入口。

`MUST`：无编辑权限的用户不显示编辑、删除操作。

## 5. 文档查询

### 5.1 组织筛选

- 点击组织节点后，仅查询当前组织及其下级组织范围内的文档。
- 叶子组织只查询本组织文档。
- 查询结果必须叠加当前用户的数据权限和文档查看权限。

### 5.2 分类筛选

固定分类及顺序：

| 顺序 | 编码 | 名称 |
|---:|---|---|
| 1 | `all` | 全部文档 |
| 2 | `tech` | 技术方案 |
| 3 | `sop` | SOP 流程 |
| 4 | `template` | 模板 |
| 5 | `review` | 项目复盘 |
| 6 | `other` | 其他 |

`MUST`：切换分类后保留当前组织和搜索关键词。

### 5.3 搜索

- 搜索范围：文档名称、原始文件名。
- 不提供标签搜索。
- 搜索框后不增加额外权限下拉框。
- `SHOULD`：输入停止 300 毫秒后发起查询，避免每次按键都请求服务端。
- `SHOULD`：搜索关键词去除首尾空格，英文不区分大小写。

## 6. 上传文档

### 6.1 上传入口

页面只保留一个上传入口，位置在当前组织文档列表工具栏右侧。

按钮文案：`上传至{当前组织名称}`。

示例：选中财务部时，显示“上传至财务部”。

`MUST`：

- 点击上传入口时，将当前组织 ID 固定为目标组织。
- 上传弹窗中只读显示归属组织。
- 上传弹窗不能选择或切换其他部门。
- 服务端提交时校验当前用户是否具备目标组织的上传权限。
- 不允许通过修改请求参数上传到无权管理的组织。

### 6.2 上传字段

| 字段 | 必填 | 可编辑 | 规则 |
|---|---:|---:|---|
| 文件 | 是 | 是 | 本期一个文档只允许一个主附件 |
| 文档名称 | 是 | 是 | 用于列表展示和搜索 |
| 归属组织 | 是 | 否 | 来自当前选中的组织 |
| 文档分类 | 是 | 是 | 固定五类 |
| 查看权限 | 是 | 是 | 仅两种固定权限 |
| 文档说明 | 否 | 是 | 简要描述内容和适用场景 |

本期不提供标签字段。

### 6.3 查看权限

| 编码 | 名称 | 查看范围 |
|---|---|---|
| `internal` | 内部公开 | 归属组织及其下级组织内有知识库权限的员工 |
| `all` | 所有人可查看 | HubX 内所有已登录且具备知识库访问权限的员工 |

`MUST`：查看权限只影响查看、预览和下载范围，不改变文档的归属组织。

`MUST`：后端返回列表前完成权限过滤，不能只依赖前端隐藏。

### 6.4 文件要求

建议支持：

- 文档：PDF、DOC、DOCX、XLS、XLSX、PPT、PPTX、TXT、MD、CSV。
- 图片：PNG、JPG、JPEG、GIF、WEBP、SVG。
- 压缩包：ZIP、RAR、7Z。
- 安装包：EXE、DMG、APK。

`MUST`：

- 同时校验文件扩展名、MIME 类型和文件头，不能只校验后缀。
- 文件名进行安全处理，禁止路径穿越和脚本注入。
- 文件存入对象存储或受控文件存储，不建议将二进制文件直接保存到 MySQL。
- 文件下载使用短时有效的鉴权地址。
- 上传完成前文档记录不得进入可查看状态。
- 文件替换和数据库更新应具备事务或补偿机制，避免产生孤立文件。

`SHOULD`：接入病毒和恶意文件扫描。

## 7. 文件预览与下载

### 7.1 文件名称点击规则

点击文档名称或下方原始文件名时：

1. 支持在线预览的格式进入预览弹窗。
2. 不支持在线预览的格式直接下载。

### 7.2 在线预览格式

| 文件类型 | 处理方式 |
|---|---|
| PNG、JPG、JPEG、GIF、WEBP、SVG | 图片查看器 |
| PDF | 浏览器 PDF 查看器 |
| TXT、MD、CSV | 服务端读取安全文本后展示 |
| DOC、DOCX、XLS、XLSX、PPT、PPTX | 转换为 PDF/HTML 后预览，或接入受控文档预览服务 |

`MUST`：Office 文件不能仅根据后缀显示模拟内容；正式版本必须完成真实内容转换或接入真实预览服务。

`MUST`：预览失败时展示失败原因，并提供“下载文件”操作。

`MUST`：预览弹窗底部提供下载按钮。

### 7.3 直接下载格式

ZIP、RAR、7Z、EXE、DMG、APK 等不支持在线预览的文件，点击后直接下载，不打开空白预览弹窗。

### 7.4 阅读次数

- 成功打开预览或成功生成下载响应后，阅读次数增加一次。
- 同一用户短时间重复打开是否去重见“待确认事项”。
- 阅读计数失败不得阻断预览或下载主流程。

## 8. 编辑文档

### 8.1 编辑权限

只有以下人员可编辑：

1. 文档上传者本人。
2. 系统管理员。

编辑权限包括：

- 修改文档名称。
- 修改分类。
- 修改查看权限。
- 修改文档说明。
- 删除原附件并上传新附件。
- 删除文档。

归属组织不可编辑。如需变更归属组织，本期不支持，应删除后在目标组织重新上传。

### 8.2 原附件展示

打开编辑弹窗时：

- 显示原附件名称和文件大小。
- 原附件右侧只显示“删除”按钮。
- 未删除原附件时，不显示新文件上传控件。

### 8.3 附件替换流程

1. 用户点击原附件右侧“删除”。
2. 原附件展示区域消失。
3. 页面提示“原附件已移除，请上传新文件后保存”。
4. 此时才显示新附件上传控件。
5. 用户选择新文件并保存。
6. 服务端成功保存新文件及文档信息后，再删除或异步清理旧文件。

`MUST`：删除原附件后未上传新文件时，禁止保存。

`MUST`：关闭或取消编辑弹窗时，不实际删除原附件。

`MUST`：附件删除在保存成功前仅是编辑会话状态，不得立即删除服务器原文件。

`MUST`：替换附件后更新文件名、文件大小、文件类型和更新时间。

`SHOULD`：替换附件失败时保留原附件，避免文档不可用。

## 9. 删除文档

- 只有上传者和系统管理员可删除。
- 删除前必须二次确认。
- 删除后文档不再出现在列表、搜索和组织数量中。
- 正式版本建议使用逻辑删除。
- 附件物理清理由后台任务异步执行。
- 删除操作必须记录审计日志。

## 10. 状态与异常处理

### 10.1 页面状态

| 状态 | 展示 |
|---|---|
| 加载中 | 列表骨架或加载提示 |
| 当前组织无文档 | “当前组织暂无文档” |
| 搜索无结果 | “当前条件下暂无文档” |
| 无查看权限 | 不返回文档数据 |
| 上传中 | 显示进度，禁用重复提交 |
| 预览转换中 | 显示转换状态，可稍后重试 |
| 预览失败 | 显示错误原因和下载入口 |

### 10.2 主要错误提示

| 场景 | 提示 |
|---|---|
| 未选择文件 | 请选择需要上传的文档 |
| 删除原附件后未上传新文件 | 删除原附件后，请上传新的附件 |
| 无编辑权限 | 仅文档上传者或管理员可以编辑 |
| 无组织上传权限 | 您无权向该组织上传文档 |
| 文件类型不允许 | 不支持该文件格式 |
| 文件超过限制 | 文件大小超过允许上限 |
| 预览失败 | 文件暂时无法预览，请下载后查看 |

## 11. 数据模型建议

### 11.1 知识库文档表 `knowledge_documents`

| 字段 | 类型建议 | 说明 |
|---|---|---|

| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |
| `deleted_at` | datetime nullable | 逻辑删除时间 |

### 11.2 文件表 `knowledge_files`

| 字段 | 类型建议 | 说明 |
|---|---|---|
| `id` | bigint / uuid | 主键 |
| `document_id` | bigint / uuid | 文档 ID |

| `deleted_at` | datetime nullable | 逻辑删除时间 |

本期一个文档只保留一个有效附件，但文件表独立设计，便于替换时安全切换文件记录。

### 11.3 审计日志表 `knowledge_audit_logs`

至少记录：

- 上传文档。
- 编辑文档信息。
- 替换附件。
- 删除文档。
- 管理员操作他人文档。
- 预览或下载敏感文档（是否全量记录见待确认事项）。

## 12. 接口建议

| 方法 | 路径建议 | 用途 |
|---|---|---|
| GET | `/api/knowledge/organizations` | 获取有权限的组织树及文档数量 |
| GET | `/api/knowledge/documents` | 按组织、分类、关键词查询文档 |
| POST | `/api/knowledge/documents` | 创建文档并绑定附件 |
| GET | `/api/knowledge/documents/{id}` | 获取文档详情 |
| PUT | `/api/knowledge/documents/{id}` | 编辑文档信息或替换附件 |
| DELETE | `/api/knowledge/documents/{id}` | 逻辑删除文档 |
| POST | `/api/knowledge/files/upload-init` | 初始化上传 |
| POST | `/api/knowledge/files/upload-complete` | 确认上传完成 |
| GET | `/api/knowledge/documents/{id}/preview` | 获取预览状态或鉴权地址 |
| GET | `/api/knowledge/documents/{id}/download` | 获取下载响应或短时地址 |

`MUST`：列表接口只返回当前用户有权查看的记录。

`MUST`：预览、下载、编辑和删除接口必须分别鉴权，不能因用户拿到文档 ID 就允许访问。

## 13. 服务端关键规则

1. 从登录会话获取当前用户，不接受前端提交上传人。
2. 根据组织数据权限校验上传目标组织。
3. 创建文档时，组织 ID 来自上传入口的当前组织上下文。
4. 编辑时禁止修改 `organization_id` 和 `uploader_user_id`。
5. 普通用户只能编辑、删除本人上传的文档。
6. 管理员操作他人文档时记录管理员身份和操作原因。
7. 预览和下载前重新计算查看权限。
8. 替换附件时先保存并校验新文件，再切换有效附件，最后清理旧文件。
9. 所有删除操作采用逻辑删除并记录审计日志。
10. 组织名称或员工姓名变化不影响历史上传记录的名称快照。

### 14.1 组织与列表

- [ ] 左侧展示真实组织树。
- [ ] 每个组织节点右侧显示正确的可见文档数。
- [ ] 父级组织数量包含本级及下级组织。
- [ ] 点击不同组织后，右侧列表与组织范围一致。
- [ ] 页面不出现三块额外汇总卡片。

### 14.2 上传

- [ ] 页面只有一个上传入口。
- [ ] 上传按钮文案包含当前组织名称。

## 15. 待确认事项

以下事项在进入正式 PHP/MySQL 开发前需要产品确认：

1. 普通员工可上传文档的组织范围：仅本人所属组织、本人所属组织及下级，还是由角色单独授权。
2. 单文件最大体积，以及不同文件类型是否设置不同上限。
3. 是否需要文档回收站和恢复功能。
4. 阅读次数是否对同一用户短时间重复访问去重。
5. 是否需要记录每次预览和下载的人员明细。
6. Office 文件采用自建转换服务还是第三方预览服务。
7. 是否允许 SVG、EXE 等高风险格式上传；如允许，病毒扫描和下载警告如何处理。
8. 组织删除或合并后，历史文档如何迁移和展示。

## 16. 当前前端原型边界

当前 React 页面已模拟：

- 组织树和组织文档数量。
- 按组织查看文档。
- 分类和关键词筛选。
- 上传到当前组织。
- 两种查看权限。
- 文件格式预览/下载分流。
- 上传者/管理员管理权限。
- 删除原附件后上传新附件。

当前尚未实现真实能力：

- PHP 接口和 MySQL 数据持久化。
- 对象存储和真实文件上传。
- 服务端权限校验。
- Office 文件真实转换预览。
- 文件病毒扫描。
- 短时下载地址。
- 审计日志。

正式上线不得将浏览器内存、Blob URL 或前端管理员标记视为安全实现。
