# 报价工作台：以步进条为核心的步骤指示、审批流转与侧边栏重构方案

> **核心指导原则**：
> **顶部的步进条（Steps）的核心使命是「指示与引导当前步骤」**。
> 工作台的主作业区、右侧辅助栏、以及审批动作体系，必须以步进条所指示的当前阶段为轴心，实现**层级清晰、阶段感知、职责互补**，彻底消除“重复出现、功能割裂、逻辑断层”。

---

## 一、 现状矛盾透析：为什么会出现重复与无法完全映射？

### 1. 结构与层级错位（步进条与侧边栏脱节）
目前报价工作台存在 **两套步进概念** 与 **两套操作入口**：
1. **顶层宏观步进条 (`ProcessOverview.steps`)**：
   - 规划了整个报价生命周期的 4 个大阶段：
     - **第 1 步：交付需求与功能清单**
     - **第 2 步：人天评估与研发工期**
     - **第 3 步：在线报价与商务增项**
     - **第 4 步：系统审批与盖章**
   - 它的作用本是指引用户“当前在哪个环节，下一步走向哪里”。
2. **底层硬编码挂载的右侧栏 (`ApprovalProcessPanel`)**：
   - 无论顶层步进条指示在第 1 步、第 2 步还是第 3 步，右侧栏都**无差别、常驻性地显示「审批流程」卡片**；
   - **阶段错配**：当用户在第 1 步录需求或第 2 步评估人天时，审批根本尚未启动，右侧栏强行展示一个待开始的审批卡片，不仅与顶部步进条指示的步骤完全背离，还挤占了表格排版宽度。
3. **主工作区与右侧栏的「动作与指示重复」**：
   - 当真正流转到第 4 步时：
     - **主工作区顶部**：有一套完整的审批指挥栏（显示黄奕、罗总、闵总、公章、成交等全生命周期节点，并提供带快捷评语的审批通过、驳回全员重审、盖章、发客、成交等全量动作）；
     - **右侧侧边栏**：又出现一个叫「审批流程」的卡片，里面也放着“同意并通过”“驳回报价”“盖章”，两套按钮功能重复，且右侧卡片缺少快捷评语库、无退回改清单、无成交战报与合同转化。

## 二、 重构目标：以「顶部步进条」为主轴的系统架构

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│  顶部宏观步进条 (ProcessOverview Steps)                                           │
│  [1.需求清单] ───► [2.人天评估] ───► [3.商务增项] ───► [4.审批盖章(当前阶段)]     │
│  ▲ 指示当前大阶段，引导流程流转                                                   │
└─────────────────────────────────────────┬────────────────────────────────────────┘
                                          │ 驱动视图与上下文联动
                    ┌─────────────────────┴─────────────────────┐
                    ▼                                           ▼
┌───────────────────────────────────────┐   ┌───────────────────────────────────────┐
│  主工作区 (ProcessWorkspaceMain)      │   │  右侧辅助栏 (ProcessWorkspaceAside)   │
│  【深度作业与决策操作中台】            │   │  【随步进条指示自适应切换的动态看板】 │
├───────────────────────────────────────┤   ├───────────────────────────────────────┤
│ • 若在 Step 1：需求与子功能树录入     │   │ • Step 1 上下文：需求完备度与模块速览 │
│ • 若在 Step 2：角色人天评估底表       │   │ • Step 2 上下文：人天工期总览与角色比 │
│ • 若在 Step 3：商务增项与阶梯定价     │   │ • Step 3 上下文：价格测算与利润率预警 │
│ • 若在 Step 4：正式公函审阅与审批盖章 │   │ • Step 4 上下文：【审批链路与审计看板】│
│   (权威唯一的操作中心，杜绝两套按钮)   │   │   - 纯只读会签进展，全生命周期映射    │
│                                       │   │   - 历次批语履历气泡，消除双重操作    │
└───────────────────────────────────────┘   └───────────────────────────────────────┘
```

### 1. 步进条的核心职责强化
- **宏观指示**：清楚标记 1 ➔ 2 ➔ 3 ➔ 4 的前进轨迹；
- **状态引导（Step Guide）**：
  - 在第 4 步「系统审批与盖章」，根据底层单据状态动态显示微观进展标签（如：`第 4 步：系统审批与盖章 (会签审批中)` 或 `(待加盖公章)`、`(已确认成交)`）；
  - 让用户抬头看步进条，就能一眼知道当前单据在全局处在什么节点、当前卡在谁手中。

### 2. 侧边栏随步进条自适应（Stage-Adaptive Aside）
彻底抛弃“无论哪一步右侧都挂着审批卡片”的粗暴设计，让右侧栏真正成为**当前步骤的得力助手**：
- **当处于 Step 1（交付需求与功能清单）**：
  - 右侧栏展示：`【报价动态】` + `【需求结构看板】`（模块数、端类型分布、功能完整性，提示下一步将流转架构师评估）。
- **当处于 Step 2（人天评估与研发工期）**：
  - 右侧栏展示：`【报价动态】` + `【评估工期看板】`（技术总人天、预计工期、工时基线对齐）。
- **当处于 Step 3（在线报价与商务增项）**：
  - 右侧栏展示：`【商务利润测算】`（总报价、毛利率、付款阶段分布、合规风险检查）。
- **当流转到 Step 4（系统审批与盖章）**：
  - **右侧栏承载「审批链路全景看板与审计履历」**：
    - 作为宏观步进条中第 4 步的**细化微观展开**；
    - **全面剥离操作按钮**（消灭重复！所有的同意、驳回、盖章等权威操作留在主工作区，避免双头操作）；
    - 呈现完整的 7 大状态映射（草稿 ➔ 待审 ➔ 驳回 ➔ 待盖章 ➔ 已盖章 ➔ 发送客户 ➔ 客户成交）；
    - 呈现各审批人的批注气泡、审批时间戳与等待倒计时；若当前用户是待办人，只提供一个微型的“当前等待您处理 ➔ 锚点指引”。

## 三、 详细改善落地方案

### 维度 1：顶层步进条的动态引导增强
在 `QuotationWorkbench.tsx` 中，让 `ProcessOverview` 的 steps 根据实际状态提供上下文引导：
```tsx
const stepsConfig = useMemo(() => {
  return STAGES.map((s) => {
    let desc: string | undefined;
    if (s === 4) {
      if (quote.status === 'auditing') desc = '三人会签审核中';
      else if (quote.status === 'pending_stamp') desc = '待加盖企业公章';
      else if (quote.status === 'stamped') desc = '已盖章 · 待发送客户';
      else if (quote.status === 'sent') desc = '已发出 · 跟进成交中';
      else if (quote.status === 'confirmed') desc = '客户确认成交 · 已达成';
      else if (quote.status === 'rejected') desc = '已驳回 · 待修改';
      else desc = '审批与盖章';
    }
    return {
      key: String(s),
      title: flowStageNames[s],
      description: desc,
    };
  });
}, [quote.status, flowStageNames]);
```
- **效果**：步进条不仅能指引步骤，还能清晰显示步骤当前的微观进展，引导力大幅提升。

### 维度 2：右侧栏阶段化重构（消除阶段错配）
将侧边栏按当前步骤拆分：
- **`StageAsideOverview`**（通用信息：客户名、当前阶段、总报价）；
- **根据当前 `stage` 渲染对应的步骤辅助面板**：
  - `stage === 1` ➔ 显示功能梳理指标与交付指引；
  - `stage === 2` ➔ 显示研发人天结构与工期核算；
  - `stage === 3` ➔ 显示商务毛利风控与回款计划；
  - `stage === 4` ➔ 显示 **`AuditTrackingTimeline`（审批流转时间线与全景审计看板）**。

### 维度 3：审批流程看板的 100% 状态映射与纯读化
重构 `ApprovalProcessPanel` ➔ 升级为 **`AuditTrackingTimeline`**：
1. **去除内部所有操作表单**（移除 `handleApprove`, `handleReject`, `handleStamp` 及其内嵌的文本框和按钮）；
2. **完整映射 7 大状态**：
   - 节点 1：销售提交（发起人、提交时间）；
   - 节点 2~4：会签审批人（销售主管、技术总监、财务决策人；通过显示绿勾 + 批语；驳回显示红叉 + 驳回理由；当前处理人显示呼吸高亮）；
   - 节点 5：印章管理（印章管理员、盖章状态、加盖时间）；
   - 节点 6：商务流转（已发送客户时间、客户确认成交或作废时间）；
3. **主从中台协作**：主作业区负责执行动作，右侧时间线负责实时同步反馈，动静各司其职。

## 四、 改造带来的核心收益

1. **认知负担骤降**：用户不会再看到“顶部一个审批，右侧又一个审批，主界面里还有一个审批”的三重困扰；
2. **步进条引导力倍增**：顶部步进条成为工作台的绝对导航核心，指示宏观大步，右侧栏联动指示微观要点；
3. **100% 状态机映射**：无论报价单走到“会签”、“待盖章”、“已发送”还是“已成交”，步进条与侧边栏都保持高度一致的步调；
4. **空间利用最大化**：前 3 步不再被空白的审批卡片占据空间，第 4 步操作集中在主视线区，公函审阅更加舒展从容。
