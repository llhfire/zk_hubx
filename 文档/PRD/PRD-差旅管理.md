## 一、模块概述

差旅管理是一级菜单（key: `travel`），覆盖**差旅核心链：出差单 -> 费用 -> 报销 -> 借款冲抵 -> 补贴**，外加宿舍与费用标准。归属财务域（看板/架构图与运营费用、成本核算相邻）。本轮范围：核心链细则收口 + 跨域接缝 + mock 充实；宿舍只做口径收口；**打卡模块整体删除**（考勤留给未来工时加工体系）。

## 二、核心链规则

### 2.1 出差单（Trip）
- 状态机沿用现有 8 态：草稿/待审批/已通过/进行中/待报销/已关闭/已拒绝/已取消。
- **关联对象必选其一**（ADR-0089）：交付期出差挂**项目**、售前出差挂**线索**；客户从所选项目/线索带出。费用归集方向随之分流：挂项目 -> 项目成本；挂线索 -> 线索商务成本。不进公共运营池。
- 费用预估按四类填（交通/住宿/餐饮/其他），作为借款额度参考。

### 2.2 审批流（固定骨架 + 金额分级）
- 出差单：部门主管 -> 财务，固定两级。
- 报销单：部门主管 -> 财务，固定两级；**财务审批通过 = 确认入账时点**（运营费用 ADR 既有决策）。
- 借款单：金额分级（≤阈值部门主管终审；>阈值部门主管 -> 财务）。阈值放系统配置。
- 节点人从组织域角色解析（部门主管/财务岗），不手写。
- 可配置审批引擎（节点/会签/条件分支）列入看板 planned，本轮不做。

### 2.3 超标处理（硬软分档）
- **交通席别 = 硬标准**：超席位（高铁二等买一等、经济舱买商务舱）自付差额，系统按标准价自动折算。
- **住宿 = 软标准**：超 `hotelLimit` 须填超标原因，部门主管 + 财务看到超标标后决定全报/部分报。
- **餐饮不实报**：按补贴包干发（见 2.5），餐票只作附件。
- 城市等级统一一套（一线/二线/三线/其他），维护在费用标准里，全部实现统一引用。

### 2.4 报销与借款冲抵
- 报销明细从出差单费用记录带出，交通/住宿实报，餐饮不入实报项。
- **借款冲抵**：报销财务审批通过后，自动按**最早未结借款优先**顺序冲抵；余额退补员工；借款未冲完部分挂账，待下次报销继续冲或退款结清。
- 借款状态机沿用：草稿/待审批/已通过/已打款/已冲抵/已结清/已拒绝/已取消。

### 2.5 出差补贴（单一包干）
- 餐饮/杂费/通讯合并为**一个「出差补贴」**，按城市分级（金额维护在费用标准里），`mealAllowance`/`communicationAllowance` 等字段废弃并入。
- **按自然日计，不含出发日与返回日**：补贴天数 = 出差自然日 − 出发日 − 返回日。
- `calcMode` 收敛为自然日一种（working_day 废弃）；随当月工资发放（联动工资表发放月）。

### 2.6 报销双出口（归集源）
财务审批通过即触发：
1. **运营费用台账只读入账**：TRAVEL 科目，挂对应项目/线索；本模块是归集源，运营费用不另录一笔。
2. **项目/线索成本流水**：挂项目的生成项目成本流水（对接精益交付成本链 R3 报销通道）。

本轮在 mock 层对齐 + 出口函数留接口，真实接缝随后端阶段接。

## 三、宿舍管理（口径收口，不展开新功能）
- 宿舍模块管实物：楼/层/房/床、入住/退住（长期 + 出差入住）、维修。
- **宿舍费用账本留在宿舍模块**（ADR-0090）：租金/水电/燃气/网络在 `DormitoryExpense`/`UtilityPayment` 记账，是这类费用的**唯一写入方**；运营费用台账对宿舍租金科目**只读引用合计**，不重复记。

## 四、打卡模块：删除
- 页面/路由（`/travel/punch`）/菜单项/`PunchRecord`/`PunchRule`/`TemporaryZone` 类型与 mock、travel-api 打卡函数全部移除。
- 出差打卡需求（驻场定位）由未来工时加工/考勤体系承接，不在本模块保留。

## 五、数据与实现口径
- 员工/部门统一接组织域员工 mock，不自造人名体系；`cust-xxx`/`proj-xxx` 引用真实客户域/项目域 ID。
- mock 充实：宿舍楼/床位/入住记录、多状态报销/借款样例，保证看板有数。
- **类型护栏**：travel mock 加类型一致性单测（mock 结构必须匹配 types.ts），防止再脱节（现状 `mockPunchRule`/`mockExpenseStandards` 已脱节）。
- 费用标准结构按 types.ts 的 `ExpenseStandard`（版本 + 生效期 + 职级 × 城市等级明细）重造 mock，`TravelRuleEngine` 的城市分级改引用统一城市等级。
- OCR 列 planned（演示件保留）；合规指南随费用标准数据走；财务审计看板从 travel-api 派生。

## 六、权限
员工提单；部门主管一审；财务终审 + 打款 + 入账；管理层看差旅看板。具体矩阵编码时按角色表落。

## 七、不做（本轮）
可配置审批引擎、真实 OCR、打卡/考勤、宿舍新功能、真实后端接入、多币种。
