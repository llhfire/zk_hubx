- 资源域：`/assets`、`/maintenance`、`/suppliers`、`/travel/dormitory`

切换行为另外点了三处验证：`/todos`（待处理 6 ↔ 已完成 1）、`/approvals`（全部审批 5）、
`/finance/contract-cost/1`（科研成本 ↔ 差旅成本）。

### 三处「看似异常」其实是数据不是 bug

`/customers/1`、`/quotation/1`、`/smart-meetings/1` 进页面显示「未找到」/近乎空白：
种子数据的 id 不是 1。按列表真实 id（`/customers/customer-pawkey`）进去，页签齐全、渲染正常。

### 视觉差异（预期内）

- `type="card"` / `card-gutter` → `variant="card"`：卡片式的 page tab，间距略收紧，语义与层级不变。
- 分段筛选的数量徽标：原来是有色填充胶囊（含 `#fff` 白字），现在是同色系文字，样式统一到页签计数。
- 页签计数从标题内联 `全部（12）` 变成 label + count 徽标，文字朗读空格略有差异。

## 环境噪声

机器 load average 一度到 **140+**，`npm test` 默认并发下 `KnowledgeBase` 的上传用例会
5s 超时偶发失败（该文件与本次改动无关，单跑 9/9 通过）。稳定跑法：

```bash
npm test -- --maxWorkers=2 --testTimeout=20000
```

## 遗留

1. `SectionTabs` 的「分段筛选」用法（`variant="card"` + count）目前承担了筛选语义。
   如果以后要区分「分区」与「筛选」，再补一个语义更准的筛选组件；现在它已经不再是绕开设计系统的问题。
2. `/ui-library` 的「页面框架」与「业务样板」用假数据，随产品结构调整需要同步更新 ——
   这次已经把「骨架不是页面」和「复制边界」写进页面，改动时照那个口径改。
3. 严格门禁剩余 40 条例外仍是下一批迁移对象（Recharts 图表适配层、22 处原生控件）。
