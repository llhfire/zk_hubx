# 功能看板 α 版本信息与已有功能详情设计

## 背景

功能看板当前将“页面场景 / 功能流程 / UX 优化”三个 checkbox 放在模块级 α 列，并在待设计功能上显示状态圆点与删除按钮。已有功能详情弹窗只有文字说明。需要把 α 完成度维护下沉到具体已有功能，同时简化 α 版本列为版本更新概况。

## 已确认需求

### 待设计功能

- 删除按钮默认隐藏。
- 鼠标悬停在待设计功能标题行时显示删除按钮。
- `未开始` 状态不显示小圆点。
- 其他状态仍显示状态圆点，并可点击切换状态。

### 已有功能详情

- 点击已有功能打开详情弹窗。
- 弹窗保留功能说明。
- 弹窗显示三个可手动维护的 checkbox：页面场景、功能流程、UX 优化。
- 三个 checkbox 独立归属于每个已有功能，不再使用模块级字段作为展示来源。
- checkbox 修改即时保存，但不计入 α 版本更新次数。

### α 版本列

- 删除模块级三个 checkbox 展示。
- 改为显示 α 版本整体更新次数和最近更新日期。
- α 版本相关看板更新通过显式 changeType 累计：已有功能说明/功能项变化和 α 更新元数据变化计数并更新日期。
- 待设计功能、β 开关/状态、备注变化不计入 α 更新次数。
- 无记录显示“暂无更新记录”。

## 数据模型

`ExistingFeature` 增加：

```ts
alpha: {
  页面场景: boolean;
  功能流程: boolean;
  UX 优化: boolean;
}
```

`FeatureBoard` 增加版本级元数据：

```ts
alphaMeta: {
  updateCount: number;
  lastUpdatedAt: string;
}
```

现有模块级 `alpha` 字段保留用于旧数据迁移兼容，但不再作为 UI 展示或已有功能详情的事实源。旧已有功能缺少 `alpha` 时补全为三个 false；缺少 `alphaMeta` 时补全为 0 和空日期。

## 保存与计数

由保存调用方显式传递变更类型：`alpha | planned | beta | note | checklist`。只有 `alpha` 变更会更新 `alphaMeta`，并由统一函数把次数加一、日期更新为当前本地日期。已有功能详情 checkbox 使用 `checklist`，不计入版本更新次数。保存层对次数和日期做归一化，禁止负数和非法日期。

## 组件交互

- `VersionCompareModal` 保持看板主体和详情弹窗职责。
- 已有功能详情状态扩展为可编辑对象；三个 Checkbox 通过 `toggleFeatureAlphaCheck` 纯函数更新对应模块/功能。
- 待设计条目包装为可悬停行，删除按钮由 CSS 默认隐藏、行悬停显示；状态为 `未开始` 时不渲染状态 Dropdown/圆点。
- α 列渲染 `alphaMeta.updateCount` 与 `alphaMeta.lastUpdatedAt`，不再渲染 `ALPHA_CHECK_KEYS`。

## 验证

- 增加/更新模型纯函数测试：旧数据迁移、功能级 checkbox 切换、α 更新元数据累计、未开始状态展示口径所需数据。
- UI 手工验证：待设计标题悬停显示删除；未开始无圆点；已有功能弹窗三个 checkbox 可独立保存；α 列显示次数/日期。
- 执行现有相关 Vitest 与 `npm run build`。

## 不做

- 不删除旧模块级 `alpha` 字段的兼容读取。
- 不把 checkbox 勾选计入版本更新次数。
- 不将 Git commit 数量作为 α 更新次数。
- 不改变 β 开关、待设计状态机和备注编辑规则。
