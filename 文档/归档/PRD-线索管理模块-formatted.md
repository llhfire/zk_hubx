## 2. 目标与范围

### 2.1 业务目标

1. 集中记录线索来源、客户需求、归属关系及每次业务推进过程。
2. 让销售/售前可在线完成跟进、报价、合同版本及附件管理。
3. 在合同审批完成后，将合同信息、回款与发票信息沉淀到该线索下。
4. 已成交线索以项目详情作为后续交付入口，避免线索与项目双处维护。

### 2.2 本期范围

* 线索列表、筛选、进入详情与线索流转。
* 线索详情基础信息、跟进、报价、合同记录、演示、资料、出差、报销。
* 合同审批通过后的合同信息、回款与发票展示及维护。
* 线索与报价、合同、附件、项目之间的关联规则。

## 3. 核心业务规则

1. 一个线索只能关联一个合同；合同可以包含多个版本。
2. 一条报价记录代表一次完整报价快照。新增报价或编辑报价均生成新记录，不覆盖历史记录。
3. 报价记录、合同版本按创建/更新时间倒序展示，最新记录置顶；默认均收起详情。
4. 报价和合同审批均采用“总经理”单节点审批：提交后为“总经理审批中”，同意后审批完成，拒绝后为已驳回。
5. 只有最新报价记录可编辑或提交审批；历史报价仅可查看。
6. 只有最新合同版本可编辑或提交审批；历史版本不显示编辑、提交审批及未提交审批标签。
7. 合同审批完成后，线索详情才显示“合同信息”和“回款与发票”主Tab；审批未完成时隐藏这两个Tab。
8. 已成交线索从列表点击线索名称或“详情”后，统一跳转项目详情；后续合同、回款及交付信息在项目详情维护。
9. 资料 Tab 是该线索所有文件的统一入口，列出该线索相关的所有文件，并支持在这里上传新文件，同一文件被多个业务模块引用时只展示一条，并标识来源。
10. 字段无值时统一显示  `-` ；不可因空值导致布局错位或隐藏字段标题。

## 4. 菜单与页面

| 菜单    | 页面定位           | 主要操作                   |
| ----- | -------------- | ---------------------- |
| 公海线索  | 未认领或可分配的线索池    | 查看详情、认领、编辑、转给他人、标记垃圾线索 |
| 我的线索  | 当前用户负责的线索      | 查看详情、编辑、转移、扔回公海、标记垃圾线索 |
| 已成交线索 | 已签约、已立项或回款中的线索 | 查看线索关联项目，跳转项目详情        |
| 垃圾线索  | 被判定为低价值/无效的线索  | 编辑、转给他人、扔回公海           |
| 线索治理  | 线索质量和治理规则入口    | 按独立治理需求实现              |

### 4.1 列表通用要求

1. 列表支持关键词检索和状态筛选；关键词至少覆盖线索名称、客户名称、联系人、联系电话、来源、归属人及关联项目/合同编号（已成交列表）。
2. 线索名称应为可点击入口；普通线索进入线索详情，已成交线索进入项目详情。
3. 列表状态、金额及日期使用统一展示格式；金额显示人民币千分位，日期显示  `YYYY-MM-DD` 。
4. 线索详情路由需携带来源标识（如  `from=my/public/trash` ），用于返回原列表和展示对应操作按钮。

## 5. 线索详情

### 5.1 页面布局与操作

页面采用左右两栏，比例为  **6:4** 。

* 左上：返回按钮、按来源显示的线索操作按钮、线索关键信息。
* 左下：主 Tab，包括基础信息、合同信息、回款与发票。
* 右侧：业务过程 Tab，包括跟进、报价、合同记录、演示、资料、出差、报销。
* 主 Tab 与右侧 Tab 均位于独立白色背景容器中。

来源对应操作：

| 来源   | 可用操作                |
| ---- | ------------------- |
| 我的线索 | 编辑、转移给他人、扔回公海、标记为垃圾 |
| 公海线索 | 认领、编辑、转给他人、标记为垃圾    |
| 垃圾线索 | 编辑、转给他人、扔回公海        |

### 5.2 顶部线索关键信息

顶部操作按钮下方显示分割线、线索名称及以下信息。除“初始信息及需求”外，字段两列排列；“初始信息及需求”独占一行。

| 字段            | 说明                     |
| ------------- | ---------------------- |
| 线索名称          | 标题形式展示，格式为  `【线索名称】` 。 |
| 线索来源          | 来源渠道。                  |
| 客资成本          | 当前线索的获客成本。             |
| 客户称呼          | 对接人的称呼。                |
| 联系电话/微信       | 电话和微信去重后组合展示。          |
| 创建人 / 优化师     | 线索创建人与投放/优化负责人。        |
| 归属人 / 协助人     | 当前负责人和协作人员。            |
| 初始信息及需求       | 线索初始描述或客户需求，优先展示完整需求。  |
| 创建时间 / 下次跟进时间 | 用于判断线索时效。              |

当线索逾期未跟进且没有新的跟进记录时，显示醒目的待跟进提醒。

### 5.3 基础信息 Tab

基础信息以两列“字段名：字段值”展示，字段如下：

| 左列           | 右列           |
| ------------ | ------------ |
| 对接主体         | 线索意向         |
| 线索状态         | 客户类型         |
| 客户预算         | 客户主体         |
| 售前群名称        | 原型图链接（可外部打开） |
| 威客 ID        | 威客任务编号       |
| 推广关键词        | 意向标签（多标签）    |
| 客户信息备注（独占一行） |              |

基础信息底部展示“客户主体信息”，支持绑定客户主体；绑定后展示主体名称、主体全称、通讯地址、公司电话、电子邮箱。

### 5.4 合同信息 Tab

显示条件：存在该线索关联的、审批通过且未作废的合同。

内容：

1. 顶部展示合同名称、履行状态、版本号、签约人及合同金额。
2. 左右两列展示合同主要信息：合同编号、签约主体、产品类别、付款方式、签约日期、审批通过时间；公司名称、客户税务登记号、联系人、联系电话、电子邮箱、通讯地址、邮政编码、开户银行\*账号。
3. 下方展示最终合同文件，提供“预览”和“下载”操作。
4. 未满足显示条件时，整个 Tab 不显示。

### 5.5 回款与发票 Tab

显示条件与合同信息 Tab 一致。回款数据来自已审批通过的合同回款计划。

#### 5.5.1 列表

列表默认不展示历史明细，列为：

| 列    | 规则                                                              |
| ---- | --------------------------------------------------------------- |
| 期次   | 显示“第 N 期”；如已拆分，父级显示“已拆分”，子项以“第 N 期-1 / 第 N 期-2”层级展示，子项使用浅色背景区分。 |
| 应回款  | 显示应回款金额，下方显示“预计日期：YYYY-MM-DD”。                                  |
| 回款条件 | 该期的回款前提。                                                        |
| 实际回款 | 显示累计实际回款金额，下方显示最后回款日期。                                          |
| 操作   | 回款状态、开票状态、拆分、附件。                                                |

父期已拆分后保留父级记录，父级仅显示汇总状态，不可录入回款/开票；父级仍可“拆分”以编辑拆分情况。已拆分的子项不支持再次拆分。

状态规则：

* 回款状态：未回款、部分回款、已回款；已过预计日期且未完成时可额外显示已逾期。
* 开票状态：未开票、部分开票、已开票。
* 状态按该期所有回款/开票明细的累计金额自动计算，不允许手工修改。

#### 5.5.2 回款、开票与附件

1. 点击未回款/部分回款状态，打开“填写回款信息”弹窗，先提示“请确认是否已回款，若已回款请提交回款信息”。字段为回款金额、回款日期、回款方式、回款凭证、回款说明；提交后立即生效。
2. 点击已回款状态，打开只读回款信息，可查看回款金额、日期、方式、凭证及说明；凭证支持下载。
3. 点击未开票/部分开票状态，打开“填写开票信息”弹窗，字段为开票日期、开票金额、发票类型、发票抬头、发票文件、备注信息；提交后立即生效。
4. 点击已开票状态，打开只读开票信息，发票文件支持预览和下载。
5. 单次新增或编辑的回款金额不得超过该期剩余可登记回款金额；开票金额同理，不得超过该期剩余可登记开票金额。
6. 点击“附件”打开附件列表（表格展示），支持新增。新增字段为附件类型、说明、附件文件；附件类型包含回款凭证、发票、原型确认书、UI 确认书、需求变更确认书、增项确认书、验收单、其他。附件文件支持下载。

#### 5.5.3 拆分回款期次

1. 点击父期“拆分”，默认生成两条子记录，每条使用虚线容器展示；最后一条下方提供居中的“新增记录”按钮，按钮外层为占满整行的虚线框。
2. 每个子记录的“回款金额”和“预计回款日期”同一行，左金额、右日期；另填写回款条件。
3. 子项金额合计必须等于父期应回款金额，才可提交。
4. 提交后保留父期，并新增对应子项；父期状态按所有子项的汇总结果计算。

## 6. 业务过程 Tab

### 6.1 跟进

跟现有系统一致

### 6.2 报价

#### 6.2.1 模块范围

本模块包含以下能力：

1. 新增报价及编辑最新报价。
2. 报价系统配置、实时成本计算和报价汇总。
3. 完善报价资料并生成一条报价版本记录。
4. 报价历史查看、展开明细、附件预览和下载。
5. 技术评估文件、报价单补传。
6. 总经理单节点审批及审批意见留痕。
7. 报价附件自动归集至该线索的“资料”Tab。

#### 6.2.2 核心业务规则

1. 一条报价记录代表一次完整报价快照；新增报价或编辑报价均生成新记录，不覆盖历史记录。
2. 报价记录按创建时间倒序展示，最新报价置顶；列表默认收起详情。
3. 只有最新报价可编辑、补传审批附件或提交审批；历史报价只可查看。
4. 编辑最新报价时，读取该报价原有的报价系统配置；提交后生成一条新的报价记录并成为最新报价。
5. 报价审批为“总经理”单节点：提交后显示“总经理审批中”，同意后为“已审核”，拒绝后为“已驳回”。
6. 技术评估文件和报价单均已上传后，才允许提交审批。
7. 报价汇总图片在报价资料提交时生成，并与该报价记录关联；报价系统文件不在报价详情中展示。
8. 任何由报价模块上传或生成的文件，都必须自动归集到该线索的“资料”Tab，并保留来源为“报价”。

#### 6.2.3 报价记录列表

##### 6.2.3.1 报价历史区域

* 标题： `报价历史`
* 标题右侧： `共 N 条`
* 右上角按钮： `新增报价`
* 空状态： `暂无报价记录`

每条报价记录包含：

| 区域   | 内容                                      |
| ---- | --------------------------------------- |
| 标题   | 报价名称；最新一条额外显示“最新报价”标签。                  |
| 状态   | 报价状态、审批状态。                              |
| 核心信息 | 报价金额、创建时间、报价人。                          |
| 操作区  | 左侧放当前记录可执行的操作，右侧固定为“展开详情 / 收起详情”。       |
| 展开详情 | 预计周期、技术评估人、报价说明、报价汇总图片、技术评估文件、报价单、审批记录。 |

展示要求：

1. “预计周期、技术评估人、报价说明”置于报价汇总图片上方。
2. 报价汇总图片、技术评估文件、报价单归为同一附件区域，每项独占一行，标题、文件名、预览/下载操作对齐。
3. 技术评估文件和报价单未上传时，展开详情中不显示对应行。
4. 文件名可点击预览；下载使用下载图标。
5. 审批记录为空时，不显示审批记录区域。

##### 6.2.3.2 状态与操作

| 审批状态          | 最新报价可见操作                      | 历史报价可见操作 |
| ------------- | ----------------------------- | -------- |
| 未提交审批，缺技术评估文件 | 上传技术评估文件；如同时缺报价单，也显示上传报价单。    | 展开详情。    |
| 未提交审批，缺报价单    | 上传报价单；如同时缺技术评估文件，也显示上传技术评估文件。 | 展开详情。    |
| 未提交审批，附件齐全    | 编辑、提交审批。                      | 展开详情。    |
| 总经理审批中        | 编辑、审批同意、审批拒绝。                 | 展开详情。    |
| 已审核           | 展开详情。                         | 展开详情。    |
| 已驳回           | 展开详情。                         | 展开详情。    |

说明：

* “提交审批”仅在技术评估文件和报价单均存在时显示。
* “同意”“拒绝”均需先弹出审批意见输入框，意见为必填。
* “编辑”不会原地修改当前记录，而是创建新的报价版本。

上传技术评估文件、上传报价单格式要求：pdf/doc/docx/xls/xlsx/png/jpeg/jpg
报价系统记录生成的图片文件命名规则为：`[系统名称]报价单+YYYYMMDD+时间戳后6位.png`。

#### 6.2.4 新增与编辑报价

##### 6.2.4.1 报价系统

点击“新增报价”后，第一步打开标题为“报价系统”的弹窗。报价系统由六个步骤组成：

1. 前端配置
2. 后端配置
3. 其他岗位
4. 出差驻场
5. 其他成本
6. 报价汇总

弹窗底部固定提供： `取消` 、 `上一步` 、 `下一步` 。在报价汇总页点击“下一步”前，项目总报价必须大于 0。

顶部持续展示四项实时汇总：人力成本、差旅与驻场、其他成本、报价总额。

###### 6.2.4.1.1 前端配置

副文本： `选择前端平台，每个平台可添加多个角色端（如用户端、商家端），并选择开发语言` 。

| 配置项     | 规则                                                                                                                               |
| ------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 前端平台    | 微信小程序、支付宝小程序、抖音小程序、iOS APP、Android APP、鸿蒙 APP、H5 移动端、PC Web 端、桌面应用、iPad 端、Android 平板端。                                           |
| 选择方式    | 平台列表每行展示 6 项；每一项的标题与右侧勾选框同行、两端对齐。                                                                                                |
| 角色端     | 勾选平台后默认生成一条角色端，可继续新增多个角色端，例如用户端、商家端、司机端、配送端。                                                                                     |
| 每个角色端字段 | 角色名称、开发语言/框架、人数、天数、日均成本、小计。                                                                                                      |
| 默认技术栈   | 小程序支持原生开发、Taro、Uni-app；移动端/平板端按平台支持 Swift、Kotlin、Java、React Native、Flutter、ArkTS；Web 支持 Vue、React、Angular；桌面应用支持 Electron、Tauri。 |
| 自定义技术栈  | 技术栈列表最后一项为“自定义”；仅勾选“自定义”后展示自定义技术栈名称和日均成本输入项。                                                                                     |

###### 6.2.4.1.2 后端配置

副文本： `选择后端服务和数据库技术栈，可添加自定义开发语言` 。

| 配置项    | 规则                                                                                                                                                                                   |

###### 6.2.4.1.6 报价汇总

报价汇总页实时展示：

1. 总人天、总人数、预计工期、项目总报价。
2. 人力成本明细。
3. 出差驻场成本明细。
4. 其他成本明细。
5. 大字号“项目总报价”金额。
6. 人力、差旅、其他成本占项目总报价的百分比。

计算规则：

| 项目     | 计算方式                                   |
| ------ | -------------------------------------- |
| 单条人力成本 | 人数 × 天数 × 日均成本。                        |
| 出差交通费  | 单程交通费 × 2 × 出差人数 × 出差次数。               |
| 出差住宿费  | 住宿费 × 每次天数 × 出差人数 × 出差次数。              |
| 出差补贴   | （餐饮补贴 + 其他补贴）× 每次天数 × 出差人数 × 出差次数。     |
| 驻场住宿费  | 月住宿费 × 驻场人数 × 向上取整（驻场天数 / 30）。         |
| 驻场餐饮补贴 | 餐饮补贴 × 驻场天数 × 驻场人数。                    |
| 驻场交通补贴 | 月交通补贴 × 驻场人数 × 向上取整（驻场天数 / 30）。        |
| 销售提成   | （人力成本 + 出差成本 + 驻场成本 + 固定其他成本）× 销售提成比例。 |
| 项目总报价  | 人力成本 + 出差成本 + 驻场成本 + 其他成本。             |

##### 6.2.4.2 完善报价资料

从报价汇总点击“下一步”后，打开“完善报价资料”弹窗。

| 字段    | 控件与来源    | 规则                                                                                 |
| ----- | -------- | ---------------------------------------------------------------------------------- |
| 报价金额  | 金额输入框    | 默认带入项目总报价；必填，可按业务实际调整。                                                             |
| 报价人   | 员工下拉列表   | 从员工列表读取；必填；新增报价时默认选择当前登录用户，支持手动修改。                                                 |
| 预计周期  | 文本输入框    | 必填；仅允许输入正整数，输入框最右侧固定显示“天”，右侧间距 10px；默认带入报价汇总的预计天数。最大支持输入 3650 天，超过给出提示“周期输入超限，请检查” |
| 技术评估人 | 人员多选下拉列表 | 必填；从员工列表读取，支持选择多位人员并以“、”展示。                                                        |
| 报价信息  | 报价汇总表格   | 展示本次报价系统的总人天、总人数、预计工期、项目总报价及三类成本明细。                                                |
| 报价说明  | 多行文本框    | 最多 500 字。                                                                          |

以下字段不在“完善报价资料”弹窗中展示：报价系统文件、技术评估文件、报价单。

点击“提交”后：

1. 保存报价系统配置快照、报价汇总结果和报价资料。
2. 生成报价系统记录并关联到该报价记录，文件名为 `[系统名称]报价单YYYYMMDD+时间戳后6位.png` 。
3. 新增一条审批状态为“未提交审批”的报价记录。
4. 如果为编辑场景，旧记录保持不变，新记录成为最新报价。

##### 6.2.4.3 附件与预览

| 附件     | 产生方式                                              | 展示位置       | 操作           |
| ------ | ------------------------------------------------- | ---------- | ------------ |
| 报价系统记录 | 提交报价资料时自动生成。文件名为 `[系统名称]报价单YYYYMMDD+时间戳后6位.png` 。 | 展开详情的附件区域。 | 打开链接、下载。     |
| 技术评估文件 | 报价记录创建后由最新记录补传。                                   | 有文件时展示。    | 文件名预览、下载、删除。 |
| 报价单    | 报价记录创建后由最新记录补传。                                   | 有文件时展示。    | 文件名预览、下载、删除。 |

文件规则：

1. 报价系统文件不在展开详情中展示。
2. 最新报价缺少技术评估文件或报价单时，操作区显示对应的上传按钮；上传后立即更新记录状态。
3. 技术评估文件/报价单文件支持 PDF、DOC、DOCX、XLS、XLSX、ZIP、RAR、PNG、JPEG、JPG；
4. PDF、图片可在线预览；其他格式可接入在线预览，无法预览时保留下载入口。
5. 文件上传、报价系统记录生成后，需要自动写入该线索“资料”Tab 的统一文件索引，来源标签为“报价”。

### 6.3 合同记录

#### 6.3.1 无合同状态

1. 首先显示“合同归档”区域；未审批完成时提示“合同审批通过并形成终稿后可上传归档”。
2. 合同记录为空时，在内容右上角显示“创建合同”按钮。
3. 点击创建合同进入新建合同流程，自动带入当前线索信息；如存在已审核报价，可带入对应报价信息，但不得因没有审批通过报价而阻断创建。

#### 6.3.2 有合同状态

1. 创建合同后，隐藏“创建合同”，展示“合同历史记录”。
2. 合同版本按倒序展示；最新版本标识“最新版本”。
3. 每个版本展示：版本号、修改内容、修改时间、修改人、合同附件和审批状态。
4. 合同附件支持预览和下载；仅在该版本存在审批记录时显示“展开详情 / 收起详情”，展开后只展示审批记录，不重复展示修改内容和附件。
5. 仅最新版本显示“编辑”和“提交审批”；审批中时显示“审批同意”“审批拒绝”，审批操作须填写审批意见。
6. 对审批中的版本创建新版本时，需提示当前审批将撤回；确认后新版本成为最新版本。
7. 合同审批通过后显示合同归档区域，支持上传 PDF、DOC、DOCX 归档文件、预览和下载。归档附件与普通版本附件分开管理。

### 6.4 演示

1. 演示用于记录可访问的交付/演示网址，不承载线索全部上传文件。
2. 新增演示包含演示类型（手动输入）、演示文件、说明；一个记录支持添加多组演示类型和文件。
3. 每组演示文件中 HTML 为必传，CSS、JS 可选；系统上传后生成可复制的网址。
4. 列表仅展示演示类型、网址、说明、上传人和上传时间，不展示 HTML/CSS/JS 文件名。

### 6.5 资料

1. 资料是该线索的统一文件库，展示所有与线索关联的上传文件。
2. 文件来源包括跟进、报价、合同版本/归档、回款、发票、出差、报销、演示及手工上传资料。
3. 同一文件被多个模块引用时仅展示一条，显示全部来源标签。
4. 支持手工上传资料、列表展示、预览和下载；按文件类型、来源、上传人、上传时间等信息筛选和追溯。
5. 演示 Tab 只展示网址和演示记录；资料 Tab 才是所有文件的权威入口。

### 6.6 出差与报销

1. 分别以列表/卡片展示关联的出差申请和报销申请，提供新增、编辑、删除及审批记录查看。
2. 新增时录入企业微信审批编号，并提示“审批编号在企业微信审批记录中获取，录入后自动关联审批记录”。
3. 出差展示申请人、部门、目的地、周期、预计费用、事由、审批状态；报销展示申请人、部门、报销金额、费用类型、事由、审批状态。
4. 当前阶段以审批编号关联为主，企业微信审批数据同步接口可作为后续集成项。

## 7. 状态与流程

### 7.1 线索主流程

`公海线索 → 认领/分配 → 我的线索 → 跟进 → 报价（可多版本） → 创建合同 → 合同多版本 → 总经理审批通过 → 合同归档 → 回款/开票 → 已成交并进入项目`

### 7.2 报价审批状态

| 状态     | 说明                           | 可执行操作               |
| ------ | ---------------------------- | ------------------- |
| 未提交审批  | 最新报价且附件未齐时，先上传缺失文件；附件齐全后可提交。 | 编辑、上传文件、提交审批        |
| 总经理审批中 | 正在等待总经理处理。                   | 审批同意、审批拒绝           |
| 已审核    | 审批同意完成。                      | 查看详情                |
| 已驳回    | 总经理审批拒绝。                     | 查看详情；可基于最新记录编辑形成新版本 |

### 7.3 合同审批状态

| 状态     | 说明                      | 可执行操作                  |
| ------ | ----------------------- | ---------------------- |
| 未提交审批  | 最新合同版本尚未进入审批。           | 编辑、提交审批                |
| 总经理审批中 | 等待总经理处理。                | 审批同意、审批拒绝；创建新版本会撤回当前审批 |
| 审批通过   | 形成可归档终稿，线索显示合同信息及回款与发票。 | 上传归档、预览、下载             |
| 审批驳回   | 当前版本未通过。                | 基于最新版本编辑，形成新版本         |

## 8. 关联与跳转规则

1. 线索详情创建合同：跳转新建合同页并带入当前线索信息；编辑合同/查看合同详情返回时必须回到原线索详情和原 Tab。
2. 合同详情返回线索详情，合同列表进入的详情则返回合同列表，不能固定返回上一页造成来源丢失。
3. 已成交线索的详情入口跳转项目详情，不再进入线索详情。
4. 项目详情、合同详情与线索详情中相同的报价、合同记录、回款与发票能力必须复用同一业务规则和组件/服务，避免三套逻辑分叉。
5. 所有上传文件都应记录来源模块、业务记录、上传人、上传时间，并可回溯到线索；文件删除应仅删除当前引用，若无其他引用再删除实体文件。

## 9. 验收标准

### 9.1 线索详情

* 页面按 6:4 展示左右内容，空字段统一显示  `-` 。
* 顶部和基础信息字段、顺序与本 PRD 一致；原型图链接可外部打开。
* 从我的线索、公海线索、垃圾线索进入详情时，操作按钮与返回位置正确。
* 合同未审批通过时，主 Tab 不显示“合同信息、回款与发票”；审批通过后立即显示。

### 9.2 报价与合同

* 报价、合同历史均为倒序，默认收起，最新记录优先。
* 编辑报价/合同不会覆盖历史，而是生成新版本记录。
* 报价审批在技术评估文件和报价单齐全前不能提交；合同和报价均能正确显示“总经理审批中”。
* 总经理同意/拒绝必须填写审批意见，审批记录可追溯。
* 合同审批通过后可上传、预览、下载归档文件，且线索合同信息与回款 Tab 可正常显示。

### 9.3 回款与文件

* 回款和开票金额均不可超过当前期次的剩余金额；新增、编辑、删除后状态和汇总自动重算。
* 拆分金额总和必须等于父期金额，父子期次层级及状态展示正确。
* 附件、报价文件、合同文件、回款凭证和发票均支持预览/下载，并在资料 Tab 中可追溯。
* 同一文件被多处引用时资料 Tab 只显示一条且展示全部来源。

## 10. 开发实施建议

1. 将线索详情的报价、合同记录、合同信息、回款与发票抽为共享业务组件/服务，项目详情和合同详情仅传入业务主体与展示模式，避免复制页面代码。
2. 将“最新记录判断、审批状态计算、回款/开票状态计算、附件聚合”做成纯函数并补充单元测试。
3. 文件上传、预览和下载统一走文件服务；业务表中只保存文件引用及来源信息，避免各模块各自处理文件。
4. 所有影响状态的操作（认领、转移、报价提交审批、审批决定、合同版本、归档、回款、开票、拆分）应保留操作人、操作时间和说明，便于详情追溯。
5. 真实审批、员工、客户主体和文件服务接入后，前端不可继续依赖静态模拟数据；列表与详情必须由同一数据源驱动。
