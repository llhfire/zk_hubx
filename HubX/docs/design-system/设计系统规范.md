# ZK HubX 设计系统规范

> 状态：**强制**。本文是前端 UI 组织的唯一事实源，与 `docs/design/页面标记与全站检查标准.md`（M-001~M-049）配套：
> M 系列是「行为规则」，本文是「结构规则」——**行为规则靠组件固化，不靠人记**。
>
> 代码位置：`packages/ui/src/design-system/`
> 原 `packages/ui/src/app/components/ui/` **已取消**，禁止再引用。
> 组件明细见 `组件清单.md`。

---

## 一、总则

### UI 组件库铁律（零例外）

**凡是构建或修改页面，页面里的 UI 必须从 `@/design-system` 取用。**页面不得直接把 Arco、原生 HTML、页面级 JSX/CSS 或业务目录里的局部组件当成 UI 组件库，也不得复制一份已有组件的结构来绕开组件库。

如果现有组件在语义、结构、交互或视觉上不恰当，处理顺序固定为：

1. 先确认是否已有同语义组件；
2. 同一语义、只是表现不同：为现有组件增加受限的 `variant` / `tone` / `size`；
3. 语义或交互契约不同：在 `design-system/` 新建组件；
4. 完成组件实现、token/CSS、测试、`index.ts` 导出、`/ui-library` 实样和门禁后，页面才能使用。

页面只负责业务数据与状态、事件与副作用、组件编排和 props 映射。**“先在页面里临时写出来，以后再抽组件”视为违规；如果组件不合适，就先停页面开发，补组件或组件变体。**

**页面不拥有「长什么样」的权力。**

任何 UI 结构一旦被定义，就只能存在于设计系统里。页面只允许出现四类内容：

1. 数据与状态逻辑（hooks、派生值、mock 数据）
2. 事件与业务副作用
3. 组件编排（把设计系统组件摆进布局）
4. 把数据转成 props

除此之外的 JSX —— 结构 + 视觉样式 —— 一律违规。

## 二、Arco 的定位

**Arco 是设计系统的实现材料，不是页面的组件来源。**页面只能从 `@/design-system` 导入组件；Arco 的基础能力只能在设计系统组件内部使用，或先被设计系统登记、封装并导出后使用。

设计系统**不为只转发 props 的 Arco 薄壳创建新的语义组件**（例如没有设计价值的 `HxButton`、`HxSelect`）。但页面需要基础控件时，必须通过设计系统的受控导出或有明确语义的组合组件使用，不能直接从 Arco 包导入。
设计系统只承担两类职责：

- **组合用法固化**：把「Arco 组件的固定组合」沉淀成组件（表格 + 工具栏 + 空态 + 分页 = `DataTable`）
- **业务语义封装**：把「业务概念」沉淀成组件（状态 → 颜色 + 文案 = `StatusTag`；合同 + 回款计划 = `PaymentPlanTable`）

判断标准：**如果一个组件只是把 Arco 的 props 原样转发，它不该存在。**

> ⚠️ Arco 对未知 prop **静默丢弃**，不报错、不告警。`<Table toolbar={...}>` 不会渲染工具栏，
> `<Descriptions long>` 不会变成整行。只有 `npm run typecheck` 能拦住这类错误——改完页面必须跑。

## 三、什么必须抽成组件

不以「重复次数」为准，以「是不是 UI 语汇」为准。

| 情形 | 处理 |
|---|---|
| 同一结构出现 ≥2 次 | **必须抽** |
| 只出现 1 次，但属于通用语汇（工具栏、金额、状态标签、空态、表单区块、文件行） | **必须抽** |
| 页面独有的编排布局 | 可用布局组件拼装，**不得写视觉样式** |

## 四、一类只有一个版本

- 变体用 `variant` / `tone` / `size` 受限枚举表达，**不新建组件**。
- 界线：**同一语义 + 同一 props 契约 = 变体；语义不同 = 新组件**。
- 反例：`ContractStatusTag` 与 `QuoteStatusTag` 若同为「状态 → 色彩 + 文案」，就是一个 `StatusTag` + 两张状态映射表，不是两个组件。
- 反例：`FilterBar` 与 `TableToolbar` 职责重叠，只保留 `FilterBar`，只有操作时传空 children。

状态色一律走 `StatusTag` 的 `tone`。九个 tone 分两类：

| 类别 | 取值 | 用法 |
|---|---|---|
| 状态语义 | `neutral` / `info` / `success` / `warning` / `danger` / `purple` | 表示好坏、进度、阶段 |
| 分类色 | `cyan` / `pink` / `gold` | **只**用于并列类别（费用类型、渠道、角色）。类别 ≤6 个时不得使用——状态页出现分类色会误导读者 |

页面里提供 `StatusMap<S>`（`Record<S, { label, tone }>`），用 `resolveStatus(map, value)` 取结果。
**禁止**在页面里定义第二套颜色映射（`STATUS_COLOR` / `getStatusColor` / `statusColorMap`），门禁会拦。

映射表统一命名 `*_TONE` / `*_META`，值只写文案和 tone，**不写颜色**：

```ts
// ✅
const SLA_TONE: Record<string, StatusTone> = { normal: 'success', overdue: 'danger' };
const CONTRACT_STATUS: StatusMap<ContractStatus> = {
  draft: { label: '草稿', tone: 'neutral' },
  approving: { label: '审批中', tone: 'info' },
};

// ❌ 又长出一套色值，会和 StatusTag 漂移
const STATUS_COLOR = { normal: 'var(--success-500)', overdue: 'var(--destructive-500)' };
```

需要「状态色但不是标签」时（进度条、卡片左侧强调条、金额着色）用 `STATUS_TONE_VARS[tone].fg`，
不要写 `var(--success-500)`。

## 五、分类目录

按**抽象层级 + 职责**分类，**禁止按业务域分类**（按域分会让每个域长出一套自己的表格/工具栏）。

```
packages/ui/src/design-system/
  tokens.css        设计变量：颜色语义、字号、间距、圆角、阴影、字体栈
  components.css    设计系统组件自身的样式（页面不得新增视觉类）
  foundation/       基础控件与页面图标受控出口（页面不得直接 import Arco / Phosphor）
  primitives/       原子：只表达一个值或一个语义，无业务状态
  layout/           骨架：页面结构、区块、页头
  data-display/     展示：表格、指标、描述列表、空态、文件列表
  forms/            输入：筛选、表单区块、上传、选择器
  feedback/         反馈：确认、提示、异步状态
  business/         业务语义：跨页面复用的业务组件
  facsimile/        文档复刻：A4 纸张/印刷缩印边界（专用子路径，不是通用 UI）
  index.ts          唯一导出入口
```

**跨类判定**：拿不准时看「换一个业务域还用不用得上」——用得上归通用类，只有本域语义归 `business/`。

## 六、样式纪律

| 允许 | 禁止 |
|---|---|
| 布局类：`flex` / `grid` / `gap` / `padding` / `margin` / `width` / `height` | 视觉类：`color` / `background` / `fontSize` / `borderRadius` / `boxShadow` / `border` 颜色 |
| 组件的 `className` 透传（用于布局定位） | 在页面里新建视觉样式类 |
| 引用 `tokens.css` 的设计变量 | 硬编码色值（`#1f2329`、`rgb(...)`、`red`） |

**「硬编码色值」包含内嵌写法**：`border: '1px solid #e5e6eb'`、`boxShadow: '0 4px 12px rgba(0,0,0,.12)'`、
`background: 'linear-gradient(... rgba(...))'` 都算违规，门禁按整串值扫描，不只是首字符。
需要新的颜色/阴影就先加 token，再在页面里引用 `var(--ds-*)`。

**需要浅色底纹时**不要写死半透明色，用 `color-mix`：

```ts
background: 'color-mix(in srgb, rgb(var(--primary-6)) 6%, transparent)'
```

例外只有一类：**文档复刻**（报价单 A4 缩略图那类 1:1 复刻纸张排版的组件）。它们不在产品字号阶梯上，
必须放在 `design-system/facsimile/`，并逐条登记在 `scripts/design-system-budget.json` 的
`facsimile.files`；页面只能作为消费方从 `@/design-system/facsimile` 引用，并登记在
`facsimile.consumers`。门禁会拒绝未登记文件或消费方。

facsimile 的纸张色、印刷规则和 A4 缩略画布变量只写在 `facsimile/facsimile.css` 的
`.hubx-facsimile` 根节点上，不进入全局 `tokens.css`，也不得泛化给普通业务页面。

**字体**：所有金额、数量、日期的数字一律走 `MoneyText` / `DateText` / `MetricCard`，字体栈统一 `"Inter Variable", Arial, sans-serif`（M-022）。

**页面骨架**：所有路由页面必须用 `PageShell` 包裹（内边距与纵向节奏只由它提供）。
自带渐变欢迎栏的工作台也必须包，用欢迎栏替代 `PageHeader`。

### tokens.css 必须挂在 `body` 上

```css
body { --ds-tone-info-bg: rgb(var(--primary-1)); ... }
```

Arco 把 `--primary-1` / `--arcoblue-1` / `--color-fill-2` 这些色阶定义在 `body` 上。
自定义属性里的 `var()` 在**声明所在元素**解析：挂在 `:root` 时这些变量对 `html` 不可见，
整组 `--ds-tone-*` 会变成 guaranteed-invalid —— 组件背景退化成透明、描边退回 `currentColor`，
**而且不报任何错**。同理，`components.css` / `foundation.css` 必须 `@import './tokens.css'`。

## 七、命名约定

- 组件名用业务语义或结构语义，**不用业务域名**：`StatusTag` 而不是 `ContractStatusTag`。
- props 用 `variant` / `tone` / `size` 三个受限枚举，新增变体先改枚举，不新建组件。
- 事件统一 `onXxx`；异步组件统一暴露 `loading` / `error` / `empty`。
- 文件一组件一文件，`index.ts` 统一导出；**禁止默认导出**。

## 八、审查与门禁

`npm run check:ds`（`node scripts/check-design-system.mjs`）扫描路由页面及其实际引用的本地
JSX 子组件，对照 `scripts/design-system-budget.json`。**预算只允许调小。**

严格门禁 `npm run check:ds:strict` 使用 AST 同时检查 88 个路由组件的所有返回分支，以及它们
实际引用的页面子组件：Arco / Phosphor / Recharts 直接引用、原生 `button` / `input` / `table`、
JSX 硬编码色和未包 `PageShell` 的返回分支都必须为 **0**。存量迁移债务只能按
「文件 + 规则 + 节点指纹 + 次数」逐条登记；改写节点不能复用旧名额，修复后立即删除例外。

**实样是交付的一部分**：`/ui-library` 的「基础 UI」与「模块组件」两个页签合计必须让 `design-system/index.ts` 的
**每一个导出**都有真实渲染（不是一行目录文字）：单一值/录入控件进「基础 UI」，组合块进「模块组件」。
新增组件不补实样，视同未交付。另外两个页签是结构说明，不是组件交付位：
「页面框架」放可运行骨架（槽位标注 + 真实页面参照），「业务样板」放真实页面切片（附「可以复制 / 不要复制」）；
骨架与样板一律用假数据，不得从业务目录取数，避免变成第二份实现。

绝对规则（必须为 0，超一条即失败）：

| 指标 | 含义 |
|---|---|
| `legacyImport` | 引用已取消的 `app/components/ui` |
| `fontFamilyOutsideDs` | `design-system/` 之外声明 `fontFamily` |
| `statusColorDef` / `statusColorAny` | 页面里又长出一套状态色映射 |
| `hardcodedColor` | 内联样式里写死颜色（含 `border`/`boxShadow`/`gradient` 内嵌） |
| `rawStyleLiteral` | 内联样式里写裸数字字号/圆角/阴影 |
| `pageWithoutShell` | 路由页面没有包 `PageShell` |

结构性规则（迁移目标为 0，已全部归零）：

| 指标 | 对应组件 |
|---|---|
| `rawTable` | `DataTable` |
| `rawEmpty` | `EmptyState` |
| `rawStatistic` | `MetricCard` / `MetricGrid` |
| `rawDescriptions` | `DescriptionsCard` |
| `rawUpload` | `UploadPanel` |
| `rawModalConfirm` | `confirmAction` / `ConfirmModal` |
| `rawCard` | `SectionCard`（`Arco Card` 一律换掉） |
| `rawAlert` | `AlertBanner`（`Arco Alert` 一律换掉） |
| `rawProgress` | `ProgressBar`（`Arco Progress` 一律换掉） |
| `rawTagColor` | 带 `color` 的 `Arco Tag` → `StatusTag` + `tone` |
| `libraryMissingDemo` | `design-system/index.ts` 的每个值导出必须在 `/ui-library` 有真实渲染 |

`rawTagColor` 的例外只有一类：**输入控件式的标签**（`closable` / `checkable` / `onClose` / `onCheck`），
例如下拉多选的已选项、可勾选的标签选择器 —— 那是表单控件，不是状态标签。此类能力也必须通过设计系统的受控导出或组件变体提供，页面不得直接回退 Arco `Tag`。
`StatusTag` 自身也支持 `onClick`（快捷筛选）与 `onClose`（已选条件），能用它就不要另造标签。

### `SectionTabs` 的三种用法

| 用法 | 写法 | 场景 |
|---|---|---|
| 页面级分区 | `<SectionTabs activeKey={k} onChange={setK} items>` | 页头下方的一级/二级分区，下划线激活态 |
| 密集面板分组 | 同上 + `variant="card"` | 详情页主区、侧栏多页签工作区；卡片激活态，宽度更紧凑 |
| 非受控 | `defaultActiveKey` | 页面内部不需要读取页签位置时，避免为单个页签引入 `useState` |

数量的三种表达：`count`（中性灰）、`count + countTone`（逾期/超时用 `danger` / `warning`）、
label 里自带节点（图标、状态标签）。**页面不要自绘彩色计数徽标**——同一份「数字 + 状态色」曾在线索、项目、报价三处各写一遍。

棘轮规则（只防增长）：

| 指标 | 说明 |
|---|---|
| `visualInlineStyle` | 内联视觉样式总数（**含用 token 的**）。布局类内联允许、视觉类必须走 token，所以它不会归零，也不该归零 |
| `rawPageTabs` | 页面里直接用 Arco `<Tabs>` 的次数（不含 `/ui-library`、`design-system/`）。**页面级分区页签只能走 `SectionTabs`**，
包括详情页的二级页签与列表页的分段筛选。计数只认 `<Tabs …>` 元素本身，`<Tabs.TabPane>` 不重复计数。**预算已收到 0**：
新增一处即失败；确需 Arco 原生页签形态时，先给 `SectionTabs` 加受限变体，不要在页面里绕开。 |

门禁失败即视为本次改动未完成。
