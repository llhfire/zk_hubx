## 三、`libraryMissingDemo` 怎么做的

它要回答的问题是「组件的实样算不算交付的一部分」。做法：

1. 从 `design-system/index.ts` 用正则取所有 `export { … }` 的值导出
   （过滤 `type Xxx`），当前共 **54 个**。
2. 从 `UiComponentLibraryPage.tsx` 取**去掉 import 段之后的函数体**，
   再把所有字符串字面量（`'…'` / `"…"` / `` `…` ``）替换成 `''`。
3. 逐个查 `\b组件名\b` 是否还在代码里。

**第 2 步是关键**：目录表里写着 `component: 'MoneyText'`，如果只做全文匹配，
这行文字会让检查假通过 —— 组件实际上一个都没渲染。去掉字符串字面量后，
只有真的出现在 JSX / 常量引用里才算。

自测过（故意在 `index.ts` 追加一个假导出）：

```
✗ libraryMissingDemo：1 项
    FakeUndemoedThing
✗ 超出预算（预算只允许调小）：
    libraryMissingDemo: 1 > 预算 0
```

还原后立刻恢复通过。

## 四、棘轮预算为什么允许涨

`visualInlineStyle` 从 1657 涨到 2288（迁移主峰），2026-10-27 的语义迁移把它收回 **2067**。
涨的那段是因为**裸数字变成了 token 写法**：

```diff
- <Text style={{ fontSize: 12 }}>        ← 值不以引号开头，旧正则不匹配
+ <Text style={{ fontSize: 'var(--text-xs)' }}>   ← 现在匹配了
```

这类改动让计数涨、违规数降。如果把预算卡在 1657，等于禁止别人做正确的迁移。
所以它只防「有没有人偷偷加新的内联视觉样式」，真正的红线是 `hardcodedColor` 和
`rawStyleLiteral`(=0)。

## 五、自测门禁的两种方式

**方式一：造违规。** 本次验证过三条：

```bash
# 1. 硬编码色（分写边框）
borderTop: '1px dashed #e5e6eb'   → hardcodedColor: 1 > 预算 0  ✗
# 2. 组件缺实样
index.ts 追加 export → libraryMissingDemo: 1 项 ✗
# 3. 还原后
→ 设计系统门禁通过（剩余待迁移计数 2067）  ✓
```

**方式二：看 `--report`。**

```bash
node scripts/check-design-system.mjs --report   # 只打印计数，不判定
```

迁移期用这个看趋势；收口时必须用不带参数的那条。
