# 销售域 α 收口日志

> 日期：2026-08-31  
> 范围：`apps/prototype` 与 `packages/ui` 共享前端；不含 β、D1、Workers 和真实外部供应商

## 结论

销售域 α 已按“线索 → 客户 → 报价 → 合同 → 回款”的现有架构完成收口。此次没有另建销售助手或第二套待办体系，而是补齐共享客户事实源、版本化合同模板、销售待办/提醒、报价协作与证据、合同历史版本和真实线索治理。

## 已完成能力

### 客户主档

- `CustomerContext` 通过 localStorage 提供统一 α 数据源；客户列表、详情、线索转客户和全局搜索不再各读一份静态客户数组。
- 企业统一社会信用代码、个人手机号执行强判重；名称相似只提示，不自动合并。
- 支持多联系人、唯一主联系人、被引用联系人停用、当前开票资料及变更历史。
- 客户详情按线索机会聚合报价、主/补充合同、项目和回款；合同与报价保留客户快照。
- 重复客户合并保留旧档案、来源和别名，不覆盖式删除历史引用。

### 合同模板与版本

- 新增 `/contracts/templates`，支持模板草稿、发布不可变版本、复制、停用、历史查看和按主体/产品分类设置默认模板。
- 合同向导与编辑器可带入发布模板，并保存 `templateVersionId` 和渲染正文快照。
- 合同历史版本可查看、与前版比较，并以选中的历史版本作为新版本基线。

### 跟进待办与机会提醒

- 明确的下次跟进时间写入统一 Todo；调整同一承诺时更新同一条，完成跟进时关闭当期待办。
- 联系人生日、合同到期和免费维护期到期进入统一 Reminder，并可稍后提醒或人工转为 Todo。
- 默认提前量集中在系统配置中，旧 localStorage 配置会深度合并新字段，不因升级丢失默认值。

### 报价协作、签署演示与合规

- 重新报价使用 `previousQuoteId`，补充报价使用 `parentQuoteId`，避免两个版本链互相污染。
- 报价差异覆盖功能清单、人天、增值项、总价、工期、付款、质保和客户文件；补充报价独立展示相对有效合同的影响。
- 支持销售/技术评估人转交、限时代理、重叠校验和操作记录；相关未完成待办随责任人更新。
- 报价与合同提供明确标识的 α 签署演示，不生成个人签名、不声明法律效力；可上传并预览真实线下签署证据。
- 合规档案只读投影已有证据，展示完整、缺失和异常项，可导出真实 HTML 摘要与 JSON 元数据。

### 线索治理

- `/leads/governance` 改为读取真实线索和系统配置的异常、重复、退回质检与规则概览工作台。
- 催办、合并和质检均由管理员显式确认；不再展示随机评分，不执行自动回收、自动处罚或自动改写线索状态。

## α 限制

- 持久化仅用于 prototype/localStorage 或既有 mock service，不代表 β/生产数据已接通。
- 签署功能只是状态与证据演示，不是《电子签名法》意义上的电子签名服务。
- 不含 AI 阶段推进建议、成交预测、自动回收、自动处罚、企微/短信/邮件外发或真实 CA/电子签供应商回调。
- 生产级 RBAC、审计后端、刷新幂等与历史数据迁移仍属于 β 范围。
